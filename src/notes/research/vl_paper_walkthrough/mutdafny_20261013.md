# MutDafny: A Mutation-Based Approach to Assess Dafny Specifications
(authored by agents unless marked 🧑)
Tag: `amaral2025mutdafny`, [paper](https://arxiv.org/abs/2511.15403)

idea: mutate code, keep spec, run verifier
- a mutant that still verifies may signal a weak spec
  - example: SharedElements with the `if` block deleted returns empty and verifies
  - fix: `==>` to `<==>` in ensures plus loop invariant
- caveat: "may", survivors are leads not proof
  - audit of 284 survivors: 77 real weaknesses, 157 equivalent, 50 unclear (27.1% useful)
  - the 77 came from only 5 specs
- nothing proved, Dafny 4.10.0 + Z3 as oracle, audit by one person
pipeline
- Dafny plugin between parser and verifier, 40 operators, 794 files
- mutant classes: killed, alive, invalid (fails resolution), timed out
  - 118,458 mutants: 64.6% killed, 25.7% alive, 9.3% invalid, 0.4% timeout
- two scans: before resolution for syntax targets, after for type-dependent ones
- one operator at one location per mutant, specs untouched
  - kill = any verification failure, incl. loop invariant or termination, not only ensures
mutation score
- killed / (killed + alive), per file, excluding invalid and timeout
  - median 92.6%, mean 82.5%, pooled only 71.5%
- high score ≠ spec matches intent
operators
- 30 ported from tools for other languages
  - kept if Dafny supports the op and result can be valid, minus always-equivalent
  - restrictions avoid trivial rejection, e.g. `/` only swaps with `%`
- 10 new + 1 extended, mined from bug-fix commits read in reverse
  - 12,308 commits → 1,475 keyword hits → 270 candidates → 148 accepted
  - new ones: VER, FAR, MCR, DCR, MVR, SAR, TAR, CBE, SWS, SWV
  - 5 of the 15 operators that exposed weaknesses were new
- poor-value operators: high invalid share, e.g. MAP 47.0%, ODL 45.6%
- CBR survives 98.6%
cost
- median 306 s per file, mean 22 min, max about 43.5 h
- plugin itself about 5% of generation time, rest is Dafny resolving
- remedy: run on each new component during development
  - future: use spec coverage to cut mutants
weak spec patterns found
- result only constrained as a subset, so empty passes
- postcondition omits that a value was inserted
- postcondition bounds items but not their sum
spec coverage in dataset
- 1,403 of 2,747 methods have no postcondition
inconsistencies in paper
- "real-world" weak specs: 4 of 5 from LLM-generated dafny-synthesis tasks
- audit all from DafnyBench, nothing on industrial projects
- Table 2 UOI operator not among the 40
verus takeaways (inference, not tested in paper)
- mutate only executable fn bodies, leave requires/ensures/spec/proof/invariant
  - Rust type and borrow check plays the resolver
  - log which obligation failed, loop-invariant kills do not show a strong contract
  - AOR often killed by overflow obligation, not contract
- most operators port, THI/THD/PRV do not
- use after proofs verify, strengthen ensures until survivors die
