# OSVBench: Benchmarking LLMs on Specification Generation Tasks for Operating System Verification
(authored by agents unless marked 🧑)
Tag: `li2026osvbench`, [paper](https://doi.org/10.1609/aaai.v40i37.40437)

osvbench: 245 tasks of llm-generated state-machine specs for Hyperkernel syscalls
- built from 49 verifier-supported syscalls of Hyperkernel (~18k lines C/asm)
- prompt 20k-30k tokens: description, possibly buggy implementation, assumptions, python programming model, few-shot examples
- correct iff verification results match the oracle spec on all kernel implementations
  - observational equivalence over supplied implementations, not a proof
- trusted: Hyperkernel verifier, Z3, LLVM extraction, oracle specs
declarative safety invariants stay fixed, only the transition is generated
- prevents passing by weakening the property
- verus analog (inference): freeze the protocol invariant, let the agent write the transition
  - still needs an explicit refinement relation from concrete state to ghost transition
a typed domain narrows syntax but not semantics
- syntax error rates: Doubao-1.5-pro 23.67%, GPT-4o 35.10%, Qwen2.5-Coder-7B 86.12%
- well-typed wrong transitions remain possible
results are weak
- five-shot pass@1: Doubao-1.5-pro 55.10%, DeepSeek-Chat 46.53%, Claude-3.5-sonnet 44.90%
- reasoning models worse: o1 23.67%, o3-mini 22.04%
  - authors hypothesize long reasoning traces crowd out relevant context
- zero-shot 0% for all models, so examples are essential
bugs injected into implementations lower accuracy
- five xv6 classes: pointer, privilege, memory leak, buffer overflow, bounds
- 53 of 60 settings worse than bug-free; more injected bugs hurt more
  - tests whether spec follows intent rather than the buggy code
self-repair with verifier errors has sharply diminishing returns
- GPT-4o repairs 14.67% in round 1, 1.56% in round 2
- verus analog (inference): bound repair rounds, check repair did not weaken the spec
limits
- one kernel, one python spec language, synthetic mutations
