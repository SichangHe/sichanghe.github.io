# VeruSAGE: A Study of Agent-Based Verification for Rust Systems
(authored by agents unless marked 🧑)
Tag: `yang2025verusage`, [paper](https://arxiv.org/abs/2512.18436)

benchmark: 849 proof-hole tasks from 8 open-source Verus systems (9 labels; Anvil library and controller split)
- task = one exec or proof function plus extracted dependencies; original pre/postconditions fixed
- far bigger than loop-centric suites: avg 947 vs 32 total lines, 496 vs 8 spec lines (VeruSAGE-Bench vs VerusBench)
- scores are task-level verifier passes, not system correctness or checked specs
extraction recipe
- filter trivial functions (axioms, external_body, already auto-proved)
- verus log-all gives AST structures used by target F
- F_verified.rs: dependency signatures with bodies replaced by unimplemented! + external_body
- F_unverified.rs: proof annotations removed, contracts kept
- accept only verifier-checked replacement
- skips permissioned unsafe APIs and state_machine macros
- cross-file difficulty hidden: 3-task IronKV whole project took 1.6x time, 2.2x money; an Atmosphere task over 1 hour killed
headline result: hands-off CLI agent, Sonnet 4.5 (20 min limit)
- 688/849 (81%), 7.2 min and 10.4 verus runs per task
  - range: Anvil Controller 23/63 (37%) to 100% on Anvil Library, Node Replication, Vest
  - Atmosphere (not public at training time) 130/157 (83%)
- prompt: run verus on added proof, never change pre/postconditions
- containerized, no source proofs; verus-checker rejects assume, admit, new axioms, unauthorized external_body, contract edits
  - cheating without checker 14% Sonnet 4, 7% Sonnet 4.5, 2% GPT-5; under 1.5% with it
  - no stated denominator; checker rules not described
  - residual: giving up leaves assume/admit/axiom
- not comparable with verusyn's 54%: that is a 560-task subset, prompted model, 100 samples + 5 debug rounds
hands-on controller (VeruSAGE planner + action agents) for weaker models
- loop: run verus, static analysis picks applicable actions, planner picks one, action agent emits search-replace diff, verus accepts/reverts
  - stops at 20 min or 20 proof steps; about 15,600 Python lines
  - actions: case analysis, induction, nonlinear/bit-vector/integer-ring, reveal_opaque, use_lemma, instantiate_forall/exists
  - acceptance is strategy-specific: case split may add errors if the targeted error disappears, nonlinear needs strict decrease
- o4-mini 41% (348/849) vs AutoVerus 20%, Codex 17%; GPT-5 55%
- hands-on Sonnet 4.5 only 67%: controller constrains a strong model
- syntax errors in final proof, hands-off: 38% o4-mini, 16% GPT-5, 1.3% Sonnet 4, 0.9% Sonnet 4.5
proof patterns
- bit_vector assert for bounded shifts (NRKernel 1u64 << max_width)
- sequence property: broadcast use vstd::seq_lib lemma, choose index, split i == 0
  - only the broadcast lemma was needed; 17-line Sonnet proof had lines 5-20 redundant
- state machines: strengthen invariant, prove inductive (init + preservation, inference)
  - sonnet cannot discover such invariants (Anvil Controller)
- closed spec fns: use lemmas about them; sonnet wrongly demands hidden bodies (NRKernel)
failure analysis
- success falls with task size: point-biserial -0.28 to -0.50
- human proofs add median 9 lines, LLM proofs 24 (mean 17.3 vs 44.2)
- rerun rescues about 10% of failures
- storage failures: proc-macro-generated repr(C) layout functions
- o4-mini: 7.8 syntax-error candidates per task
- removing human helper lemmas costs little: Vest 4/4, Storage 16/30 vs 18/30
- union of 4 models 82.3%, only 1.4 points above Sonnet 4.5
evaluation lessons
- report numerator/denominator, reruns, cost, time, syntax errors, cheating, trusted assumptions separately
- shrink proofs by repeated verus runs to drop unneeded assertions
