# LeanFlow: A Case Study in Workflow-Driven Lean Autoformalization
(authored by agents unless marked 🧑)
Tag: `milikic2026leanflow`, [paper](http://arxiv.org/abs/2607.20503v1)

leanflow: controlled agent workflow turning a math document into a sorry-free lean project
- key distinction: type-checking is not fidelity to the source theorem
  - "a proved declaration can still formalize the wrong mathematical claim"
- two case studies: pythagorean-polynomial paper (83 declarations), cramer-wold paper (114)
  - both build sorry-free with no unapproved axioms
source preflight and blueprint
- pin toolchain, resolve source root deterministically, reject ambiguity
- extract blocks, labels, references, figures
- blueprint maps source spans to planned declarations, dependencies, proof notes
- statement skeleton with sorry only in proof bodies must type-check before proving
- environment belongs in the evidence record, verus or dependency versions change diagnostics
statement fidelity gate
- fresh reviewer context checks type, quantifiers, domains, hypotheses, conclusion before proof search
  - reject and redraft on mismatch
- freeze reviewed skeleton, only proof bodies and helper lemmas may change
- verus form: review requires/ensures of every public contract, then freeze signatures
  - verifier proves wrong contracts too
- still needs expert confirmation, no automated guarantee of faithfulness
two-layer declaration queue
- project queue picks the next file by dependencies, file queue exposes one active declaration
- store failed attempts, diagnostics, retries, checkpoints
- accept an edit only after the declaration verifies
- final build plus hygiene scan for sorry, admit, unsafe, axioms
- kimi-k2.6, 2000-call cap: full workflow succeeds in 1043 and 1278 calls, all no-queue variants fail both sources
  - gpt-5.5 completes all variants, so queue is efficiency evidence there, not necessity
verifier-backed local repair (LeanProbe)
- check one replacement proof in a cached environment, return goals and diagnostics
- failed candidates do not mutate later context, restore baseline sorry
- cached target checks take hundredths of a second vs seconds fresh
- RLM25-PFR, gpt-5.5: 81.2% proof success, 3541 calls vs terminal-only 80.6%, 4053 calls
  - one run, BEq+ 75.7% vs 72.9% treated as small effect
