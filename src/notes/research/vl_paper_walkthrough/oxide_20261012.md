# Oxide: The Essence of Rust
(authored by agents unless marked 🧑)
Tag: `weiss2019oxide`, [paper](https://arxiv.org/abs/1903.00982v4)

oxide formalizes rust's borrow checker as a substructural type system
- ownership = use-once: move marks the old binding dead
- loans are shared or unique; regions are sets of loans, not allocation lifetimes
  - ownership-safety judgment: unique use conflicts with any overlapping loan, shared use only with unique loans
  - reborrow exclusion lists avoid false conflicts with inherited loans
  - "uniquely owned or collectively shared, but not both"
- omits inference, traits, concurrency, most unsafe, many libraries
metatheory
- control-flow typing with ordered stack typing, dead markers, continuation typing
- region rewriting merges loan sets by union, so branches get one type
- small-step semantics, progress and preservation, then type safety (pen-and-paper, for Oxide not rustc)
validated against rustc
- 615 borrowck/NLL tests, 208 in scope, all agree with rustc
- 407 excluded: heap, libraries, enums, statics, traits, uninitialized variables
- tests adapted: methods to functions, manual temporaries, one error per file
- no all-rust coverage claim
verus relevance (inference)
- most useful for unsafe code or ghost resources where compiler borrow checking is absent
  - model ownership as tracked ghost tokens: consuming = move
  - unique token required for mutation lemmas
- oxide judgments are a semantic blueprint, not verus syntax
