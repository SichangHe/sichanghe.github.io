# VerMCTS: Synthesizing Multi-Step Programs using a Verifier, a Large Language Model, and Tree Search
(authored by agents unless marked 🧑)
Tag: `brandfonbrener2024vermcts`, [paper](https://arxiv.org/abs/2402.08147)

verifier-guided tree search over partial programs, no training (Dafny, Coq; Phind-CodeLlama-34B-v2)
- core idea: a prefix that fails the verifier cannot be fixed by later text, so prune it at once
  - verifier score of prefix: -1 finished unit fails, +1 verifies so far, 0 not scorable yet
  - reward only for complete programs: +1 accepted, -1 rejected
- evaluate-and-maybe-expand
  - keep sampling LLM completions until the verifier returns nonzero or depth limit L
  - add child to tree only on +1
  - replaces rollouts and learned value: verifier is exact, cheap next to LLM
- widen node
  - every node gets a zero-valued child; selecting it adds a sibling instead of going deeper
  - width grows only where search stalls
  - tuned on one Dafny problem: temperature 1.0, c_UCT 3, widen prior 0.1
- optimism lemma 2.1: +1 for every not-yet-failed prefix upper-bounds expected best outcome
  - inference: holds for any non-underestimating score, so empirical comparison carries the usefulness claim
- hidden check lemma
  - append lemma with intended statement, proved by one call to the model's lemma, to the verifier input only
  - catches weaker/different model lemma
  - limit: checks lemma not definitions, e.g. wrong fac defined as constant 1 still passes
  - paper's reverse-permutes check is unfinished (TODO, empty body)
- pass@T: fraction of runs succeeding within T generated tokens, Wilson 95% intervals
  - fair for methods with unequal cost per attempt; ignores verifier time and tokens read as feedback
results (15 problems: 9 Dafny, 6 also Coq; T up to 5000)
- about 30% absolute gain in pass@5000 over whole-program sampling
  - 4x relative on Dafny; whole sampling gets 0 on Coq
  - ranking: VerMCTS > rollout MCTS > whole sampling > Reflexion
  - 1 Dafny and 3 Coq problems unsolved by every method
- ablation is rollout MCTS, which also drops widening, so verifier scoring is not isolated
limits
- scoring is coarse: Dafny unit is a whole function, error found only at its last line
- tuning problem (opt0) is in the test suite
- Coq prompts carry strong tactic hints
- number of runs n, depth limit L, per-action token cap not given
- one 2023 model; weak Reflexion may not hold for stronger models
- depth-limit hit scores -1 without a verified failure, outside lemma's proof
verus adaptation (inference)
- unit = whole item in verus! (spec fn, proof fn, exec fn with requires/ensures)
- forward references give unresolved-name errors a later item would fix
  - score unresolved names as 0, or require define-before-use
- hidden check works if the model keeps prescribed names and parameter order
- c_UCT and widen prior need a new sweep
- report verifier seconds beside tokens
