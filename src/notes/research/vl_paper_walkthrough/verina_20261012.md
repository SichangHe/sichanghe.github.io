# VERINA: Benchmarking Verifiable Code Generation
(authored by agents unless marked 🧑)
Tag: `ye2025verina`, [paper](https://arxiv.org/abs/2505.23135v3)

lean benchmark for code + spec + proof generation, 189 tasks
- each: nl description, lean code, pre/postcondition, optional proof, positive/negative tests
  - sources: 49 MBPP-DFY, 59 CloverBench (o3-mini translated + fixed), 81 student submissions
  - median task: 9 code lines, 4 spec lines, 5 positive + 12 negative tests
- modular tasks: SpecGen, CodeGen, ProofGen, and compositions
- lean, not verus: no direct transfer; contamination risk acknowledged
best model o3 (pass@1)
- code 72.6%, spec sound + complete 52.3%, proof 4.9%
- end-to-end: code&spec 41.2%, proof 3.2%
- ground-truth spec helps CodeGen; ground-truth code barely helps SpecGen
qa: coverage + mutation
- positive tests cover every ground-truth code line (100%, via python `coverage.py`)
- each positive mutated into 3+ negatives, labeled by violated pre/post component
- 2+ authors review every task
spec evaluator: proof then tests
- precondition `P̂` sound iff `P -> P̂`, complete iff `P̂ -> P`
- postcondition `Q̂` sound iff `P ∧ Q̂ -> Q`, complete iff `P ∧ Q -> Q̂`
- try llm/lean proof of relation, fall back to tests + lean `plausible`
  - outcomes: proved, counterexample, "might hold", unknown
- end-to-end proof is against ground-truth spec, blocks vacuous code+spec pairs
proof repair with lean feedback
- Goedel Prover V2 32B 11.2% pass@1, DeepSeek Prover V2 7B 8.6%, o3 4.9%
- iterative refinement, 64 rounds: up to 20.1%
  - 64 verifier calls is costly; still low
