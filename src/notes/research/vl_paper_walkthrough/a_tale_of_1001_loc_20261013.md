# A Tale of 1001 LoC: Potential Runtime Error-Guided Specification Synthesis for Verifying Large-Scale Programs
(authored by agents unless marked 🧑)
Tag: `wang2025tale`, [paper](https://arxiv.org/abs/2512.24594)

Preguss: LLM writes ACSL contracts and loop annotations until Frama-C/Wp proves analyzer-reported possible runtime errors (RTE) cannot happen
- OOPSLA1 2026, C programs, goal is RTE-freeness only, no functional correctness
- trust
  - static analyzer assumed to report every possible RTE
  - Frama-C/Wp and its SMT solvers assumed sound
  - leftover unproved guard assertions (hypotheses) are unverified until a human checks them
  - library functions without source (`memcpy`, `memset`) get hand-written contracts
  - soundness theorem (Theorem 20) and termination sketch (Theorem 21) are on paper
alarms as verification goals
- each analyzer alarm is the property the LLM must make provable, instead of describing what the function does
  - Fig. 1 `abs(int x)`: alarm `INT_MIN < x` becomes `requires`, checking call sites separates `abs(-42)` from `abs(INT_MIN)`
  - AutoSpec plus RTE assertions: 22/51 programs vs 17/51 for plain AutoSpec
- Verus form (inference)
  - Verus's own failed obligations (overflow, index, div by zero, callee `requires`) play the alarm list
  - safe Rust excludes uninitialized reads and invalid pointers, so list is shorter
verification units and bottom-up queue
- unit = one guard assertion + host function + its direct callees (modular verification needs nothing else)
  - call-site precondition checks created up front with predicate `true`, so queue length is fixed
- order: callees before callers, then smaller line number
  - earlier assertion's spec may supply the later one's hypothesis
  - acyclic call graphs only (Wp's weak recursion support)
- limits: many callees can overflow context; globals left out of the slice
feedback and role split
- give the unproved proof obligation to the LLM, make it diagnose root cause before writing specs
  - example `search`: obligation shows `arr_0` vs `arr_1`, fix is `loop assigns i`
  - ablation: removing feedback refinement or syntax correction lowers success, time and cost worsen
- host call: preconditions, assigns, loop invariants for the host only, callers hidden
  - hiding callers prevents over-constrained preconditions encoding one caller's use
- callee call: postconditions and loop invariants only, no callee preconditions
- Verus form (inference)
  - never add a `requires` while the call site is in view
  - targets the agent failure of passing a proof via an unsatisfiable `requires`
acceptance rule
- delete every unproved non-precondition spec at once
  - an unproved invariant `false` would prove everything
- keep an unproved precondition, check it later at callers
  - failure at a caller marks a possible real RTE
- unproved guard assertion goes to the hypothesis set, assumed, continue
  - hypothesis may be a real bug, a solver miss, an over-strong generated precondition, or beyond tool reach
  - the hypothesis list is the human review product
- bounded syntax repair: return ill-formed specs with verifier error, then drop
- terminates: fixed queue length, units never revisited, `iter` bounded (2 in experiments)
results
- 51 small programs (Claude Sonnet 4): Preguss 46/51 (79.7% per trial) vs AutoSpec 17/51 (32.7%), AutoSpecRte 22/51 (41.8%)
  - cost $2.721 vs $0.448, time 65.6 vs 287.2 min
  - Loops 5/8 (37.5%) is the weak category
- real modules, success rate over V-Units
  - Contiki AES-CCM* (544 lines) 94.7%
  - X509-parser policy (1,199) 86.6%
  - SAMCODE (1,280) 87.9% printed, formula gives 89.2%
  - Atomthreads (1,451) 78.1%, no human reference, $18.52
  - human specs touched down 80.6% to 88.9% vs reference set, a count not time
- found 6 genuine RTEs in SAMCODE hypotheses, from 2 developer-confirmed logic bugs
- limits
  - no inductive definitions or axioms, so linked lists and trees fail
  - complex nested loop invariants
  - weakening an over-strong precondition invalidates dependent proofs
  - reference sets include redundant specs, inflating the reduction figure
