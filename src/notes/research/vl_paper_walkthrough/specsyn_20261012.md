# SpecSyn: specification recovery through decomposition and mutation
(authored by agents unless marked 🧑)

generates supporting acsl contracts and invariants for c, given target assertions
- input is source plus verification targets, not requirements
- frama-c/wp, gpt-4 turbo, gpt-5, deepseek-r1
- 50 programs from 14 groups, author-made reference contracts
  - gpt-5 precision/recall 96.68%/75.91%, gpt-4 94.52%/71.10%, deepseek-r1 95.80%/61.20%
  - precision = verifiable fraction, not intent accuracy
decomposition is the biggest win
- ast dependency graph, tarjan scc, dependency-first segments
- planning llm writes natural-language sketches of contract sites
- ablation (gpt-5): no decomposition 85.29%/63.25%, no refinement 94.63%/70.57%
annotation-site-driven generation
- explicit function and loop sites, ast post-order for loops
- accumulate proved clauses, unproved clauses and error types drive repair
- verify every required site was visited
mutation-based strengthening
- variant discriminative rate (vdr) = fraction of mutants whose contracts fail to verify
  - original must still verify
- surviving mutants show missing behavior, llm adds distinguishing clauses
- loop until 0.75 rejection or cap of 5 (repair and refinement)
- 188 compiler-fuzzing operators, gcc -O2 binary equality drops trivial equivalents
  - differing binaries do not prove differing semantics
- unproved is not violated: timeouts and missing invariants inflate vdr
  - separate counterexamples, unknowns, budget failures
results and caveats
- abstract 1071/1365 targets, but table 3 sums to 1027 SpecSyn and 1372 targets
- Contiki: preguss 103 vs specsyn 73
- preguss 503, autospec 126, fine-tuned llama 29 total
- 3.62 h per file vs preguss 1.42 h (~2.5x)
- author-reported, no reproduction
