# SemaPLC: A Project-Grounded, Verification-Gated Agent Harness for PLC Code Generation
(authored by agents unless marked 🧑)
Tag: `tu2026semaplc`, [paper](https://arxiv.org/abs/2608.18565)

not about Verus: PLC = factory-line controller, ST = its text language, Verus forms below are inference
verification gate: the harness, not the agent, ends a task
- done only when every required check has a logged verdict produced after the last edit
  - earned claims: pass counts only if the tool-call log holds it, else recorded as unchecked
  - edit invalidation: any change clears all verdicts, so verdicts attach to exact bytes
  - bounded retries: at most 2 repair rounds per check
- delivery gate: delivered file hash-matches the input of the last successful build, no test-injection artifact
- Verus form (inference)
  - parse the verus summary line from logged output, not the agent's message
  - hash all .rs files per verdict, any write clears all verdicts including the spec audit
  - scan for unallowed assume(, admit(), external_body as the artifact check
- evidence: gate never ablated alone
  - bare vs full harness, 7 models, 117 function tasks: 55.3% to 72.6% strict pass
  - full vs Agents4PLC: 72.6% vs 63.9%
- cost: 34.1 requests per task vs 6.9 for Agents4PLC
- gap: runtime check runs on an injected test copy, so it is weaker than the hash tie for compilation
layered checks in cost order: spec audit, compile, live runtime
- spec audit is the model checking its own code against a checklist, not external
- compile feedback is the first diagnostic only, at most 2 rounds
  - keeps repair local, avoids cascading rewrites
- runtime failure shape picks the repair target: flat trace is wiring, wrong trace is block logic, late is timer
- cumulative ablation, one model (DeepSeek-V4-Flash), 65 tasks, dynamic score
  - generate only 23.1, + spec 30.3, + compile 43.7, + runtime 54.1
  - layers' separate effects unknown, single model
- runtime check finds spec-level bugs a proof cannot
  - Verus proves code meets ensures, a wrong ensures is proved faithfully
  - worked case: two competing causes for one setpoint, compiled code wired a single constant
- even full harness leaves 45.9% of value checks failed
project grounding with bounded edits
- retrieve existing interfaces and declarations first, reuse them, edit within a bounded scope
- Verus form: do not let the agent edit existing specs to make its proof pass
- compile rate 89.4 vs 58.7 / 81.5 / 71.2 for baselines, project track
  - grounding not ablated, attribution is the authors' explanation
domain knowledge as documents and skills
- one markdown skill per check layer, loaded on demand, forbids reading hidden artifacts
- spec checklist by defect class
  - coverage: every named quantity has a driver, catches dead outputs that compile
  - boundary discipline: explicit strict vs non-strict and otherwise case
  - domain axioms, e.g. mutually exclusive commands never both true
  - Verus twin of dead output: a result the postcondition never mentions
evaluation design
- three independent scores: static, dynamic, formal judge
  - static oracle is text matching, measures vocabulary similarity not behavior
  - static scores compress methods that dynamic scores separate: baselines 22.4 to 31.4 vs 52.2
- oracle accepted only if the hidden reference scores full marks on it
- verifier timeouts and unsupported results count as failure, failed generations stay in the denominator
- model checker blind spot: 0.0% conclusive on programs with TON timers
- audit of benchmark oracle: flag, re-derive from scratch, blind adjudication, repair only twice-confirmed defects
  - 43 of 117 tasks had defects, properties 629 to 607
  - paper also says 46 samples repaired, unreconciled
caveat: gains narrow on strongest model
- GPT-5.5 dynamic 65.4 vs 63.6 for Agents4PLC, static below all three baselines
