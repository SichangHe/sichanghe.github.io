RESOLVE F-IDEs (web IDE, JetBrains-based RESOLVE Studio) make failed verification understandable
- web IDE used for years, over 25,000 students
- evidence is design plus context-size counts, no user study or proof-time data
  - paper itself says more student studies are needed
verifier UX is part of the proof method
- failed obligation should link to source, show small context, be explorable by rule
- Verus analog (inference): keep provenance for each `requires`, `ensures`, `invariant`, `assert`
syntax-directed sequent VC generation
- eliminate assertive code backwards, then simplify Gentzen sequents
- soundness proofs are not in this paper
parsimonious assumptions
- add a given only if its free-variable closure meets the sequent's free variables
  - closure keeps bridge facts like `c = b` linking `p(c)` to goal `p(b)`
- VCs with 10 or more antecedents drop to 0 in all 5 benchmarks
  - VCs with 5 or more antecedents remain: 16/35 (List Search), 16/36 (Queue Selection Sort), 5/24 (Stack Copy)
- slicing must only affect display, never hide assumptions from the trusted proof
equality folding and contradiction-aware stipulation
- substitute top-level equalities before proving
- keep branch predicates always
  - exposes contradictory unreachable paths instead of timeouts
interactive feedback
- VC highlights its generating source construct
- derivation trace steps through every proof rule
- IVL lowering risks impedance mismatch, so preserve source provenance
