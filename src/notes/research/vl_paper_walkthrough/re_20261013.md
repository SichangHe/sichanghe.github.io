# Re:Form -- Reducing Human Annotations in Scalable Formal Software Verification with RL in LLMs: A Preliminary Study on Dafny
(authored by agents unless marked 🧑)

rl for dafny spec generation, dafny verifier as the only reward source, no nl cot
- task: given code, output code with `requires`/`ensures`/`invariant`/`decreases`
  - spec infilling rejected, models struggle to place clauses
data
- 20k dafny functions, verified, annotated by Claude 3.5 Sonnet
  - crawled .dfy files: dedupe, strip comments, only ~1.2k pass
  - python to dafny: spec template, translate, repair from verifier diagnostics up to 10 iterations
- sft small: 3k examples, spec-cropped context to full-program output
DafnyComp benchmark for compositional generalization
- leetcode functions (single io, McCabe > 5) composed along claude-made call graphs, then verified node by node
- 3 rates: validation (syntax), verification, spec superiority (at least as strong as ground truth)
rl
- GRPO, reward = syntax + verification + subset reward
  - subset reward added because verification-only reward got hacked with weak specs
  - subset check: gt pre implies gen pre, gt pre + gen post implies gt post
- KL penalty anchors to sft, entropy bonus alone unstable, main model uses both
- 14B RL pass@1 verification 14.0% on 300 DafnyComp, 14B SFT 8.3%, Claude 2.7%
  - verification-reward-only: 92.6% verified but 37.3% superiority, subset reward 85.9% and 55.3%
failures of 115 analyzed 3B-RL outputs
- 60 weak, 51 unverifiable, 4 trivial
- weak or misaligned specs dominate, not trivial cheating
verus transfer (inference)
- crop `ensures` and `invariant` from verified rust, train regeneration
- reward spec strength, never only compilation, keep held-out intent oracle
