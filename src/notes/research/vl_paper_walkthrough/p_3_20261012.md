# P^3: Joint Program-and-Proof Planning for Verified Code Generation
(authored by agents unless marked 🧑)
Tag: `li2026p`, [paper](https://arxiv.org/abs/2608.09277v1)

setting
- verified codegen in Lean 4: emit program π and proof κ for spec σ=(P,Q)
- claim: committing to code before proof structure wastes repair
- evidence: 1 run per task/model/method, 4 closed LLMs, Lean 4.28.0
- Verus
  - paper says SMT systems (Dafny, F⋆, Verus) have the same problem family
  - Appendix C: Verus transfer plausible, not empirically established
  - detailed Verus mappings are my inference
joint plan ρ before code
- 4 commitments
  - contract and algorithm/complexity instruction
  - decomposition: recursion variable, branches, representation, helpers, termination
  - concrete library functions and lemmas
  - proof obligations: bridging predicate, induction/cases, auxiliary lemmas
- procedure
  - propose candidates, reject if sketch violates instruction or predicate cannot entail Q
  - select smallest anticipated proof burden, freeze
  - elaborate under ρ, repair locally, replan if unplanned algorithm/invariant/lemma needed
- results
  - 3.3-8.3 pp gain over implementation-only planning (Table 3)
  - Verina traces with Opus: 131/141 successes kept first plan, 4/48 failures blamed on planning
  - retention is only a proxy
- Verus inference: plan lists requires/ensures, invariants, decreases, ghost state; missing invariant means replan
plan-gated elaboration
- code and proof scaffold both follow ρ, local repair cannot redesign the algorithm
- full-restart rate drops
  - Verina: P^3 5.3-11.7% vs sequential 18.5-28.6%
  - AlgoVeri: 5.8-11.2% vs 23.2-34.9%
  - Lean4Commit0: 1.2-2.2% vs 4.3-5.2%
- Lean kernel is final checker, LLM and planner untrusted
proof-friendly decomposition
- listMax: structural recursion mirrors postcondition
- accumulator fold is shorter but needs generalized invariant over arbitrary init
- record the stronger predicate in ρ before coding
- shortest code can cost proof effort; no decomposition universally best
Lean4Commit0 benchmark
- 108 libraries (65 Python, 17 Rust, 15 C/C++, 11 Java)
  - 511 code and 519 theorem placeholders
  - relational theorems across APIs
- admission gates
  - reference I/O satisfies spec
  - mutants rejected (98.6%)
  - LLM review of trivial/duplicate specs (82.7%)
  - Quality = 0.5·Mutation + 0.5·Review >= 80% (mean 90.7%)
- solve rates only 9-22%
- tests may miss intent, accepted artifact is correct only relative to its spec
phase gates (Appendix E)
- 6 phases: understand, plan, PASS-PLAN verdict, sketch with intended sorry, fill tactics, quality gates
- spec read-only, only standard axioms
- failed instruction check sends agent back to planning
- no per-gate ablation
