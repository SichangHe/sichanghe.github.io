# Lazy Annotation for Program Testing and Verification
(authored by agents unless marked 🧑)
Tag: `mcmillan2010lazy`, [paper](https://www.semanticscholar.org/paper/0f7e8234197643b7240c4af76620b743c37b50d8)

## scope and result
McMillan (CAV 2010, LNCS 6174, pp. 104–118) adapts DPLL conflict learning to symbolic execution. The method symbolically executes feasible program paths, and when the search fails to reach a goal it deduces a program annotation so the same blockage does not recur. The abstract states: “The method generates Floyd/Hoare style annotations of the program on demand, as a result of failure to achieve goals, in a manner analogous to conflict clause learning in a DPLL style SAT solver.” (Abstract, p. 104). InterLA extends the method to procedure summaries; an interpolating prover (FOCI in the implementation) supplies formulas.

## technique 1: on-demand intraprocedural annotation
What it is. A symbolic state holds parameters `P`, a constraint `C` over them (the conjunction of the branch guards along the path), and a map `E` from program variables to terms over `P`. Vertices and edges of the control-flow graph are labeled with formulas; the paper says “A label represents a condition under which no goal can be reached.” Initially there are no labels, which is equivalent to false. A state is blocked when the current vertex label is implied. When blocked, the algorithm backtracks along the edge just executed and labels it with a formula that blocks that edge. When all outgoing edges of a location are blocked, the location is labeled with the conjunction of the labels that block them (Section 1, p. 104; Section 2.1, pp. 110–111).

How to apply it (paper’s rules Decide, Conjoin, Learn, Figure 2, p. 111). (1) Designate a set of goal locations `G0`. (2) Decide: symbolically execute along an edge that is not blocked, using a sound symbolic interpreter. (3) If the new query is blocked by the label of its location, it is not added to the query set. (4) Learn: when an unblocked edge has all symbolic successors blocked, add an edge label that blocks the current query and is justified (`{φ} a {A(l2)}`); it can be obtained as an interpolant for `A = χ(s1)` and `B = Sem(a) ∧ ¬A(l2)'` (Section 2.1, p. 111). (5) Conjoin: when all outgoing edges are blocked, label the location with the conjunction of those edge labels; if the location is a goal, it is reached and removed from the remaining goals. (6) The algorithm terminates when no rule applies. The `simple` example learns `x ≥ 0` at several places and finally labels `l1 : T`, “proving that the goal error cannot be reached from l1” (Section 1, p. 105).

The paper defines an interpolant for a pair `(A, B)` with `A ∧ B` inconsistent as a formula `Â` such that `A` implies `Â`, `Â` implies `¬B`, and `Â ∈ L(A) ∩ L(B)` (Section 2, p. 108). The paper’s stated advantage: using interpolants to compute preconditions avoids quantifier elimination, which “can be very expensive” (Section 1, p. 105).

Verus form. Inference: represent a Rust control-flow location with a ghost state summary and use `requires`/`ensures` to state edge relations. A failed Verus obligation can trigger a candidate `proof fn` lemma or `assert`; loop facts belong in loop `invariant` declarations. The learned formula is only a candidate until Verus proves it. Verus’s solver interface is not an interpolant API, so extracting interpolants would require a separate front end.

Evidence and limits. Theorem 1 (stated on p. 111, proof sketch pp. 111–112) says that when IntraLA terminates, all locations in `G0 \ G` are reachable and all locations in `G` are unreachable. Inference: this depends on a sound symbolic interpreter (defined in Section 2, p. 109) and justified annotations, which the proof sketch maintains as invariants. The paper says of the unbounded case: “Because the problem of determining the reachable goals is undecidable, we do not expect this algorithm to terminate in all cases.” (Section 2.2, p. 112).

## technique 2: bounded execution plus inductive strengthening
Without bounds, an unbounded loop means “we can keep extending the run infinitely without reaching a blocked state.” (Section 2.2, p. 112). The method adds an auxiliary variable `τ` that is non-increasing and infinitely often decreasing in a well-founded pre-order over a domain characterized by predicate `W`, labels every location with `¬W`, and fixes an initial value `τ0`; every infinite run is then eventually blocked, so IntraLA terminates (if the symbolic interpreter is finitely non-deterministic). On termination this is “a form of bounded model checking”. To get an unbounded proof, the dependence on `τ` is removed by substituting a fixed value `⊥` (typically the bottom of the pre-order), giving `AU`. Labels of `AU` that are not justified are iteratively dropped until a fixed point, the greatest inductive subset of `AU`, which then strengthens `A`. If the result holds in the initial state for all values of `τ`, the remaining goals are unreachable; otherwise `τ0` is increased and IntraLA is rerun (Section 2.2, p. 112; algorithm Strengthen, Figure 3, p. 113).

How to apply it. (1) Choose `τ` and `W`; for example, decrement `τ` on every program action with `W` being `τ >= 0`, or decrement it only on back-edges, or use a vector with one element per strongly connected component (SCC) of the graph. (2) Run IntraLA to termination for `τ0`. (3) Substitute `⊥` for `τ` in the labels and drop unjustified labels until a fixed point. (4) Test whether the initial state satisfies the resulting annotation at `l0`; if so, return the remaining goals as unreachable, else add the subset to `A`. (5) Increase `τ0` and repeat. For a loop with a large fixed bound `N`, incrementing `τ0` by one could give O(N²) decision steps; doubling `τ0` “would give O(N log N) steps” (Section 2.2, p. 113). Alternatively, if a loop is statically bounded, its decrements of `τ` can be removed.

The paper’s `loop1` example uses `τ0 = 0`, learns `l3 : x ≥ y ∧ τ < 1`, then plugs in `τ = 0` and finds `x ≥ y` inductive (Section 1, pp. 106–107). The paper also says the hope is that interpolants “will converge to inductive assertions after a small number of iterations of the loops” (Section 2.2, p. 113); the conclusion adds that “the question of how to obtain convergence in practice for unbounded loops needs further study.” (Section 4, p. 118).

Verus form. Inference: model `τ` as a ghost natural-number budget and state its decrease in a loop invariant and lemma. Use the resulting invariant as a candidate `ensures` fact. A Verus proof of a loop invariant can establish unbounded safety only if the invariant is genuinely inductive; a bounded run alone cannot do so.

## technique 3: negative procedure summaries
What it is. A negative summary is a transition formula `φ` over entry and exit variables with the meaning that if `φ[d0, d1]` holds, then entry to the procedure in data state `d0` may not result in exit in state `d1`; it is true when that exit state is not reachable (Sections 1 and 2.3, pp. 107, 113). A special variable `f` marks aborts: on reaching a goal a procedure exits immediately with `f` true; on normal exit `f` is false. Stack-frame shifts use `push` and `pop`; the weakening `W(φ) = φ ∧ ¬(f ∧ f')` removes transitions from the negative summary at the return site, “allowing the calling context to abort when the called function does” (Section 2.3, pp. 113–115). `Sum` (Figure 4, p. 114) applies IntraLA to a query and returns either a reachable exit state that violates the post-condition (a counterexample) or, if the query set empties, a summary showing no such counterexample exists.

How to apply it (rules DecideC and LearnC, Figure 5, p. 116). (1) Designate a special variable `f` and exit locations `Ω`; the initial annotation labels each exit `r : ¬IS ∨ f'` and the initial post-condition is `¬f`. (2) At a call edge `(l1, call(l2), l3)`, compute the callee post-condition `ψ2 = ¬W(A(l3)) × ψ1` and the callee query `q2 = ((l2, push(s1)), ψ2)`. (3) Call `Sum(q2, A, G)`. (4) If `Sum` returns an exit state `s3`, DecideC adds a query at `l3` with state `pop(s3)`. (5) If `Sum` returns that the query is blocked, LearnC annotates the call edge with a blocking and justified formula. (6) That formula can be an interpolant with `A = χ(s1) ∧ ¬ψ1'` and `B = ¬pop(A(l2)) × ¬W(A(l3))` (Section 2.3, p. 115). The justification condition for call edges is `{push(φ)} ¬A(l2) {push(W(A(l3)))}`.

Paper examples: for `call1`, the callee `foo` gets the negative summary `l1 : x' < x`, reusable in other contexts; for `rec1`, `τ` is decremented on recursive calls (Section 1, pp. 107–108).

Verus form. Inference: give each Rust function a ghost summary relation and prove it with `requires`/`ensures`; represent caller/callee state relation in ghost fields and use `proof fn` lemmas for frame transfer. Rust ownership supplies concrete stack/borrow discipline, but the paper’s `push`/`pop` summary calculus must be modeled explicitly.

## technique 4: implementation and measured search reduction
Impact II implements InterLA. It uses LLVM to generate control-flow graphs from C programs (basic blocks correspond to graph edges), uses the FOCI interpolating prover both for satisfiability and interpolants, models the C heap with the theory of arrays, and uses static analysis to partition loads and stores into alias classes, each modeled by one array. External functions are modeled as having no side effects and returning a non-deterministic value. A reached goal yields a satisfying assignment to the symbolic constraint as a test case. Marking every location as a goal gives tests with “100% coverage of reachable locations” and proves the uncovered locations unreachable; the paper notes that “since the compiler inlines small functions, some goals may be duplicated” (Section 3, p. 116).

The experiments “test the hypothesis that this approach can produce a greater diversity of program behavior more quickly than methods such as DART that enumerate all execution paths.” (Section 3, p. 116). The comparison is InterLA against an implementation of DART using the same symbolic interpreter and prover, on three device-driver benchmarks previously used as software model checking benchmarks, with 104 to 279 reachable basic blocks. DART terminates in these tests because all loops are bounded and there is no recursion. Backtracks to saturation (all reachable locations reached) and to completion, learn versus no learn: `kbfiltr` 87/94 versus 1,290/1,811 (ratios 15, 19); `diskperf` 214/221 versus 7,552/15,148 (ratios 35, 69); `floppy` 327/330 versus 13,827/27,788 (ratios 42, 84) (Figure 6, p. 117). The paper reports the effect is “more pronounced in the larger program, with learning reducing backtracks to completion by a factor 84.” (Section 3, p. 117). The paper says the number of backtracks is also the number of test sequences generated. Inference: these counts measure search effort in test generation, not proof effort or proved-correct tests.

Verus form. Inference: apply a similar experiment to verifier-guided Rust proof search: count verifier invocations and accepted goals with and without learned ghost summaries, keeping source and solver settings fixed. Treat generated annotations as heuristics and report the final Verus acceptance rate separately.

The paper summarizes the benefit: “Lazy annotation allows us to deduce program annotations in response to search failure, much in the way that a DPLL SAT solver learns conflict clauses.” (Section 4, p. 117)

## what is proved, measured, and trusted
Theorems 1 and 2 concern reachability: when the algorithm terminates, reached goals are reachable and remaining goals are unreachable (pp. 111, 115). The implementation section states: “When a goal location is reached, Impact II extracts a satisfying assignment to the symbolic constraint C of the symbolic state as a test case.” (Section 3, p. 116) The experiments measure backtracks and coverage on three driver benchmarks; the paper reports no other evaluation. Inference: trusted components therefore include the LLVM translation, FOCI, the array and alias models, the external-function assumptions (no side effects, non-deterministic return value), and the choice of goals, none of which the paper validates. Inference: for agent-written verified Rust, learned annotations can reduce repeated solver work, but a wrong goal, alias abstraction, or external contract can make an apparently complete result unsound.

## what VL should reuse
Inference: reuse failure-triggered learning, interpolation-shaped summaries, bounded-to-inductive strengthening, and separate measurement of search cost and proof evidence. Do not redo generic DPLL-style path learning without a Verus-specific diagnostic study. Inference: the product risk is learning a convenient invariant that blocks hard paths while leaving a specification gap; require explicit coverage of goals and review of external assumptions.

## techniques for the catalog
- lazy path annotation — learn edge and location formulas only when symbolic execution is blocked (paper)
- interpolant generalization — derive relevant preconditions without quantifier elimination (paper)
- bounded-to-inductive strengthening — use a decreasing budget, remove it, and retain the greatest justified invariant subset (paper)
- negative procedure summaries — compute reusable transition exclusions for modular calls (paper)
