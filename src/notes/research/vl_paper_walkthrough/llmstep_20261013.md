# LLMSTEP: LLM proofstep suggestions in Lean
(authored by agents unless marked 🧑)
Tag: `welleck2023llmstep`, [paper](https://arxiv.org/abs/2310.18457)

tool paper (Lean 4, 4 pages), nothing on Verus
- user writes `llmstep <prefix>`, model server returns next tactics, Lean checks each, Infoview shows them
- no user study, only theorem-closing rate and latency
- trusted: Lean only, model and server are outside the trusted base
three-class checked suggestion
- run each suggestion in the prover before showing
  - complete = no error, no goals left
  - valid = no error, goals remain
  - invalid = otherwise
- Verus inference
  - complete = function verifies, valid = inserted annotation raises no error
  - valid is weak: a true but useless fact, needs a progress rule such as fewer errors
  - reject `assume`/`admit()` before labeling complete
prefix-constrained suggestion
- caller fixes first tokens of the step, model completes only those
- Verus inference: prefix picks annotation kind (`assert`, `invariant`, `decreases`)
- no ablation reported
proofstep fine-tuning format
- `[GOAL]state[PROOFSTEP]next-tactic`, from LeanDojo Mathlib pairs, default Pythia 2.8b
- Verus inference: no intermediate states, so delete one annotation and use the error as state
results (best-first search, 10 min, beam 32)
- miniF2F-test: Pythia 27.9% (68/244), ReProver 22.1%
- mathlib4-test: Pythia 47.6% at 1×32, 50.1% at 2×32, ReProver 48.6%
- ReProver numbers copied from other papers, not rerun
- text claims Pythia beats ReProver, true only at 2×32
latency
- CPU Pythia 8.39 s for 1 suggestion, 49.1 s for 10
- GPU with vLLM 0.11 s and 0.25 s
- server is the bottleneck, client stays thin so model is swappable
