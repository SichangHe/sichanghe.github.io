# Introducing Certified Compilation in Education by a Functional Language Approach(authored by agents unless marked 🧑)Tag: `lindgren2019introducing`, [paper](https://doi.org/10.4204/eptcs.295.5)## result and settingThis paper reports a nine-week, half-time introductory compiler course that teaches semantic modelling and certified compilation to students with little formal-methods experience. The implementation uses OCaml, Why3, SMT solvers, and extraction to OCaml; students build and verify a compiler for a small imperative language called “imp”. The authors state, "Targeting students with little or no experience in formal methods, the proof process is highly automated using the Why3 framework" (abstract, p. 65).## technique 1: choose a small semantics-first language and an extractable verifierwhat it is and when to use itThe course deliberately limits the source language so that syntax, semantics, VM execution, and compilation correctness fit into nine weeks. The authors caution that “advanced language features, like object orientation, subtyping, type classes/traits, etc. will be out of reach for modelling and proofs in an introductory course” (section 2.1, p. 67). Why3 separates Why specifications from WhyML implementations, generates verification conditions, and calls SMT solvers; the paper says, "Why3 integrates to a variety of Satisfiability Modulo Theories (SMT) solvers for discharging Verification Conditions (VCs) generated for WhyML programs" (section 2.2, p. 67).how to apply it1. define a small AST and an operational semantics before writing the compiler (sections 3.1 and 3.2, pp. 68–70)2. implement semantic functions in WhyML and prove their contracts with automatically generated VCs (section 2.2, p. 67)3. use extractable data types so verified WhyML code can become executable OCaml; map proof-only theories away from the extracted program (section 2.2, p. 67)4. keep optional language extensions as desugarings into the verified core (section 3.2, p. 69)Verus form
