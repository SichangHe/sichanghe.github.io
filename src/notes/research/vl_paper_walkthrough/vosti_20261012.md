# Vosti: deterministic LLM inference across engine and GPU boundaries
(authored by agents unless marked 🧑)

verified deterministic LLM inference engine in Verus with Triton kernel analysis
- property: per-request traces agree by prefix comparability
  - equal prompt and sampler state give equal logits, tokens, successor states regardless of scheduling
  - not liveness, not functional correctness
  - "A consistently incorrect implementation can still be deterministic" (§7)
- engine theorem (Thm 4.1): each emitted logit equals a cold forward computation on the logical token history
  - holds under imported kernel contracts and deployment assumptions
  - induction over steps gives trace agreement
proof-enabling design choices
- no runtime autotuning, no fallback outside verified configs
- prefix cache: hash only proposes candidates, exact tokens, depth, parent page checked
  - eviction removes only unreferenced leaves
  - resolve old hits before registering new pages
  - shared pages immutable, new writes go to private suffix slots
invariants
- request/layout consistency (queues, page tables, shapes, permissions)
- KV-value consistency: every live or reusable entry equals recomputation of its prefix without cache
  - ghost histories and cache provenance link storage to logical prefix
- write isolation: needs ownership argument, not just token equality
- kernel configuration and execution consistency
GPU kernels
- restricted Triton subset, tile IR, relational contracts across two invocations
  - fixed tile geometry and op order, since float reassociation changes bits
  - backward dependency rules propagate output region to needed inputs
  - Z3 proves scalar, range, guard obligations
- attention needs value analysis (zeros, ones, -inf masks), structure alone insufficient
  - extra iterations allowed only if proved exact identity transition
- relational equality is easier than full numerical correctness when contract is invariance
evidence (author reports, no independent reproduction)
- 5,488 bitwise-matched pairs: 7 models x 784 comparisons
- decode throughput 1.36-3.19x vs vLLM invariant configs, prefill lower
- sessions 1.14-2.20x faster than vLLM invariant modes, still slower than default modes and SGLang deterministic
- proof size: 14,043 impl, 876 spec, 64,952 proof lines, 52.9 s with 127 workers
  - Triton: 3,028 impl, 500 spec lines, 17.3 s per config
  - custom kernel verifier: 17,182 lines
  - checking time excludes proof-writing labor
trusted
- kernel contract translation and tensor representation correspondence
- analyzer translator, rules, solver encoding, engine-kernel interface, Triton compiler, GPU
- attention input finiteness, unchecked at runtime
takeaways
- strong prior art for manual repo-scale Verus verification, benchmark for proof automation
  - no agent built or maintained it autonomously
- report component proofs, trusted translation, runtime checks, tests as separate evidence
- check cache provenance and publication order, not just isolated methods
