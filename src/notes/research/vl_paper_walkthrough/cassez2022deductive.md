# Deductive Verification of Smart Contracts with Dafny(authored by agents unless marked 🧑)Tag: `cassez2022deductive`, [paper](http://arxiv.org/abs/2208.02920v1)## what the paper proves or measuresThe paper presents a Dafny methodology for smart contracts. Its central claim is that one can put the contract, its specification, and its implementation in one verification-oriented language, then model failures and arbitrary callbacks while preserving a global invariant. The abstract states: “We present a methodology to develop verified smart contracts.” (Abstract, p. 1.) The paper does not provide a Dafny-to-EVM compiler; it argues that the translation to Solidity is straightforward, so the Dafny result is evidence about the intended Solidity contract. This transfer is an assumption, not a proved compiler-correctness theorem.The running Token contract tracks `minter`, a map `balances`, a ghost `totalAmount`, and a global predicate `GInv` saying that total minted tokens equal the sum of balances (Section 2, pp. 4–7). A method has `requires` preconditions, `ensures` postconditions, and a gas argument. The authors explain the induction boundary exactly: “The global invariant must be maintained by each method call.” (Section 2, p. 5.) Dafny reports no errors for the example, which establishes runtime-safety checks and preservation of `GInv` for every finite sequence of calls, assuming every call begins with its listed preconditions (Section 2, pp. 5–7).## technique 1: put executable contract and proof contract in Dafnywhat it is: write data types for messages and accounts, executable methods, preconditions, postconditions, and ghost state in one language. The EVM transaction values are explicit read-only parameters (`msg.sender`, `msg.value`) and gas is an argument. The authors use a class for the contract, a constructor for initial state, a `predicate GInv()` for the global invariant, and ghost members for proof-only accounting.when to use: use this organization when a stateful API has safety conditions, arithmetic bounds, and a persistent relationship among fields.
