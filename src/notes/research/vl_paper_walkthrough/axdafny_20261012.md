# AxDafny: Agentic Verified Code Generation in Dafny
(authored by agents unless marked 🧑)
Tag: `breen2026axdafny`, [paper](https://arxiv.org/abs/2606.32007)

agent writes Dafny code + proof annotations, Dafny verifier is the feedback loop
- proposer/reviewer/memory architecture, 20 attempts per instance
  - memory = previous attempt verbatim + LLM rolling scratchpad
- candidate accepted only if all hold
  - original `requires`/`ensures` preserved (subset check on extracted clauses)
  - no `{:axiom}`, `{:verify false}`, `assume`, `{:extern}` (regex)
  - `dafny verify` passes
  - LLM reviewer finds no semantic cheating, e.g. predicate rewritten to `true`
- verifier diagnostics fed back: unmet pre/postconditions, invariants, termination, locations
  - counterexample flag can be enabled but no ablation
trust
- specification is trusted, so verified code may not match intent or resource bounds
  - verifier/compiler/tests/LLM review also trusted (the note's inference)
- 14/250 benchmark specs (5.6%) needed semantic fixes after LLM review
DafnyBench results
- Gemini-3.1-Pro 725/782 (92.7%), GPT-5.5 medium 88.9%, low 85.3%
- DafnyPro 86.2% (uses retrieval), without hints 76.2%
LCB-Pro-Dafny (250 competition problems: 100 easy, 100 medium, 50 hard)
- AxDafny verifies 141/250 (56.4%): 75 easy, 52 medium, 14 hard
- direct GPT-5.5 pass@1 29/250 (11.6%)
- gains continue through 15 iterations, proof-hint gains concentrate in first 5
verified != fast
- easy verified outputs: 32/75 pass tests, 39 TLE, 4 MLE
- medium: 6/52 pass, 44 TLE, 2 MLE
- verifier checks functional specs, not asymptotic complexity
- report verification and runtime as separate metrics
