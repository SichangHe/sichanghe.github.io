# KaPilot: LLM-Assisted Generation of Kani Specifications for Unsafe Rust Verification
(authored by agents unless marked 🧑)
Tag: `wang2026kapilot`, [paper](https://doi.org/10.1145/3832239)

kapilot = 5-agent pipeline generating Kani contracts for unsafe Rust from documentation
- targets memory safety + panics, not functional correctness inferred from code
- agents: SafetyReq, HarnGen, SpecGenerate, SpecPrecheck, SpecVerify
- eval: Kani 0.62.0; GPT-5, DeepSeek-v3.2, Claude-Sonnet-4; GoldSet 54 functions with expert truth, ULSet 70 without
core idea: documentation-derived requirements are the spec target, implementation is hidden from contract generation
- SafetyReq: Safety/Panics docs + cross-refs -> one atomic sentence per property, with `<src>-<sec>` provenance
  - 6 rules: scope, atomicity, variable reference, traceability, exclusivity, completeness
  - score = harmonic mean of rule scores; up to 3 feedback iterations
- SpecGenerate sees requirements, metadata, Kani API docs, few-shot pairs, prior feedback, but not target source
  - motivation (not measured): defective implementation must not become its own contract
  - cost: incomplete docs can make functional postconditions impossible
- offset case: code-centric AutoSpec misses `same_allocation` and fails Kani
harness + metadata prep
- AutoHarness first, LLM fills missing parameter declarations if it fails
- AutoHarness cannot handle complex params, missing traits, user-defined types
- harness proves only the bounds/paths its assumptions represent
SpecPrecheck: lightweight LLM filter before Kani, triage only, not a sound verifier
- checks requirement coverage, scores pre strength/post adequacy 1-10; below 6 gets feedback; max 5 iterations
SpecVerify: contextual repair + mechanical vacuity check
- feeds counterexample, passing/failing harnesses, failure-specific rule (e.g. `assigns` violation -> fix `modifies`)
- vacuity: append `ensures(|_| false)`; if it still verifies, assumptions are unreachable
  - as_flattened: `T::IS_ZST && ...` precondition excluded all non-ZST, fixed to `!T::IS_ZST || ...`
- verus analogue (inference): temporary impossible postcondition, require it to fail
shuffle-and-implication selection
- combine weakest-pre and strongest-post across candidates, plus loop invariants (each, and conjunction)
- experiment: 2 candidates, 2 iterations; implication does not imply implementation correctness
results (GoldSet, good/bad/fail of 54)
- GPT-5 31/17/6, DeepSeek 28/15/11, Claude 34/16/4
- ULSet pass rates 71.4%, 68.6%, 68.6%; no truth, so good/bad unknown
- vs adapted AutoSpec (GPT-5): 31 vs 17 good, 6 vs 14 failures; adaptation, not original
- ablation good counts: no SafetyReq 6, no precheck 12, no verify 12, no few-shot 11, direct prompt 8
- good = Kani passes, pre no stronger and post no weaker than truth; 2 experts, Cohen kappa 0.81-0.95
trusted
- docs completeness, LLM extraction, human ground truth, Kani, harness representativeness, manual good/bad judgment
- Kani proves only for bounded harness/unwind
