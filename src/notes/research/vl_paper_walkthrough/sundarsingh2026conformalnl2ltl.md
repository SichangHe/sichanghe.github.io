# ConformalNL2LTL: Translating Natural Language Instructions into Temporal Logic Formulas with Conformal Correctness Guarantees
(authored by agents unless marked 🧑)
Tag: `sundarsingh2026conformalnl2ltl`, [paper](https://arxiv.org/abs/2504.21022v2)

## problem and contribution
The paper defines semantic translation of a natural-language robot task ξ and skill set A into an LTL formula ϕ. Its formal target is “Pσ∼D (ϕ ≡ ξ) ≥ 1 − α” (Sec. II, p. 3), where equivalence means that plans satisfying one also satisfy the other. The abstract states: “Our method constructs LTL formulas iteratively by solving a sequence of open-vocabulary question-answering (QA) problems using large language models (LLMs).” (Abstract, p. 1). The contribution is an uncertainty-aware translator. The paper identifies this version as arXiv:2504.21022v2, dated 20 February 2026 (p. 1).

## technique 1: incremental QA formula construction
Inference: use this decomposition when an NL instruction must be converted into an inspectable sequence of operators and atomic propositions (APs). Algorithm 1 (p. 4) gives the procedure: initialize k=1 and an empty formula; build prompt ℓ(k) containing translation rules, examples, the task, and the partial formula; obtain a response through the prediction-set procedure described below; append it to ϕ(k); rebuild the next prompt; stop when the end token `/` is returned. Example II.1 (p. 3) maps “Pick up the red box and place it in storage” to `♢(p_red_box ∧ ♢(storage ∧ pd))`, after inferring APs from the skill set and landmarks. The description states that “QA problems collectively form the LTL formula.” (Sec. III-A, p. 4).

Inference: a possible Verus adaptation is to translate each requirement into a `spec fn` or `ensures` clause over an abstract state, then prove the executable Rust operation meets it. Temporal requirements would need an explicit state-machine interpretation. A proof about that encoding would still depend on a trusted interpretation of the NL requirement. The paper does not evaluate this adaptation.

## technique 2: sampled responses, pruning, and semantic merging
This procedure obtains a confidence proxy from models without logits. Algorithm 2 (p. 4; Sec. III-B, p. 5) queries ψ m times, prunes invalid operators/APs and responses containing multiple operators or APs, computes each valid response's frequency, merges semantically similar APs, keeps the more frequent representative, and returns unique responses with recomputed frequencies. The implementation first requires matching numerical landmark identifiers, then merges APs whose textual embeddings have cosine similarity exceeding ζ=0.75 (Sec. V-A, p. 10). Example III.1 (pp. 5–6) uses m=5 and ζ=0.75: `p red box` occurs twice, `p red package` once, `p green bottle` once, and invalid `pre%blocks` is removed; the first two are merged, yielding frequency 0.75 for `p red box` and 0.25 for `p green bottle`. The paper defines frequency as “the fraction of valid responses equal to s, i.e., the number of times s was generated divided by the total number of valid responses mk > 0.” (Sec. III-B, p. 5).

Inference: a Verus analogue can use deterministic candidate enumeration and a ghost map of normalized proposition names, with proof lemmas that normalization preserves identity. Embedding similarity and LLM sampling remain trusted preprocessing; they cannot be justified by `ensures` unless their outputs are supplied as assumptions or independently verified data.

## technique 3: conformal prediction over dependent QA sequences
Inference: use this when a user needs a coverage target rather than an uncalibrated confidence score. The paper treats prompts as sequences because each prompt depends on the prior answer, violating independence across steps. It samples independent, identically distributed (i.i.d.) calibration scenarios, constructs true-response prompt sequences, and computes the non-conformity score `r̄i = 1 − F̄(ϕi,calib | ℓ̄i,calib)`, where F̄ is the minimum correct-response frequency over every step and both models (Sec. III-D, pp. 6–7). With D calibration scenarios, q̄ is the empirical quantile at level `ceil((D+1)(1−α))/D`. Algorithm 3 includes a sampled response in a model's prediction set when its frequency is at least `1−q̄`. Local sets are constructed on the fly; their Cartesian product defines a formula prediction set (Eqs. (14)–(18), pp. 7–8). Theorem IV.2 assumes fixed m and ζ and a benign user who selects the true response when it is present in a non-singleton set (p. 8). With multiple equivalent formulas, calibration and user selection favor the correct response with the highest primary-model frequency (Remark IV.3, p. 9; Appendix B, pp. 15–16). The paper states: “This correct formula is constructed by computing S̄(k) defined in (6). Then, we select the correct response from S̄(k).” (Sec. III-D, p. 7).

Inference: a Verus adaptation could encode a finite candidate set and prove set-membership implications for a supplied calibration table. Such a deterministic proof alone would not establish statistical coverage; that requires the distributional assumptions and the correctness of the calibration procedure. A possible Rust boundary is a verified consumer whose `ensures` clause says the chosen proposition belongs to the supplied set.

## technique 4: auxiliary model and human escalation
When the primary prediction set has multiple members, query an auxiliary model and intersect the two sets. Its prompt has the same structure and partial formula, but model-specific content in parts (a)–(c) (Sec. III-D, p. 7). Select the sole intersection member; ask a human to choose if multiple members remain. An empty primary set causes failure; an empty intersection or one lacking a correct response can cause the user to halt the translation (Algorithm 1, p. 4; Sec. III-C, p. 6). Inference: a wrong singleton need not be detected automatically. The proof explicitly treats choosing a wrong singleton as translation failure (Sec. IV, p. 9). The paper reports GPT-4o as primary and Deepseek v3 as auxiliary (Sec. V, p. 9).

## evidence, limits, and product implications
The in-distribution evaluation generated 1,000 scenarios: 365 easy, 440 medium, and 195 hard (Sec. V-A, p. 10). For each target, 200 of 220 sampled scenarios calibrated and 20 tested, repeated ten times (Sec. V-B, p. 11). Table I (p. 11) reports auxiliary-model success rates 94.44%, 96.77%, and 99.24% at 95%, 97%, and 99% target coverage; user-help rates 0%, 0.279%, and 0.378%; and scenario help frequency 0%, 2.5%, and 4%. Removing the auxiliary model gives 95.33%, 97%, and 98.2% success, 3.41%, 4.03%, and 7.43% user-help rates, and 30%, 36%, and 36.5% scenario help frequency (Table I). Section V-C instead gives 36.54% for the last frequency. Inference: several reported success percentages cannot be recovered as the stated average of ten success fractions with 20 tests each, which would change in increments of 0.5 percentage points; the paper does not resolve this discrepancy.

Baseline success over 182 scenarios is 87.4% for UA-NL2LTL, 82.87% for Lang2LTL with the authors' added few-shot examples, 53.53% without those additions, and 73.16% for nl2spec (Table II; Sec. V-D, p. 12). The nl2spec comparison disables user editing of sub-translations (p. 12). Out-of-distribution (OOD) tests use different task families and skill sets: Table III (p. 13) reports 79.5%, 80.5%, and 84.5% success at 95%, 97%, and 99% targets. The authors state: “the translation success guarantees do not hold under distribution shifts” (Sec. V-F, p. 13). They identify misplaced parentheses and nonsensical APs that conform to generation rules as common errors (Sec. V-B, p. 11).

Inference: for VL, the transferable pattern is calibrated escalation before emitting a specification. Testing whether this reduces wrong Rust contracts would require separate evidence. The paper's guarantees concern sampled NL-to-LTL scenarios and do not establish that a Verus contract captures a product requirement.

## what is proved, measured, and trusted
Theorem IV.2 establishes marginal translation coverage under the stated distributional assumptions, fixed m and ζ, and benign user selection (Sec. IV, pp. 8–9). Its help-rate optimality claim additionally assumes that the formula score models true conditional probabilities (p. 8). Experiments measure empirical translation success, user-help rate per response, and the fraction of scenarios requiring help. The guarantee relies on the chosen NL interpretation, correct calibration labels, and i.i.d. scenarios. Sampling and embedding similarity affect candidate scores; the proof does not assume these are accurate conditional probabilities for its coverage claim (p. 9). Downstream plan correctness separately relies on a correct, complete LTL planner (Sec. V-E, p. 12). The paper explicitly notes that ambiguous NL interpretations change the ground truth and can create distribution shift (footnote 4, p. 10).

## techniques for the catalog
- incremental QA translation — build an LTL string one operator or AP at a time while carrying the partial formula in every prompt
- sampled-response confidence — prune invalid outputs, count frequencies, merge semantic synonyms, and use the resulting candidate set
- sequence conformal prediction — calibrate a worst-step frequency score over dependent prompt sequences to obtain coverage-controlled prediction sets
- auxiliary escalation — intersect primary and auxiliary prediction sets, then ask a user or fail when ambiguity remains
