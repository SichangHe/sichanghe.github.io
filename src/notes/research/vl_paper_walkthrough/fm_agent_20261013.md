# FM-Agent: Scaling Formal Methods to Large Systems via LLM-Based Hoare-Style Reasoning
(authored by agents unless marked 🧑)
Tag: `ding2026fmagent`, [paper](https://arxiv.org/abs/2604.11556)

what it is
- Ding, Wang, Chen (SJTU): Hoare-style per-function reasoning done entirely by an LLM in natural language
  - contracts are english sentences, callee contracts assumed, each function checked alone
  - output is a failing test, not a proof
- no soundness: "FM-Agent cannot ensure soundness"; sequential functions only
- measured: 522 confirmed bugs in 4 agent-written systems (277k lines, 8,549 functions), all with Claude Sonnet 4.6
  - CCC 339, VibeTensor 141, VibeOS 23, Bespoke OLAP 19
  - ~2 days and 3.4B tokens total, inference: ~6.5M tokens per bug
- trusted or unknown
  - every natural-language contract
  - oracle: GCC/DuckDB where available, else the generated contract judges its own report
  - functions with no reported bug have no status, no miss rate measured
caller-driven contracts
- write callee pre/post from call sites, not its body, so a buggy body cannot define its contract
  - pre = disjunction of callers' pre, post = conjunction of callers' post, merged by LLM
  - process a function only after all callers' specs exist, top-down from entry functions
  - mutually recursive functions: give callers' implementations instead
  - example: CCC `from_keyword` rejects `nullptr`; body-derived contract hides it, caller-derived exposes it
- ablation: 57 bugs vs 339 in CCC
  - confounded: also removes stepwise reasoning
- inference: assumes callers are right, entry functions still get contracts from own body
- verus form (inference)
  - write callee `ensures` = what caller's proof needs, `requires` = what all call sites can prove
  - callee body `admit()` until its turn
layered call-graph schedule
- collapse SCCs, topological layers from entry points, generate a layer in parallel, batch N prompts per request
- phases run concurrently, e.g. compiler lexing/parsing/IR/optimization
- no timing evidence given
natural-language hoare pass
- carry a prose condition through blocks, flag any exit whose condition fails to imply the post
  - branches: disjunction; callee specs taken as given
  - groups statements into blocks to cut LLM calls
- motivating experiment: Claude Code predicts 98.6% (438/444) of outputs on VerusBench functions
  - tests concrete outputs, not inferring all-input conditions
  - paper words it as 98.6% of functions in the intro, of cases in sec 2.3
- verus form (inference): this is `assert`s as comments, but Z3 checks each; use as a cheap screen before proving
post-condition first for loops
- guess the post, then find an invariant meeting 3 checks: implied by pre, maintained, plus negated guard implies post
  - no invariant found means the post may be wrong, retry
  - claim: invariants are harder than posts, no numbers
- no termination check (verus needs `decreases`)
uninterpreted-function ambiguity test
- translate condition to a formula, if it needs undefined function symbols the prose is too vague, stay in natural language
- not evaluated
- detects vagueness, not mistranslation
system-entry bug confirmation
- report a bug only if an LLM-written whole-system test triggers it within N=10 tries
  - crash observed directly, wrong output checked against a reference implementation
  - preliminary: all 10 known CCC bugs triggerable from a described cause
- verus form (inference): when a function resists proof, write a test violating the `ensures`
  - a failing test shows code or contract is wrong
  - verifier cannot drop unproved obligations, unlike a bug finder
- not reported: potential bugs before validation, dedup by root cause, developer acknowledgment
goal-driven incremental re-check
- relevance score = text overlap with developer goal + callers/callees + class score
- re-check if modified/new, spec updated, or calls a function whose spec updated
- verus also needs re-check when a `spec fn` body changes
- not evaluated
inconsistencies and wide claims
- function count 4,910 in text vs 4,957 in table 1
- no comparison with Verus, Dafny, symbolic execution, or LLM bug finders
- SMT path and incremental mode described, not evaluated
