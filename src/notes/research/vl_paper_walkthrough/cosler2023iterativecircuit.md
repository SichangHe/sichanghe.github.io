# Iterative Circuit Repair Against Formal Specifications
(authored by agents unless marked 🧑)
Tag: `cosler2023iterativecircuit`, [paper](http://arxiv.org/abs/2303.01158v1)

## problem and verification loop
The paper repairs defective sequential circuits against LTL specifications. An implementation is correct when all traces satisfy the specification: “A circuit C satisfies an LTL specification ϕ if all possible traces through the circuit Traces C satisfy the specification, i.e., if ∀t ∈ Traces C . t |= ϕ.” (section 3.1, PDF page 3). The learned model proposes a repair; model checking decides whether the proposal satisfies the specification (Figure 5, PDF page 9; the paper names nuXmv as the model checker in section 3.2, PDF page 4, for labelling the dataset); if it still fails, the proposal is fed back for another iteration. The authors describe the pipeline directly: “If the prediction still violates the specification after applying the repair model once, we re-feed the specification with the new violating circuit into the repair model until it is solved.” (section 5.3, PDF page 8).

Inference: this is a useful VL pattern for a Rust/Verus agent: generate a patch, run the verifier, feed the failing obligation or counterexample back into generation, and stop only on a successful proof. The paper’s checker is a temporal model checker whose verdict is satisfied or violated; Verus proof diagnostics are a different feedback language, and the paper feeds back the violating circuit itself, not a counterexample trace.

## technique 1: build paired formal-repair data
Each sample contains an LTL specification, a defective AIGER circuit, and a corrected target circuit (section 3, PDF page 3). The authors first replicate a neural synthesis model, evaluate it with beam size 3, model-check each predicted circuit with nuXmv, and classify it as violated, matching, or satisfied. The reported RepairRaw split has roughly 580,000 training specifications and about 72,000 in each of the validation and test splits, with 55% violated, 16% exact matches, and 29% satisfied-but-different predictions (section 3.2, PDF page 4). For violating predictions, they replace misleading targets: they search for alternative solutions with the synthesis model (up to beam size 4) and, if a correct alternative circuit has a smaller Levenshtein distance to the faulty circuit, it becomes the target; they select samples with distance to the target at most 50 (section 3.2, PDF pages 4–5).

They also generate human-like defects with Algorithm 1. Sample a number of changes from a discrete truncated normal distribution around zero (standard deviation 7.5, bounds 1 to 50); for each change, delete a line with probability 0.2 (inputs and outputs are not removed) or change a variable number with probability 0.8; choose the line or the position uniformly; sample a different variable number from a discrete truncated normal around the old one (standard deviation 10, bounds 0 to 61); then spot-check altered circuits with model checking (section 3.2, PDF page 5). The exact algorithm says: “with probability pdelete do … Remove line l of C” and otherwise “replace variable number at position pos in C with var0” (Algorithm 1, PDF page 4). In less than 2% of the cases an altered circuit still satisfies the specification (section 3.2, PDF page 5). In the final dataset, 61% of samples contain errors introduced by Algorithm 1 and the others are mispredicted circuits; 38% of samples have a Levenshtein distance below 10, and the distance has mean 15.7, standard deviation 12.77, and median 13 (section 3.2, PDF page 5).

Inference: for VL, analogous data should pair a Verus contract, a failing Rust implementation, and a repaired implementation, with the verifier deciding whether a mutation is genuinely defective. This is a proposed adaptation, not a paper result.

## technique 2: separated hierarchical Transformer
The model separates the LTL specification from the circuit. Separated local layers are independent encoders that share no parameters; the specification is partitioned into assumptions and guarantees, which are processed by shared local layers, while the circuit is processed by its own separated local layer; the results are concatenated and fed into the global layer (sections 4.1–4.2, PDF page 6). The paper states: “The separated hierarchical Transformer handles multiple independent inputs that differ in structure, type, or length better.” (section 4.1, PDF page 6). Properties use tree positional encoding; circuits use the standard linear positional encoding; every DSL symbol is a token, AIGER variable numbers are limited to 0–61, and a special prefix token on the circuit encodes the presumed realizability of the specification (section 4.2, PDF page 6).

Training uses four attention heads, four local layers in each separated local layer, four global layers, eight decoder layers, embedding size 256, feed-forward size 1024, Adam, batch size 256, and 20,000 steps on a single GPU of an NVIDIA DGX A100 system (section 5.1, PDF page 7). Specification inputs are restricted to five inputs, five outputs, no more than 12 properties (assumptions plus guarantees), and no property with AST size greater than 25 (section 5.1, PDF page 7).

## technique 3: iterative checker-guided repair
At beam size 16, the text reports a correct implementation in 84% of cases on a single try (Table 1 gives 84.8% semantic accuracy at beam size 16 and 58.3% at beam size 1); the model copied the defective circuit in only 31 of 1024 samples, and syntax errors were rare, “a total of 8 errors out of every beam” (section 5.2, PDF page 7; Table 1, PDF page 8). The paper calls Levenshtein distance “the dominant indicator of a sample’s difficulty”, with specification and circuit size “less of a factor” (section 5.2, PDF page 7). For violating predictions, the mean syntactic improvement is −9.98 edits; 75.9% satisfy more single-guarantee sub-specifications and 2.4% satisfy fewer (section 5.2, PDF pages 7–8).

Table 1 gives the pipeline settings (maximum iterations n) but no sample counts. On the held-out synthesis dataset, semantic accuracy rises from 77.1% for the synthesis model to 82.6% after one repair iteration and 83.9% after up to five, a +6.8 percentage-point gain. On SYNTCOMP, it rises from 64.1% to 71.7% after one iteration and 75.9% after up to two, a +11.8 point gain (Table 1, PDF page 8). The prose of section 5.3 attributes +11.8 to smart home and +23.8 to syntcomp, which contradicts Table 1 and the abstract; this study follows the table. These percentages are benchmark-set accuracies, not universal success probabilities.

Inference: Verus can supply the checker in this loop with `verus` proof results and counterexample-guided prompts. A failed proof is evidence about the current specification and implementation, but only successful verification establishes the encoded contract; external bodies, libraries, and environment assumptions remain trusted as in the Verus scope.

## limits, trust, and product threat
The paper says a deep learning approach is “inherently incomplete” (section 2, PDF page 3). Inputs are restricted (variable numbers 0–61, at most five inputs and five outputs, section 5.1, PDF page 7). The paper notes that a specification can have multiple correct implementations, which makes the choice of target ambiguous (section 3.2, PDF page 4), and that a specification can be unrealizable (section 3.1, PDF page 3). Inference: trusted elements include the LTL/AIGER encodings, nuXmv, dataset labels, model implementation, and the specification itself; the paper does not discuss these as limits, and it gives no guarantee that a repair is found. Inference: threat to agent-written verified Rust is medium to high if the agent treats a model suggestion as proof; it falls to medium when every candidate is required to pass Verus and tests, but specification omissions and trusted dependencies remain.

What VL should reuse: checker-in-the-loop iteration, target disambiguation by semantic validity plus edit distance, synthetic defect generation, and separate encoders for heterogeneous specification and implementation inputs. Inference: VL should not make a generic “LLM repair is correct” claim without verifier results on a stated sample set.

## techniques for the catalog
- checker-guided iterative repair: repeatedly regenerate a candidate and model-check it until the formal specification is satisfied
- formal-repair dataset construction: pair specifications with defective and corrected implementations, filtering labels with a checker
- probabilistic defect injection: create realistic mutations by deletion and rewiring sampled from bounded distributions
- target disambiguation: replace misleading supervised targets with closer valid implementations
- separated hierarchical encoding: process independent specification components and implementation tokens with distinct local encoders
- semantic progress scoring: measure repaired behavior by specification satisfaction and syntactic progress by edit distance
