# MechMath: Sorrifier-Driven Formal Decomposition Workflow for Automated Theorem Proving
(authored by agents unless marked 🧑)
Tag: `qiu2026mechmath`, [paper](https://arxiv.org/abs/2603.24465)

keep what compiles, cut only failing pieces with `sorry`, prove each hole as a fresh lemma
- lean 4 + mathlib competition math, gemini 3.1 pro in all roles; nothing about Verus, all Verus forms are inference
- repair-in-place grows context; regenerate wastes mostly-correct work
- trusted: lean kernel and the formal statements; LLM judgments are advisory
  - public code: github.com/MechMath/MechMath-v1
sorrifier: deterministic loop, one innermost error at a time
- take first error, replace smallest enclosing block with `sorry`, recompile, repeat
  - one at a time because later errors are often cascades
  - `have`/`replace`: replace body only, keep the claim
  - `calc`/`choose`: replace the whole block
  - error outside any block: truncate there, append `sorry`
- reuse of original skeleton lines: 74.5% miniF2F, 71.1% ProverBench (range 5% to 98%)
- ablation, Putnam 2025 A1-A4, 128 call budget: discard-and-retry 0/4, iterative repair 3/4, MechMath 4/4
  - only 4 problems, no repeated runs; MechMath used more calls than repair on A3 (69 vs 42)
- verus analogue: `assume(P)` for claims, `admit()` for bodies, rerun after each cut
  - final acceptance must reject leftover assume/admit since Verus verifies silently
hole to lemma
- at each `sorry`, LLM keeps only relevant hypotheses, writes standalone lemma
  - verus: `proof fn sub_k requires R ensures P`, R gathered from requires, invariants, branch conditions
- no ablation isolates hypothesis pruning
subgoal check before proving
- lean checks statement syntax; verifier LLM checks extraction fidelity and soundness (counterexample hunt)
- syntax/extraction error: re-extract; logic error: send back to parent proof
- Putnam A2 example: y=0.5 gave 0.421 vs 0.318, subgoal false
- intercepted on miniF2F: 5 logic errors across 3 problems, 1 extract error
- verus: mechanical fidelity check by calling `sub_k` (body `admit()`) in the parent and running Verus
assemble and recurse
- replace each `sorry` with `apply lemma`; verus: call `sub_k(args)` in `assert ... by`
- subgoal reproducing itself means no progress, retry directly, then give up at a threshold (value not given)
- tree is wide and shallow, so siblings run in parallel
informal proof first
- numbered atomic steps, no "obviously"; verifier scores 3 times, accept only if all 3 pass; at most 16 rounds
- informal stage helped A2, cost more on A1
- side effect: exposed 4 wrong ProverBench statements (p6, p13, p20, p28)
  - verus takeaway: repeated rejection of the informal proof signals a wrong spec
formalize by mirroring informal steps
- one `have`/`calc` per step; initial attempt plus at most 4 repair rounds, then sorrify
- verus: one named intermediate `assert` per plan step so cuts stay local
hard mode: retriever for unknown identifiers + reasoner comment on strategy
- both together cost more than easy mode on 3 of 4 problems
- Putnam B1, B6 solved only in hard mode
failure tiers
- F1 leaf step fails: sorrify and extract
- F2 false intermediate claim: subgoal check flags it, regenerate parent
- F3 skeleton defect (wrong induction variable, case split): regenerate global plan
- no classifier assigns tier in advance
results
- Putnam 2025: easy 9/12, hard 11/12, A5 unsolved; single models at Pass@32 get 0/12
  - hard avg 114 min, $18.5; Numina 165 min, $72.7
- IMO 2025 (P1,P3,P4,P5): avg 197 min, $82
- miniF2F-test 242/244 (99.2%)
- ProverBench number theory 24/40 vs Hilbert 16/40
- note: paper has internal inconsistencies (Table 3 caption, A5 budget, Hilbert numbers read off plots)
threat: moderate as method, low as product
- same loop is cheap to rebuild for Verus with a general frontier model, no fine-tuning
