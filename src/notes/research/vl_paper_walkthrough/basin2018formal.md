# A Formal Analysis of 5G Authentication
(authored by agents unless marked 🧑)
Tag: `basin2018formal`, [paper](https://arxiv.org/abs/1806.10360)

## what is proved or measured
This paper formalizes 5G AKA from the 3GPP standard and analyzes confidentiality, authentication, and privacy. EAP-AKA’ is described for background in Appendix B, but is not the subject of the reported formal analysis. The authors extract assumptions and goals from technical specifications and requirements, then model protocol state and adversarial message scheduling in Tamarin (sections 3–5). The abstract says, “Using the security protocol verification tool Tamarin, we conduct a full, systematic, security evaluation of the model with respect to the 5G security goals.” Inference: the output is a set of proved lemmas, attacks, and minimal assumptions, not a proof that the standard text or deployed implementations are correct.

The paper identifies goals missing from the standard and attacks that appear when sequence-number concealment and re-synchronization are modeled. It reports that critical goals are not met except under additional assumptions missing from the standard, and gives provably secure fixes. Denominators are protocol variants and security goals, not percentages of all 5G deployments. Trusted artifacts include the formal model's faithful interpretation of 3GPP, Tamarin's symbolic semantics and proof engine, cryptographic assumptions, and any abstraction that omits implementation details. Inference: for Verus, the key lesson is to make assumptions and state transitions explicit before proving Rust code; protocol-model proofs do not establish memory safety or correctness of a Rust implementation.

## technique: extract a formal model from a standard
Use this for a large, ambiguous specification. First identify entities (subscriber, home network, serving network), messages, persistent state, cryptographic operations, and stated security goals. Then resolve terminology and omissions by writing an executable symbolic model. The authors say, “We extract and formally interpret the standard’s security assumptions and goals.” They model 5G AKA with sequence numbers, XOR concealment, and re-synchronization instead of replacing counters with stateless nonces (sections 2.2.2 and 4.3). Inference: a Verus implementation should define enums for protocol states and messages, pure specification functions for transcript and key derivation, and explicit `requires` clauses for long-term-key and freshness assumptions.

## technique: symbolic protocol rules and adversary scheduling
Tamarin represents protocol roles as multiset-rewrite rules. A rule consumes state facts and received messages, emits sends and new state, and records action facts for lemmas. Model the Dolev-Yao adversary by allowing network interception, replay, and composition of messages while keeping cryptographic primitives abstract. Then state correspondence, secrecy, and observational-equivalence lemmas and ask Tamarin to prove them or produce a trace. The paper emphasizes that AKA protocols have large flows and state machines and that privacy depends on re-synchronization behavior. Inference: Verus can encode each transition as a proof function preserving a state invariant, with `ensures` describing accepted messages and derived keys; adversarial traces are ghost sequences, not executable network code.

## technique: fine-grained security goals
Do not collapse authentication into one predicate. The paper checks confidentiality, mutual authentication, key establishment, user and network privacy, unlinkability, and key confirmation, including variants conditioned on synchronization and compromise assumptions. For each goal, state the exact event correspondence or secrecy property, run the model, and record the weakest assumptions under which it holds. The paper reports that automated analysis “identifies the minimal security assumptions required for each security goal.” Inference: in Verus, represent each goal as a separate lemma over a trace and avoid one broad `ensures` clause whose assumptions hide which party or phase is protected.

## technique: attack traces and repaired protocol rules
When a lemma fails, inspect the generated trace, locate the protocol branch that leaks identity or accepts an unauthenticated value, and change the corresponding standard rule. The paper found a privacy attack involving a desynchronization error message; prior analyses that assumed synchronized SQNs missed it. The authors then make “explicit recommendations with provably secure fixes for the attacks and weaknesses we found.” Section 5.3.2 repairs a session mix-up by sending `⟨SUPI, SUCI⟩` instead of `SUPI` in the final home-network response. Section 5.3.3 adds the serving-network identity to the challenge MAC, or replaces a full key-confirmation roundtrip with a one-way authenticated message. The authors verify these authentication repairs; a complete evaluation of privacy repairs remains future work (section 5.3.4). Inference: preserve the failing trace, repair the relevant transition, and rerun affected properties; port the same workflow to Verus by turning a trace into a regression theorem and proving that the repaired transition preserves secrecy/authentication invariants.

## technique: compare protocol variants and assumptions
The analysis compares 5G AKA with and without key confirmation, and with and without an additional assumption that the serving/home-network channel binds messages to the correct session (sections 4.3 and 5.2). For each property, prove it under one assumption set, then disprove each version formed by removing a single assumption. Section 4.4.3 reports 124 lemmas, about 1,000 lines for these lemmas, and approximately five hours to establish proofs and find attacks. The roughly 500-line protocol model handles an unbounded number of sessions; these figures describe this model, not deployed networks.

The prior-work discussion says sequence numbers were “abstracted away by nonces” (section 1, PDF p. 2), which removed persistent state and re-synchronization. Comparing other AKA protocols is proposed future work, not a completed EAP-AKA’ analysis. Inference: keep variant-specific state in distinct modules and prove implementation refinement rather than silently sharing assumptions.

## technique: inductive helper lemmas and proof-search strategies

Section 4.4.2 explains why default automation fails even on full executability. First prove that the subscriber’s sequence number strictly increases and the home network’s sequence number monotonically increases. The model represents natural numbers with multisets and comparisons with pattern matching, enabling induction. Use these helper lemmas in the security proofs and Python oracles to guide proof search. The authors report approximately 1,000 lines of Python and several person-months to write generic strategies. Oracles guide the search without changing which proof steps are sound (section 4.2). Inference: for Verus, first prove monotonic-state lemmas, then use them in protocol invariants; the Tamarin oracle code itself is not a Rust proof.

## techniques for the catalog
- standards-to-model extraction — turn prose specifications into explicit roles, states, messages, assumptions, and goals
- Tamarin multiset rewriting — model protocol transitions and Dolev-Yao scheduling with symbolic facts and rules
- fine-grained goal lemmas — state secrecy, authentication, privacy, and key-confirmation properties separately
- attack-trace repair — use counterexample traces to revise state transitions or message protection and rerun proofs
- assumption minimality — prove each goal and disprove versions with one assumption removed
- inductive helper lemmas — prove counter monotonicity and guide search with reusable strategies
