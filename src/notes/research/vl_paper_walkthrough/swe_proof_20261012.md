# SWE-Proof: real repository issues with a proof instead of tests
(authored by agents unless marked 🧑)
Tag: `swe_proof`, [arXiv 2609.21190v2](https://arxiv.org/abs/2609.21190v2)

swe-proof: Ma, Mikek et al. (Berkeley, Georgia Tech, UIUC, AWS), preprint under review
- results are author reports, artifacts promised not checked
- no Rust/Verus; backends Nagini, Velvet (Lean), pure Lean
benchproofer turns SWE-bench Verified (500 issues) into verified tasks
- per issue: spec, axioms, verifying reference impl, failing pre-fix impl, proof, Python patch
- also 242 of 266 SWE-bench Pro Python tasks
- spec writer sees the ground-truth patch, so benchmark specs say nothing about agents writing specs from an issue
reusable techniques
- verify only changed code, summarize unchanged callees with axioms
  - axiom may be weaker than callee as long as proof closes
  - axioms are a last resort: Nagini 264 axioms over 137 instances, pure Lean 3 total
  - axiom must never encode the fix
- two opposing loops refine each axiom
  - correctness: fuzzer runs the real callee, violation sends axiom back
  - usefulness: verifier must close proof with it
- mechanical spec gates
  - discrimination: pre-fix impl must fail
  - mutation: one-operator mutants must fail
  - hygiene: import allowlist, no sorry
- adversarial auditors must give an executable counterexample
  - too strong: spec disagrees with repo code
  - too weak: wrong impl verifies
  - successful attacks become permanent tests
- model-to-code link
  - conformance: run executable copy against real patched function
  - equivalence: each step is type refinement, axiomatized callee, or identical op
- leakage gate: spec must not let an auditor rebuild the patch
experiments: Claude Opus 4.8, all 500 instances, 250 steps
- tests miss defects: 26.8% of test-passing patches overturned by audit (85.0% pass → 58.2% survive)
  - inference: paper inconsistent about the control cell behind this, treat with care
- self-written spec does not help: 85.6/85.0/83.8% vs 85.0% baseline
- correct spec helps: 96.2/94.0/95.2%, +6.9 points over localization alone
- natural-language spec does not substitute
  - 17.8 points of pass rate come from patches distinguishable from ground truth
- spec synthesis alone passes five-property audit only 46.0/60.0/61.4%
  - faithfulness fails 42.5%, soundness 13.1%
  - unresolved instances fail audit 92.3% vs 50.5% resolved
- bottleneck is the self-constructed spec, not implementation or proof
trust boundary
- proved: rewritten model meets spec given axioms
- unchecked by proof
  - axioms true of real callee
  - model matches Python patch (agent-written translation, "weakest link")
  - spec matches issue intent
- auditor agreement (Fleiss κ 0.861) is not correctness
