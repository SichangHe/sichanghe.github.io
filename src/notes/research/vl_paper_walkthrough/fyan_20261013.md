# Fyan: A Human--AI Harness with Semantic Auditing for Document-Level Formalization
(authored by agents unless marked 🧑)
Tag: `zhao2026fyan`, [paper](https://arxiv.org/abs/2609.39228)

problem: lean passing does not mean the statement matches the source
- fyan audits statement fidelity between math doc and lean 4, before proof search
- result is lean/math only; every verus mapping is inference
- "a proof assistant checks the theorem, not whether it faithfully represents the source" (§1)
slot-paired semantic audit
- code cuts informal source and formal candidate into slots
  - binder domains, hypothesis conjuncts, goal conjuncts, used definitions
- model only writes one row per paired slot group: relation, conversion or argument, optional repair
- unpaired source slot is scored as omission by code
- source formula tree extracted and reviewed by a separate call before any lean is shown
- candidate comments stripped before judging
- fixed checklist: hypotheses present, no extra conditions, conclusion strength, notions realized, domains/types, non-vacuity
- verus mapping (inference)
  - slots = params, `requires` conjuncts, `ensures` conjuncts, `spec fn` bodies incl closed
  - domains_types = overflow, nat subtraction; non_vacuity = satisfiable `requires`, not `ensures true`
  - hard part: product requirements are rarely one quantified formula; no evidence for prose requirements
- failure: herstein 4.3.25, left ideal vs two-sided ideal; evidence present but verdict unaffected
polarity rule for admissible one-way changes
- conclusions may be stronger, assumptions weaker, never reverse
  - sign flips under negation and left of implication
  - slot at both polarities needs both directions
- omission = replacement: deleted conjunct is ⊤, deleted disjunct is ⊥
- changed quantifier domain needs adapter map, direction fixed by quantifier kind and polarity
  - adapters may not depend on future witnesses
- verus mapping (inference)
  - agent contract serves requirement iff A0 ⟹ A1 and G1 ⟹ G0
  - dropped `requires` conjunct ok, dropped `ensures` conjunct not
- sufficient, not complete; checker covers only ⊤ ⊥ ∧ ∨ → and fixed-domain quantifiers
model fills record, code computes grade
- grades: same 3, trivial equivalent 2, mutated 1, unaligned 0
  - grade 2 must name a conversion from a closed list
  - grade 1 needs bounded local proof
- statement grade = min over rows, omissions, checks (non-compensatory)
- grade ≥ 2 accepts and freezes; else localized repair request, ≤ 3 attempts
- malformed record repaired in form; valid unfavorable record never resampled
- no valid record after 3 tries = reject (fail closed)
- evidence: ConsistencyCheck, 300 items, DeepSeek-V4.1-Flash, inconsistent = positive
  - original labels: audit recall 0.873, precision 0.771, acc 0.807; direct judge 0.820, 0.939, 0.883
  - author re-verified labels: audit recall 0.777, acc 0.813; direct judge recall 0.636, acc 0.750; McNemar p=0.027
  - cost ≈ 0.15 CNY/item vs 0.007 for direct judge
- caveats
  - audit less accurate than direct judge on original labels
  - lead rests on author-relabelled data (Claude Opus 5.5 screening)
  - 10 of 300 runs had no valid record
  - all 46 misses are grade-2 acceptances; "standard unfolding" is widest entry
bridge obligation
- accepted grade-1 statement S1 needs machine-checked proof S1 → S0, S0 source-facing
  - evidence: object coverage e, hypothesis transfer a, claim transfer g
  - S0 itself audited before freezing
- default: grade 1 returned for repair; bridge only if threshold lowered to 1
- bridge certifies only S1 → S0, not that S0 is faithful
- verus mapping (inference): wrapper fn with source-facing contract calling convenient-contract fn; freeze the wrapper's contract
- no measured count of bridges
frozen signature and model-free completion gate
- accepted normalized signature bound to source, definitions, evidence; any edit makes certification stale
- agent's COMPLETE token is only a request
- gate per root: zero `sorry`, builds, signatures current, bridges discharged, certified, transitive axiom audit clean
- evidence: 7 of 343 ProofNet# failures were changed signatures
- gate checks statement unchanged, not right; ODENumLib passed with weakened statements
other harness techniques
- document units and dependency graph: model proposes, code checks coverage, acyclicity, recomputes topological order
  - lints for lost biconditionals, altered strict inequalities
  - verus mapping (inference): `<==>` → `==>`, `<` → `<=` lints
  - ODENumLib: 23 units, 20 closed, no ablation
- statement scaffold: all planned lemma statements with `sorry` bodies, vacuous targets rejected, read-only during proving
  - verus mapping (inference): `assume(false)` bodies, replace one at a time with signatures locked
  - ODENumLib: 9 of 19 retained scaffolds changed substantively
- advice as comments only: supervisor/human help cannot edit statements or state
  - mined skills admitted only if every named lemma exists in live env
  - no independent effect claimed
measured results
- FormalTCS 143 items: strict lean pass 86/143 (60.1%) vs 69/143 (48.3%) general agent harness
  - statement translation certified equivalent 8/143 vs 5/143
- ProofNet# prover alone: 216/343 (63.0%)
paper contradicts itself
- odenumlib built before audit existed, so no experiment runs audit + bridge + proving together
- 20 units in §3.4 vs 23 in appendix D; only 17 of 20 replay
- units counted formalized despite assumed hypothesis or one direction only
takeaways for verified-rust product (inference)
- low threat as competitor: lean math only, no executable code
- high relevance as weakest point: statements change during proving
- audit is a filter, not a guarantee: 46 of 206 inconsistent statements pass
