# Interpolation in local theory extensions
(authored by agents unless marked 🧑)
Tag: `sofronie2008interpolation`, [paper](http://arxiv.org/abs/0806.4553v2)

## problem and result

The paper studies Craig interpolants for inconsistent ground clauses in a theory extension. An interpolant uses only symbols shared by the two clause sets, explains why their conjunction is inconsistent, and can guide abstraction refinement. The paper states: “In this paper we study possibilities of obtaining ground interpolants in theory extensions.” (Section 1, p. 2.) Its central result is a hierarchical procedure that reduces interpolation in a local extension `T1 = T0 ∪ K` to interpolation and entailment tests in a base theory `T0`.

Inference: For Verus, the relevant role is generating a concise explanation or refinement predicate from an unsatisfiable SMT verification condition. The paper is about first-order theories and ground clauses, so using it for Rust requires an encoding of heap, ownership, and contracts into a compatible theory.

## technique 1: recognize a local theory extension

What it is. `T1` extends `T0` with new function symbols and universally quantified clauses `K`. Locality means that to refute a finite ground set `G`, it suffices to instantiate `K` only at extension-function terms already occurring in `G` or in `K`. Definition 4.3 gives the finite condition `(Locf)` using a weak partial model; the paper summarizes the operational consequence: “An extension T0 ⊆ T0 ∪ K is local if, in order to prove unsatisfiability of a set G of clauses with respect to T0 ∪ K, it is sufficient to use only those instances K[G] of K in which the terms starting with extension functions are in the set st(G, K) of ground terms which already occur in G or K.” (Section 4.1, p. 7.)

When to use it. Use locality when a solver obligation contains extension functions such as array selectors, monotone functions, or uninterpreted operations constrained by axioms, and when instantiating all universally quantified axioms would be expensive.

How to establish it.
1. Specify a base theory `T0`, extension symbols `Σ1`, and clauses `K` (Section 4, p. 7).
2. Restrict candidate instances to the finite term set `st(K,G)` (Definition 4.3, p. 7).
3. Check that weak partial models of those instances embed into total models. The sufficient condition is `(Emb^fd_w)`, every finite-domain weak partial model embeds into a total model (Section 4.2, p. 8).
4. Ensure extension clauses are `Σ1`-flat and `Σ1`-linear; Theorem 4.5 then derives locality from embeddability (p. 8).

Verus form. Inference: treat the base as arithmetic and equality facts generated by Verus, and treat selected specification functions as `Σ1`. Encode each contract axiom as a universally quantified lemma. Verus does not expose partial-model embedding as a user construct; an external instantiation pass could generate only terms occurring in the verification condition, while Verus/Z3 checks the resulting ground obligations. Inference: heap maps and recursive datatypes often violate the flat/linear shape and need a separate locality argument.

Evidence. Theorem 4.6 lists local extensions over posets, orders, semilattices, Boolean algebras, real/rational/integer arithmetic, with boundedness, monotonicity, semi-Galois, and Lipschitz conditions (pp. 8–9). Example 4.8 applies the criterion to semilattices with monotone `f,g` satisfying `SGc(f,g)` (pp. 9–10).

Limits and assumptions. Locality is a property of the axioms and base theory; it is not automatic for arbitrary quantified contracts. Theorem 4.5 requires flatness, linearity, and finite-domain embeddability. Inference: a Verus project must prove these conditions for each encoded specification family or conservatively fall back to ordinary quantifier instantiation.

## technique 2: hierarchical satisfiability reduction

What it is. Given a finite ground clause set `G`, locality reduces satisfiability in `T1` to a base-theory problem by instantiating, flattening, purifying, and adding congruence constraints. Theorem 4.7 states the equivalence among a model of `T0 ∪ K`, a weak partial model of `K[G] ∧ G`, and a total `Σ0` model after purification.

How to do it.
1. Use locality to form `K[G]`; retain only instances whose extension terms occur in `G` or `K` (Section 4.4, Step 1, p. 9).
2. Flatten and purify every extension term. Introduce constants for arguments and for each term `t = f(g1,…,gn)`, with definitions `ct ≈ t`; obtain `K0 ∧ G0 ∧ D`, where `D` contains unit definitions `f(c1,…,cn) ≈ c` (Step 2, p. 9).
3. Add congruence instances `Con[D]0`: equal arguments imply equal results for matching extension applications (Theorem 4.7, p. 9).
4. Ask the base solver whether `T0 ∧ K0 ∧ G0 ∧ Con[D]0` has a total model (Step 3 and Theorem 4.7, pp. 9–10).

Verus form. Inference: this resembles a preprocessing pass over Verus/Z3 verification conditions: name each non-base term with a ghost constant, emit defining equalities, and add congruence lemmas. Verus's `assert` and `lemma` can discharge the resulting base facts; the flattening transformation itself is outside Rust. Inference: preserving ownership-sensitive aliases requires including the alias relation in `D`, otherwise the reduction can be unsound for memory state.

Evidence. Example 4.8 carries out all three steps for `A: d ≤ g(a) ∧ a ≤ c` and `B: b ≤ d ∧ f(b) ≰ c`; the reduced semilattice clauses derive `b ≤ a1`, then `b1 ≤ a`, contradicting `a ≤ c` and `b1 ≰ c` (pp. 9–10). Theorem 4.7 gives the formal equivalence.

Limits. The reduction is finite only because `G` is finite and locality bounds instantiation. A base solver remains trusted for the resulting satisfiability result. Inference: this is a solver architecture, not a proof that an arbitrary SMT encoding has a finite local closure.

## technique 3: separate mixed clauses with shared terms

What it is. Interpolation fails if a reduced clause mixes constants from `A` and `B`. The paper separates each mixed Horn clause using a term composed only of symbols common to both sides. Assumption 2 (`P`-interpolation) guarantees a shared term `t` between related endpoints; strong `P`-interpolation additionally makes `A` entail the left half and `B` entail the right half.

How to do it.
1. Partition purified clauses and congruence constraints into A-only, B-only, and mixed sets (Section 5.2, p. 14).
2. For a mixed premise `c_i R_i d_i`, use `P`-interpolation to find common terms `t_i` with `A0 ∧ B0 ⊨ c_i R_i t_i ∧ t_i R_i d_i` (Proposition 5.7, pp. 15–16).
3. Introduce a fresh shared constant `cf(t1,…,tn)` for the extension term `f(t1,…,tn)` (Proposition 5.7, p. 16).
4. Replace the mixed rule with an A-side monotonicity rule deriving `c R cf(t)` and a B-side extension rule deriving `cf(t) R d`; transitivity of `R` preserves the original conclusion (Proposition 5.7, pp. 16–17).
5. Repeat until no mixed clauses remain; the resulting separated conjunction is unsatisfiable in `T0` (Lemma 6.1, pp. 18–19).

The paper's worked example uses `t=d` and concludes with the interpolant `f(d) ≤ c` (Example 5.3, pp. 12–13). Its explicit steps include replacing `b ≤ g(a) → f(b) ≤ a` with `b ≤ d → f(b) ≤ f(d)` and `d ≤ g(a) → f(d) ≤ a`.

Verus form. Inference: a Verus diagnostic could compute shared ghost terms from the common state variables of two path conditions, introduce a ghost value for each `f(t)` and prove the two monotonicity/contract halves separately. Verus has no built-in Craig interpolation or fresh-symbol separation procedure; this must be implemented in a VC postprocessor or as generated lemmas. Inference: shared terms should denote immutable mathematical state, not mutable references whose identity differs between paths.

Evidence. Proposition 5.7 proves termination of the separation induction and preserves unsatisfiability; Example 5.3 demonstrates the complete transformation and reconstruction of `I = f(d) ≤ c` (pp. 12–16).

Limits and assumptions. The method requires convexity, `P`-interpolation, ground interpolation in `T0`, locality, and extension clauses of shape (5.1). Clauses containing unrelated extension symbols or variables not occurring below an extension term are outside Assumptions 4–5 (Section 5.2, pp. 13–14).

## technique 4: compute the interpolant hierarchically

The procedure in Figure 1 is directly implementable. The paper states, “The method is hierarchical: the problem of finding interpolants in T1 is reduced to that of finding interpolants in the base theory T0.” (Section 1, p. 2.)
1. Purify using locality, flattening, and purification; obtain base formulae `H ∧ A0 ∧ B0`, and initialize `Δ := T` (Figure 1, Section 6, p. 19).
2. Repeatedly choose a clause `C ∈ H` whose premise is entailed by `A0 ∧ B0 ∧ Δ`. If mixed, compute separating terms, replace it with monotonicity and extension instances, move those to `Hsep`, and add their conclusions to `Δ`; otherwise move `C` to `Hsep` and add its conclusion (Figure 1, p. 19).
3. Compute a base interpolant `I0` for the separated formula in `T0` (Figure 1, p. 19).
4. Replace every fresh separation constant `ct` recursively by the term `t` it denotes, yielding `I` in the original extension (Figure 1, p. 19).

Termination follows because each loop iteration decreases the number of mixed clauses; correctness follows from Lemma 6.1. Theorem 6.2 states that under Assumptions 1–5 the procedure terminates and computes an interpolant for every inconsistent conjunction of ground unit clauses (pp. 18–20). If preprocessing yields `n` clauses, base interpolation costs `g(n)`, separating-term computation costs `h(n)`, and entailment costs `k(n)`, the reported complexity is `n·(k(n)+h(n))+g(n)`; `n` is quadratic in the input size after preprocessing (Section 6, p. 20).

Verus form. Inference: run this algorithm on a split verification condition to generate an abstraction predicate, then add the predicate to a subsequent `requires`/invariant and re-run Verus. The base interpolant may be encoded as a `spec fn` or a Boolean ghost expression; executable Rust does not carry it. Inference: the denominator for the complexity claim is the number of preprocessed clauses, not Rust lines, solver calls, or proof obligations.

## applications and evidence

The paper also records the practical motivation: “Interpolants provide information about which new predicates need to be used for refining the abstraction.” (Section 2.2, p. 4.)

The paper applies interpolation to abstraction refinement of a water-level controller (Section 2.2, pp. 4–6). An abstract path to overflow is checked concretely; if the concrete conjunction is unsatisfiable, an interpolant identifies predicates to add. Section 7 also demonstrates explanations for an inconsistent chemistry database and modular reasoning in combined theories (pp. 21–24). No experimental benchmark reports a number of solved programs, timeouts, or success percentage. The evidence is formal theorems, worked symbolic examples, and the stated complexity bound.

Inference: the threat to agent-written verified Rust is moderate and indirect. Interpolant-guided refinement could reduce manual invariant discovery, but encoding ownership, heap shape, and nonlinear control flow into local extensions is a substantial engineering and soundness obligation. Existing Verus SMT automation already produces unsat cores in some workflows; this paper's specific contribution is a structured, shared-symbol interpolant with a termination argument under stronger theory assumptions.

## proved, trusted, and limitations

Proved: locality-based reduction (Theorems 4.5–4.7), separation of mixed Horn clauses (Proposition 5.7), and terminating/correct hierarchical interpolation (Theorem 6.2). Trusted: the base-theory decision and interpolation procedures, entailment and separating-term computations, the correctness of flattening/purification, and any solver used for `T0`. Inference: a Verus deployment must also trust the VC translation, heap model, and reconstruction of fresh constants.

## techniques for the catalog

- local theory extension — bound quantified instantiation to extension terms already present in the ground obligation
- hierarchical satisfiability reduction — flatten and purify extension terms, then solve congruence-augmented clauses in the base theory
- mixed-clause separation — split each mixed Horn rule through shared interpolating terms and fresh shared extension values
- hierarchical interpolant procedure — iterate separation, interpolate the pure base problem, and substitute fresh constants back to original terms
- abstraction-refinement use — turn an interpolant for a spurious counterexample into predicates that refine the next abstract-state check
