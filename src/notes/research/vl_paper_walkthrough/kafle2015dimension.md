# Decomposition by tree dimension in Horn clause verification
(authored by agents unless marked 🧑)
Tag: `kafle2015dimension`, [paper](https://doi.org/10.4204/EPTCS.199.1)

## problem and result

The paper decomposes nonlinear constrained Horn clause (CHC) proofs by the tree dimension of derivations. Dimension measures branching: a list has dimension zero, while a complete binary tree's dimension equals its height. The abstract says: "A given set of Horn clauses P can be transformed into a new set of clauses P≤k , whose derivation trees are the subset of P’s derivation trees with dimension at most k." (Abstract, p. 1). The complementary program `P>k` represents derivations of dimension at least `k+1`. Proving both pieces proves the original program, and the pieces can run in parallel.

## technique 1: at-most/at-least dimension decomposition

What it is. For each predicate `H`, split it into `H≤d` and `H=d` for dimensions up to `k`. Linear clauses propagate dimension directly. For a nonlinear clause with `r` body atoms and target dimension `d`, the construction creates two kinds of clauses: one child has exactly dimension `d` and the others at most `d−1`, or two children have exactly dimension `d−1` and the remaining children at most `d−2` (Definition 2, pp. 2–3; the second kind needs `d ≥ 2` when `r > 2`). Epsilon clauses accumulate exact dimensions into at-most predicates. The at-least program `P>k` contains the renamed clauses of Definition 2, all original clauses of `P`, and link clauses `H≥0 ← H`, so that its `H>k` predicates generate derivations of dimension at least `k+1` (Definition 3, pp. 3–4; Fig. 4, p. 4). The paper itself notes that, because the original clauses are copied, this form is possibly "as hard as the original problem for P" (§4.2, p. 6), which motivates technique 2.

How to apply it. (1) Translate the program to CHCs with an integrity predicate such as `false`. (2) Choose `k=0,1,...`. (3) Generate `P≤k` using the linear, nonlinear, and epsilon rules. (4) Ask an existing sound CHC solver whether `P≤k` is safe. (5) Generate `P>k` and ask the solver. (6) If the result for `P≤k` is not safe (unsafe or unknown), return it; otherwise if the result for `P>k` is not unknown (safe or unsafe), return it; otherwise increase `k` and repeat (Algorithm 1, §3, pp. 4–5). The paper also suggests, as an optimisation, using `P>k` in place of `P` in the next iteration, since `P≤k` is already proved safe (§3, p. 4). Step (1) is the study's gloss on the paper's setting of CHCs with `false`-headed clauses (§3, p. 4). The paper's Fibonacci example uses clauses `fib(A,A)` for the base case and two recursive calls for the nonlinear case (Fig. 1, p. 2); its `Fib≤0` contains the base clause and the `false` clause but no copy of the recursive clause, so it covers only derivations of dimension 0 (Fig. 3, p. 3).

Evidence and proof obligation. The decomposition lemma states: "For all k, program P is safe if and only if both P≤k and P>k are safe." (Lemma 1, §3, p. 5). The algorithm is sound: a safe return means the original has a model, and an unsafe return means a feasible derivation of `false` exists (Proposition 1, §3, p. 5). The paper describes each such set of clauses as "an under-approximation of the original set of clauses" (§1, p. 1); Lemma 1 is what turns safety of both fragments into safety of the whole program.

Verus form. Inference: represent a recursive Rust computation as a ghost derivation tree and define a `spec fn` for its dimension. Generate separate proof obligations for trees with `dim ≤ k` and the residual `dim > k`; use `assert` and `proof fn` lemmas to combine their safety results. Verus does not manipulate CHC predicates or invoke an external CHC oracle automatically, so the transformation would be a preprocessor or proof-generation service. The executable Rust code can remain unchanged if the generated specifications faithfully model it.

## technique 2: finite tree automata difference

What it is. A trace finite tree automaton (FTA) has predicate symbols as states, clause identifiers as ranked constructors, and transitions `c(p1,...,pn) → p` for each CHC. Its language is isomorphic to successful and unsuccessful derivation trees (§4.1, pp. 5–6). To construct `P>k` without copying the original clauses, first eliminate epsilon clauses from `P≤k` by unfolding them, inherit each originating clause's identifier, build FTAs for `P` and `P≤k`, determinize their union, and remove states accepting a `P≤k` derivation. The resulting FTA difference accepts exactly trees of dimension greater than `k` (§4.2, pp. 6–9).

How to apply it. (1) Give each source clause a unique ranked identifier whose arity equals its body-atom count. (2) Unfold every `H≤d ← H=d` epsilon clause into copies of the underlying linear or nonlinear clauses. (3) Assign each unfolded clause the identifier of its source clause. (4) Build the trace FTA for the original and at-most programs. (5) Form the language difference by standardizing predicate names, taking the union, determinizing, and deleting states containing an accepting state of the at-most FTA. (6) Convert the resulting transitions back to CHCs using the inverse identifier map (§4.2, pp. 6–9). The determinisation uses an optimised algorithm [10] that returns a compact "product form" (§4.2.1, p. 8). The Fibonacci construction yields a program with predicates `fib_0`, `fib_1` and `fib`, in which derivations rooted at `false` have dimension at least 1 (Example 2, p. 8; Fig. 8, p. 9).

Verus form. Inference: a Verus proof generator could use an FTA to partition recursive call trees before emitting lemmas. The FTA and determinization are outside Verus; resulting predicates can become ghost tags or `spec fn` cases. The paper notes that "determinisation of FTAs is often considered prohibitively complex even for small FTAs" (§4.2.1, p. 8). A VL implementation should use it only when the residual proof is easier than the original.

## technique 3: dimension instrumentation

What it is. Add a final dimension argument `K` to every predicate. For each original clause, add dimension variables for body calls and a `dimn(K1,...,Kn,K)` relation implementing the tree-dimension recurrence (Definition 9, §5, p. 9). Base clauses use `dim0(K)`; two-child clauses use `dim2`; for the three-atom counting-change clause the paper composes two `dim2` calls into `dim3` (Fig. 10, p. 10; Fig. 12, p. 11). Existing Horn solvers can then prove bounds by checking an integrity constraint. For McCarthy's 91-function, the paper adds `false :- K > 2, mc91(X,Y,K)` and proves that all successful derivations have dimension at most 2 (Example 4, p. 10). For Fibonacci the paper states the property that the dimension is at most half the input value, expressed by `false:- fib(A,B, K), 2*K -1>=A` (Example 5, p. 10), and for counting change that the dimension is at most the number of coin kinds, via `false :- B>=1, K > B, cc(A, B, C, K)` (Example 6, p. 10). The paper says these are established by applying a Horn clause solver (Examples 4 and 5).

How to apply it. (1) Add a dimension argument to every predicate. (2) Add `dim0` for base clauses. (3) Add a relation implementing the dimension recurrence for each nonlinear clause. (4) Add an integrity constraint expressing the desired upper bound, lower bound, or relation to data. (5) Run a CHC solver; a safe result proves the dimension property (§5, pp. 9–11). The paper notes that deciding whether dimension is bounded by a constant is undecidable in general, and that verifying a given dimension "is as challenging as proving any other properties of the program" (§5, p. 10). Inference: this is a verification attempt, not a decision procedure. The paper also says that knowing the dimension bound 2 for `mc91` would let a proof of any property of successful derivations be restricted to `P[2]` (§5, p. 10).

Verus form. Inference: add a ghost natural `k` to recursive specifications and a `decreases` or ranking argument for the recursive call. Define dimension recurrence as a `spec fn`; prove bounds with `ensures` and `assert` lemmas. Verus's termination checker can establish a decreasing measure but does not automatically synthesize CHC dimension relations. Dimension instrumentation can nevertheless expose a structural measure useful for bounding proof search.

## evidence, trust, and limits

The exploratory evaluation uses 16 nonlinear CHC benchmarks and an abstract-interpretation solver over convex polyhedra with a five-minute timeout. The decomposition solves 14/16 with an average time of 4 seconds over solved problems; QARMC solves all, and an earlier finite-tree-automata refinement solves one additional problem (Table 1 and text, §7, p. 12). Of the 14 solved problems, 13 are solved with `k=0` and `running` with `k=1`; `triple` and `buildheap` are unsolved. The authors explain that "The splitting induced as a result of separating a set of traces has an effect on delaying join and widening operations during convex polyhedra analysis which increases its precision" (§7, p. 12); this is their explanation, not something the experiments isolate. The paper says the aim is not a systematic comparison with other techniques but "exploratory experiments" (§7, p. 12). These are benchmark counts, not a universal speed guarantee. Inference: the method trusts the CHC encoding, the SAFE oracle, convex-polyhedra abstract interpretation, FTA determinization, and the assumption, stated in §3 (p. 4), that if the oracle cannot decide `P≤k` it would also return unknown for larger `k`. The paper itself calls the results preliminary (Abstract; §8) and the experiments exploratory (§7). Separately, §8 (pp. 12–13) notes that a set of CHCs of bounded dimension can be turned into an equivalent set of linear CHCs (Afrati et al. [2]), with the complexity of that procedure still open.

The conclusion (§8, p. 12) reads: "We presented a program transformation approach to Horn clause verification using the notion of tree dimension to decompose the verification problem by separating dimensions." Inference: this describes a proof transformation, not a replacement for the underlying solver.

Inference: threat to agent-written verified Rust is low to moderate. Dimension partitioning can organize proofs of recursive, branching data structures and help parallelize residual obligations, but it does not prove that the Rust implementation matches the CHC model. A wrong dimension relation or omitted recursive branch can make a residual proof vacuous. The paper cites existing tree-automata refinement [19], CHC solvers [12, 19, 18, 17, 6] and Ganty and Iosif's dimension-based summaries [11] (§6, p. 11); VL should reuse such tools as proof-search infrastructure rather than claim a new decomposition principle.

## techniques for the catalog

- tree-dimension decomposition — split CHC derivations into at-most-k and residual at-least-k fragments and prove both
- FTA language difference — construct the residual derivations by subtracting the at-most fragment's trace automaton
- dimension instrumentation — add a ghost dimension argument and recurrence relations so CHC solvers can prove dimension bounds
