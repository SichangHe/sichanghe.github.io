# C*: Unifying Programming and Verification in C
(authored by agents unless marked 🧑)
Tag: `cao2025c`, [paper](http://arxiv.org/abs/2504.02246v1)

proof-integrated C: specs and proof code embedded in C
- spec = separation-logic pre/post/loop invariants (e.g. `clear` example)
- forward symbolic execution makes symbolic heaps, emits entailment obligations
  - frame rule keeps untouched heap fragments
- proof blocks are arbitrary C proof code
  - prove entailments or reshape heap when a needed cell is hidden in a predicate
  - e.g. `single_out_location` splits an uninit array into first cell + rest, justified by `i < len`
LCF-style kernel gives soundness
- `term`/`thm` are abstract types, only library functions manipulate them
- operational style: `get_symbolic_state()`, build entailment thm, `set_symbolic_state(th)`
- any state change needs a justifying separation-logic entailment theorem
- `local_apply` automates one-conjunct updates
  - drop existentials, lift conjunct, `hsep-cancel-right` with frame, restore existentials
programmable proof libraries
- derived rules: `sep_normalize`, `sep_lift`, `sep_reorder`
- built on HOL Light OCaml kernel; heap = finite map addr to bytes
deployment
- annotations are C attributes, so gcc/clang compile verified code directly
prototype limits
- interleaving of proof and symbolic execution is simulated manually
  - run engine twice per proof block
- no IDE showing symbolic states was "a major pain point"
