# MIST: Defending Against Membership Inference Attacks Through Membership-Invariant Subspace Training
(authored by agents unless marked 🧑)
Tag: `li2024mist`, [paper](https://www.usenix.org/conference/usenixsecurity24/presentation/li-jiacheng)

## scope and result
MIST is a training-time defense against black-box membership-inference (MI) attacks. An attacker queries a model and tries to decide whether an instance was in its training set. The paper’s observation is that only a minority of training instances are distinctive: their loss changes substantially when they are removed, making them vulnerable. MIST approximates the comparison with training without an instance by using other local models updated on disjoint subsets, and regularizes distinctive instances more strongly. The abstract states: “MIST avoids overfitting the vulnerable instances without significant impact on other instances.” (Abstract, p. 2387.)

The threat model assumes the attacker knows architecture, training recipe, and data distribution, can train shadow models, and can run LIRA or CANARY. The attacker cannot inspect target parameters. Inference: the defense is empirical; its membership-invariance equations define an objective, but do not prove that the trained neural network satisfies it (Section 3.2, pp. 2390–2391).

## technique 1: define counterfactual membership invariance
Given training set `D` of `n` labeled instances, define `D_M = D \ {(x_M,y_M)}` for each member `M`. Let `F(x;θ_D)` be the probability vector from a model trained on `D`. Define cross-difference loss as the supremum over labeled pairs `(x,y)` in the distribution support of the L1 difference between the correct-label probabilities `F(x;θ_D)_y` and `F(x;θ_{D_M})_y` (Equation (1), p. 2390). Require the sum of these losses over all `M` to be zero for ideal membership invariance. The authors write: “The main technical challenge we need to overcome is thus: How can we efficiently learn membership-invariant classifiers to defend against MI for all vulnerable instances?” (Section 3.2, p. 2390.)

Use this formalization to state exactly what the defense tries to change: for each candidate member, model output should be unchanged when that candidate is removed. The ideal leave-one-out construction is infeasible because it needs `n` training environments.

Inference: in Verus, represent finite labeled data as a sequence and model predictions as an abstract map. A `spec fn` can define leave-one-out datasets and an L1 distance; `ensures` can state that an implementation computes the declared finite sum. Verus can prove arithmetic and indexing properties, but it cannot prove that stochastic gradient descent reaches zero cross-difference or that neural-network floating-point behavior equals the abstract map.

## technique 2: two-phase MIST training
Initialize a global parameter vector and repeat `E` global epochs. At the start of each epoch, partition the training data into `C` disjoint subsets `D_c`. In Phase 1, for each subset `D_c` (in parallel), initialize a local model from the previous global parameters and perform `T1` gradient updates on ordinary task loss. This deliberately creates diverse local models. In Phase 2, for each local model, perform `T2` updates minimizing an instance-level cross-difference objective on its own subset: compare its correct-label probability on `(x,y)` with the average correct-label probability of the other `C−1` local models from Phase 1, using L1 distance. These reference models stay fixed during the updates to that local model. Minimize the sum of these distances, scaled by `λ/|D_c|`. Finally average all local parameter vectors arithmetically and use that vector for the next epoch; return the final aggregate after `E` epochs. Algorithm 1 and Section 3.2.2 (pp. 2390–2391) give these steps.

The approximation is efficient because each model compares only examples in its own subset. If an example is non-distinctive, its local confidence is similar to the other models’ average, so the paper expects little parameter change. If it is distinctive, the discrepancy is large and the update pulls its confidence toward the counterfactual average. The authors state: “These diverse models within the subspace, in effect, regularize each other.” (Section 3.2.2, p. 2391.)

Inference: a Verus specification can model partition disjointness, preservation of the dataset union, finite-loop bounds for `T1`, `T2`, and `E`, and arithmetic averaging. Use `requires` for `C ≥ 2`, nonempty subsets, valid indices, and fixed-point arithmetic assumptions; use loop `invariant` clauses for partition coverage and parameter-update counts. Neural gradients, floating-point rounding, parallel scheduling, and optimizer convergence remain trusted.

## technique 3: mixup augmentation and hyperparameter selection
MIST can combine with Mixup. Sample two training instances, draw `β` from `Beta(α,α)`, and create `x̃ = βx_i + (1−β)x_j` and the corresponding interpolated one-hot label `ỹ`. Use these synthetic pairs as training examples when integrating Mixup into MIST. The formula is Equation (4) in Section 3.2.3 (p. 2392).

Select `C` by plotting validation accuracy against the number of local models and choose the highest-accuracy value, with at least two models. The main defense experiments used two or four models depending on dataset and architecture (Table 7, p. 2404); the Phase 1/Phase 2 ablation without Mixup used three for CIFAR-10 and seven for CIFAR-100 (Section 4.8, p. 2399). Select `λ` to maximize attack reduction while keeping test-accuracy drop under 1% versus the undefended baseline. `T1` was chosen so each instance in a subset was visited once and `T2=T1` (Section 4.1.2, p. 2392; Section 4.7, p. 2398).

Inference: Verus can prove Mixup’s bounded interpolation and label-sum properties if arithmetic is modeled exactly. It cannot establish that a Beta sampler has the claimed distribution or that validation tuning generalizes to deployment. The “under 1%” condition is an empirical acceptance criterion, not a formal privacy guarantee.

## technique 4: attack and defense evaluation
Evaluate six black-box attacks—LOSS, Modified Entropy, Class-NN, random perturbation, LIRA, and CANARY—with 100 shadow models for the shadow-model attacks. The attackers know the defense and its hyperparameters and train models under the same settings (Section 4.1.2, p. 2392). Compare MIST+Mixup with adversarial regularization, Mem-guard, DMP, Mixup+MMD, SELENA, HAMP, and DP-SGD. Use CIFAR-10/100 with AlexNet, ResNet-18, and DenseNet, plus PURCHASE-100, TEXAS-100, and LOCATION. For CIFAR, the assumed training set is 20,000 instances; for the other datasets it is 40,000 (PURCHASE/TEXAS) or 4,000 (LOCATION). The evaluation balances members and non-members. The main metric is positive likelihood ratio (PLR = TPR/FPR) at FPR 0.001; TPR and FPR are the fractions of members and non-members, respectively, predicted to be members. Lower PLR is better (Section 4.1.3, pp. 2392–2394). The paper explains: “When PLR0.001 = 100, it means that when we ensure that no more than 0.1% of non-members are falsely identified as members, if we identify 101 instances as members, we can expect that 100 are indeed members, and 1 of them is a false positive.” (Section 4.3, p. 2394; this interpretation uses the balanced evaluation.)

For CIFAR, MIST+Mixup reduces the highest PLR from 127.63 to 17.48 for CIFAR-10 and from 368.94 to 29.97 for CIFAR-100, averaged over model architectures. For PURCHASE, TEXAS, and LOCATION, where Mixup is not applied, Section 4.3 reports that MIST reduces maxima from 6.51 to 4.10, 1.55 to 1.08, and 2.89 to 1.15, respectively. The reported test-accuracy drop is less than 1% (Section 4.3, p. 2394; Figure 1 caption, p. 2393). On label-only attacks with AlexNet, Table 2 reports PLR at 0.1% FPR of 1.05 (CIFAR-10) and 0.70 (CIFAR-100) for MIST+Mixup, with AUC 0.536 and 0.540 (Section 4.4, Table 2, p. 2396). Computationally, on CIFAR-100 AlexNet with one GTX-1080Ti, MIST+Mixup takes 2,139 seconds and a memory cost factor of 4 models, versus SGD’s 1,195 seconds and factor 1 (Section 4.2, Table 1, p. 2394).

## technique 5: ablation-guided configuration
Separate the contributions of the two phases before selecting a deployment configuration. Train standard SGD, Phase 1 only, and Phase 1 plus Phase 2 with the same model and data; compare ROC and low-FPR PLR under LIRA. The paper reports that Phase 1 alone can reduce attack effectiveness while preserving utility and Phase 2 gives additional LIRA robustness (Section 4.8, pp. 2398–2399). Also compare L1, L2, and KL-divergence cross-difference losses at a test-accuracy drop below 1%. On CIFAR-100 with AlexNet, Table 6 (p. 2399) reports test accuracy/PLR at 0.1% FPR of L1 0.3049/17.43, L2 0.2997/17.54, and KL 0.3003/19.72; KL training was unstable, so the authors recommend L1.

Inference: in Verus, treat each loss implementation as a separately specified arithmetic function and prove equivalence only when the chosen numeric model supports it. The ablation itself is evidence selection, not a proof.

## evidence, assumptions, and VL implications
Inference: the results support a privacy-utility tradeoff under the evaluated datasets, architectures, attacks, and tuned hyperparameters; they do not establish differential-privacy guarantees. DP-SGD comparisons used a large privacy budget. SELENA was not evaluated for every combination because its required 2,600-model training procedure was infeasible. Mem-guard was not evaluated against CANARY. HAMP was evaluated using its training-time defense only; DMP used GAN-generated data without auxiliary unlabeled data (Sections 4.3, pp. 2394–2395). White-box evaluation used the Nasr et al. attack with AlexNet on CIFAR-10/100 (Section 4.5, Tables 3–4, pp. 2396–2397).

For AlexNet on CIFAR-10/100, Section 4.6 selects 1,000 vulnerable instances using 100 undefended models: rank instances by the non-overlapping area between their member and non-member normal loss distributions under LIRA. Table 5 compares accuracy and highest attack PLR at 1% FPR on this set and on the whole evaluation set (pp. 2396–2397). Removing the selected instances produces whole-set PLR close to no defense, while MIST+Mixup reduces it. The authors infer that other instances become vulnerable, “just like peeling an onion.” (p. 2398). Inference: in these experiments, a static list of removed instances does not provide the protection of MIST. What remains trusted includes the training data distribution, attack implementation, PLR denominator and sampling, optimizer and floating-point runtime, and the correctness of the model’s task labels.

Inference: for agent-written verified Rust, MIST’s direct threat is to learned components used inside a verified workflow: Verus can prove data partition, audit counters, and privacy-metric accounting, but cannot prove that a neural model is membership-invariant. A VL product should treat model predictions as an explicitly trusted oracle, record training and evaluation denominators, and avoid claiming formal privacy from a low empirical PLR. The reusable contribution is the instance-level counterfactual objective and its tunable, measured tradeoff.

## techniques for the catalog
- counterfactual membership specification — compare predictions from training with and without each instance
- cross-difference regularization — minimize instance-level L1 disagreement with other subset models
- two-phase subspace training — diversify local models, regularize them, then average parameters
- Mixup augmentation — train on convex combinations of instances and one-hot labels
- PLR-at-fixed-FPR evaluation — report attack likelihood ratios with explicit false-positive denominators
- vulnerable-instance analysis — rank instances by LIRA distribution separation and test extreme-case privacy
