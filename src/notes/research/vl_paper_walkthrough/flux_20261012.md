# Flux: Liquid Types for Rust
(authored by agents unless marked 🧑)
Tag: `lehmann2023flux`, [paper](https://doi.org/10.1145/3591283)

what is proved and trusted
- theorem 3.1: well-borrowed evaluations of well-typed programs do not get stuck
  - soundness is under a Stacked Borrows dynamic borrow checker
  - assumes rust's borrow guarantees, does not re-prove the compiler or unsafe code
- evaluation is an empirical comparison with Prusti, not proof of general functional correctness
indexed refinement types on rust types
- indices on base types: `i32[n]`, `RVec<T>[n]`; existential predicates for ranges e.g. `usize{v:v<n}`
- rvec api
  - `len(&RVec<T>[@n]) -> usize[n]`
  - `get` requires `idx: usize{v:v<n}`, so bounds checks become ordinary typed calls
  - `push(&strg RVec<T>[@n], value:T) ensures *self:RVec<T>[n+1]`
- limit: lightweight properties only
  - paper says Prusti can verify deep properties e.g. sortedness that Flux cannot
ownership-aware strong references
- `&mut` preserves the index, `&strg` records a strong update that changes it
  - e.g. `incr(x: &strg i32[@n]) ensures *x:i32[n+1]`
- pipeline: spatial phase infers locations, then horn constraints, then liquid inference solves them
- no user loop annotations needed in the benchmarks
polymorphic liquid inference replaces quantified invariants
- put the universal property in a refined element type, infer a quantifier-free predicate
  - kmp: Prusti needs `forall x, x<t.len() ==> t.lookup(x)<i`, Flux infers it via polymorphism
- inference: richer relations between elements may not fit quantifier-free templates
measured comparison (table 1, 8 benchmarks, 7 algorithms + Wave modules)
- spec lines 145 for 944 rust loc (Flux) vs 315 for 921 (Prusti)
- loop annotations: 0 lines (Flux) vs 88 lines, 9% of loc (Prusti), max 24% for heapsort
- total verification time 7.13 s vs 246.65 s
  - fft 0.70 s vs 166.76 s, Wave 4.50 s vs 28.74 s
  - authors speculate the gap is quantified loop invariants in the SMT solver
- overflow: paper says Flux can verify absence statically, examples assume run-time checks
