# Lemur: Integrating Large Language Models in Automated Program Verification
(authored by agents unless marked 🧑)
Tag: `wu2023lemur`, [paper](https://arxiv.org/abs/2310.04870v5)

sound LLM-verifier interface (Wu, Barrett, Narodytska, ICLR 2024)
- LLM proposes predicates; they stay assumptions until a sound verifier V proves them invariant
- calculus of transition rules with soundness proof (Thm 3.1)
  - trust base: V soundness, assumption semantics, parser; LLM output never trusted
assumption-trail decomposition
- property p = <predicate, line>; V(P,A,p) returns TRUE/FALSE/UNKNOWN
- state <P,A,M>: M = trail of goals, A = empty or one proposed assumption q
- on UNKNOWN, propose earlier q; if V(P,{q},p) is TRUE, prove q recursively, compose q -> p
- example: prove x != 30 for loop adding 4 via x % 4 == 0
- Verus (inference): q as invariant/lemma precondition, p as ensures
  - never `assume` as final certificate; trail = ghost list in an external driver
transition rules
- propose, decide, repair 1 (implication UNKNOWN), repair 2 (q proved false), backtrack, success 1/2, fail
- fail only when the original goal is falsified
- success 2 (stable case split): q -> p and not q -> p both proved, q itself unproved
  - Verus (inference): `if q {..} else {..}` with both branches proving the target
- program P never changes, only proof state
bounded terminating algorithm (Algorithm 1)
- at most k proposals per goal; q must have a smaller line number than p
- returns SUCCESS / FAIL / UNKNOWN; terminates (Thm 4.1)
- bounds trade completeness for predictability; no guarantee a candidate is found in k
- Verus (inference): replace line number with a ghost rank (e.g. unresolved loops before target)
prompt as verifier-facing parser
- format: `assert(...);// Line number`; "Don't explain"; chain-of-thought was verbose and unreliable
- named markers (`// Line A`) at loops because models miscount lines
- sample several times, parse, dedupe by AST, rank by frequency then shorter expression
- Verus (inference): symbolic labels, grammar over invariant/requires/ensures, compile before verify
backends
- ESBMC (k-induction), UAutomizer (predicate abstraction), 30s timeout per call
- k-induction incomplete (Appendix A)
- Verus (inference): SMT VC generator is V; timeout maps to UNKNOWN, never FALSE
results
- Code2Inv, 133 benchmarks, 10 min limit
  - ESBMC alone 68, Lemur GPT-3 103, GPT-4 107
  - avg solved time 0.34s / 35.6s / 32.9s; proposals 0 / 8.6 / 4.7
- SV-COMP, 47 hard benchmarks (baselines unsolved in 10 min), 15 min limit
  - baselines 1 each, GPT-3 14, GPT-4 25 (7.2 proposals, 234.5s avg)
  - reruns GPT-4: with repair 25/24/24, without 19/20/20
- internal inconsistency: prose says 12 of 26 solved vs 25 in table
- no proof sizes or failure taxonomy; transfer to Rust/Verus untested
