## 1. VerusBelt: A Semantic Foundation for Verus’s Proof-Oriented Extensions to the Rust Type System

Authors: Travis Hance, Laila Elbeheiry, Yusuke Matsushita, Derek Dreyer. PACMPL 10, PLDI, article 247, June 2026; DOI 10.1145/3808325. [Author/project PDF](https://iris-project.org/pdfs/2026-pldi-verusbelt.pdf#page=4). Query phrase: VerusBelt semantic soundness implementation. Selected to prevent treating semantic foundations as missing prior work.

Exact quote, §1, Non-goals: “We do not attempt to verify the actual implementation of Verus itself”. Fact: §6 covers primitive proof-oriented APIs, lifetimes, sharing and mutable references in an idealized language; Rocq/Iris mechanization. Task: semantic soundness. Dataset/benchmark, numerical baseline and performance metric: not applicable; theorem and API coverage are the result. Limit: §6 distinguishes real Rust layout/provenance, actual verification-condition generation, solvers and ghost erasure from the model. It does not claim these components contain bugs. Negative evidence: proving Verus types sound is already a substantial contribution. Relation: the proposed target is actual translation behavior, rather than re-proving these types. Confidence: high. Primary peer-reviewed paper; full public PDF freshly retrieved and hashed. Its bytes differ from the existing collection copy; both were preserved, without assuming substantive version differences.

## 2. Verifying Verus: A Lean 4 Formalization of the SST-to-AIR Expression Translation

Author: Shuge Rong. CMU master's thesis, May 2026; committee Jeremy Avigad and Bryan Parno. [Institution PDF, printed p.56](https://www.andrew.cmu.edu/user/avigad/Students/rong_ms_thesis.pdf#page=57). Query phrase: Verifying Verus SST AIR Rong thesis. Selected as the closest translation formalization.

Exact quote, §5.1, printed p.56: “The proof of the soundness theorem itself is not completed.” Fact: gives expression semantics, AIR models, a Lean translation and representative proof cases. Task: translation soundness; benchmark/baseline and performance metric: not applicable. Result: infrastructure and partial mechanization, not a finished proof of the production translator. Limit: §5.1 excludes array primitives and parts of prelude/bitvector reasoning; §5.2 identifies other pipeline stages as future work. Negative evidence: defining another expression model alone duplicates this work. Relation: use its semantics where compatible; test the production implementation and identify unsupported constructs explicitly. Confidence: high in quoted scope. Primary thesis, not a peer-reviewed completed-verification result; full PDF freshly retrieved.

## 3. Validating the eBPF Verifier via State Embedding

Authors: Hao Sun, Zhendong Su. OSDI 2024, pp.615–630. [Official proceedings page](https://www.usenix.org/conference/osdi24/presentation/sun-hao). Query phrase: verifier validation concrete state embedding. Selected because concrete-state oracles for verifier logic are established.

Exact quote, abstract, p.615: “uncovered 15 previously unknown logic bugs”. Author claim: within one month, ten fixed at publication and two exploitable. Task: test abstract-state overapproximation by embedding concrete runtime states and a failure sink into accepted eBPF programs. Dataset: eBPF programs and Linux verifier versions in the paper's evaluation. Baseline: existing eBPF fuzzing/testing and prior range-analysis verification; metric: discovered/confirmed logic bugs, not a universal detection rate. Limit: verifier-specific instrumentation and observed states; no arbitrary Rust or SMT verifier completeness guarantee. Negative evidence: execution-derived verifier oracles are already demonstrated. Relation: our proposed contribution must show value from Verus-specific translation interactions and witness localization, beyond applying this idea. Confidence: high in abstract/method extraction; medium in transfer inference. Primary peer-reviewed paper, full existing collection PDF reread and hashed. Fresh USENIX PDF requests returned 403; no fresh download is claimed.

## 4. Alive2: Bounded Translation Validation for LLVM

Authors: Nuno P. Lopes, Juneyoung Lee, Chung-Kil Hur, Zhengyang Liu, John Regehr. PLDI 2021, DOI 10.1145/3453483.3454030. [Author PDF](https://web.ist.utl.pt/nuno.lopes/pubs/alive2-pldi21.pdf#page=1). Query phrase: bounded translation validation compiler semantics. Selected as direct method-level competition.

Exact quote, abstract: “we discovered and reported 47 new bugs”. Author claim: 28 fixed at publication; eight language-reference patches. Task: check refinement of LLVM IR pairs. Dataset: LLVM unit tests plus transformations in the evaluation. Baseline: compiler validation approaches and existing LLVM tests; metrics include bug yield and validation resource costs. Limit: bounded loop unrolling can miss bugs; IR semantics and undefined behavior require careful modeling. Negative evidence: independent semantic checking of translations is established. Relation: a generic translation validator is not new; Verus-specific semantics, generated adversarial obligations and localization must provide measurable value. Confidence: high. Primary peer-reviewed paper; full PDF freshly retrieved, different bytes preserved alongside prior collection file.

## 5. Verus: Verifying Rust Programs using Linear Ghost Types

Authors: Andrea Lattuada, Travis Hance, Chanhee Cho, Matthias Brun, Isitha Subasinghe, Yi Zhou, Jon Howell, Bryan Parno, Chris Hawblitzel. OOPSLA 2023; inspected extended arXiv v2, March 11, 2023, 2303.05491. [Primary extended paper](https://arxiv.org/abs/2303.05491v2). Query phrase: Verus linear ghost types mode erasure formalization. Selected to delimit existing semantics.

Exact quote, abstract: “prove type safety and termination of specifications and proofs”. Fact: formalizes linearity, borrowing and modes in a small calculus; demonstrates pointers, interior mutability and concurrent examples. Task: Rust systems verification with linear permissions. Dataset: case-study examples; baseline: alternative verification approaches discussed, not a uniform measured competitor benchmark. Metric/result: formal theorem coverage and demonstrated verification examples. Limit: small formal model does not itself verify every production translation pass. Negative evidence: mode separation and ghost termination already have a formal account; erasure research cannot claim a blank slate. Relation: finite expression testing should initially exclude ghost erasure and concurrency, rather than promise unsupported whole-language semantics. Confidence: high. Primary paper; arXiv extended version differs from publisher bytes, preserved separately.
