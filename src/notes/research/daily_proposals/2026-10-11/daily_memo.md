# Preserve parser results across fragmented input
(authored by agents unless marked 🧑)

Status: provisional proposal. Literature novelty, advisor fit and realistic implementation feasibility remain unresolved.

Build a small Verus library for parsers that pause when input runs out and resume on the next delivery. The proposed guarantee is that every partition of the same ordered bytes produces the same final values, consumed positions and error class, with a proved bound on parser-owned state. Start with a dependent length-prefixed format, then TLS 1.3 ServerHello and extension framing. Exclude TLS cryptography, record processing and handshake state. The artifact would be a resumable state machine, compositional transition proofs and a reproducible fragmentation harness.

This develops the parser alternative screened locally on October 10. It is new relative to recent delivered and final daily proposals, not an independently discovered idea. Today's substantial addition is stronger contrary literature, a pinned current Vest interface check, and a narrower semantic proposal. Unlike October 10's selected allocator-cost family, this studies parser behavior under arbitrary input arrival partitions; a generic credit library or another work-bound theorem is not its contribution.

## Evidence and the strongest objection

[Vest, USENIX Security 2025, PDF p.6](https://www.usenix.org/system/files/usenixsecurity25-cai-yi.pdf#page=6) says: “The parse function operates on byte slices”. Its future-work discussion, PDF p.16, names “supporting streaming formats, which would allow for incremental parsing of large data streams”. This is a paper-era boundary, not proof of current absence. A focused check of pinned commit `11af01ddaef76cceded03517cd48764adb9d35b1` found that its `NoLookAhead` [proof trait](https://github.com/secure-foundations/vest/blob/11af01ddaef76cceded03517cd48764adb9d35b1/vest_lib/src/core/proof.rs#L220-L249) promises that buffers sharing a successfully parsed prefix “parse to the same value”. The trait defines a useful contract; whether the selected combinators or TLS target implement it is unverified. The inspected [Pair implementation](https://github.com/secure-foundations/vest/blob/11af01ddaef76cceded03517cd48764adb9d35b1/vest_lib/src/combinators/tuple/exec.rs#L37-L52) calls `self.0.parse(ibuf)?` and then `self.1.parse(&rest)?`; second-field failure returns an error without a first-field continuation. This narrow observation does not establish repository-wide lack of streaming.

The strongest contrary source is [EverParse3D, PLDI 2022, PDF p.3](https://www.normalesup.org/~ramanana/research/everparse/pldi2022/paper.pdf#page=3): “Parsing from non-contiguous or streaming data sources, with on-demand fetching of data”. Its §3.2, PDF p.7, supports formats that “don’t fit in memory” and says consuming a byte makes it “provably impossible to read that byte again”. Thus verified streaming, large-input handling and consumption permissions are established prior art. Its same passage states: “The behavior of actions is underspecified”. That qualifies action guarantees; it does not imply the input-stream model is weak or unsound. A public code audit may defeat this entire proposal.

[EverParse, USENIX Security 2019, §4.4, PDF p.9](https://www.microsoft.com/en-us/research/wp-content/uploads/2019/05/20190601everparse.pdf#page=9) describes input as “a slice” with length and position. Its strong-prefix theory and round-trip guarantees are prior work. [PulseParse, arXiv v2, PDF p.7](https://arxiv.org/pdf/2505.17335v2#page=7) describes “incremental, mostly zero-copy parsing” through partial views with pointers into an input array. Its abstract already guarantees “a constant amount of stack space”. Neither incremental traversal nor bounded stack is a new contribution.

[Leapfrog, PLDI 2022, abstract](https://arxiv.org/pdf/2205.08762v1#page=1) makes equivalence proofs “fully automatic and push-button”. It supplies relational methods for parser automata; a generic parser-equivalence claim would overlap. [Narcissus, ICFP 2019, abstract](http://adam.chlipala.net/papers/NarcissusICFP19/NarcissusICFP19.pdf#page=1) derives encoders and decoders that “form inverses of each other”. Round-trip correctness is occupied. Its §6 discusses fixed-length byte buffers and unverified extracted representations. These are author results and scope statements, not reproductions today.

The unsupported gap is whether a useful generic library lacks the exact conjunction of caller-visible suspension, terminal equivalence across all arrival partitions and a retained-state theorem. Six reviewed papers cannot establish that absence. No “first” claim is justified. EverParse3D is a mandatory prior-art baseline, not optional related work.

## Proposed contract for the first pilot

The first machine parses one length-delimited message. The caller creates a new machine for the next message. Freeze a deterministic reference result: either `Accepted(value, consumed_length, suffix)` or `Rejected(error_class, logical_offset)`. Provisional payload events normalize into that value; there is no independently observable committed event trace before acceptance. Success can leave a suffix for the caller and does not require EOF. `finish` signals EOF only while the message is incomplete; it returns Truncated. A previously detected malformed or oversize result remains sticky. At a completed length field, check arithmetic overflow/malformed encoding first, then oversize policy; EOF is considered after all supplied bytes have been processed. These rules must match the reference.

`feed(chunk)` returns `(consumed_length, NeedMore | Accepted | Rejected)`. Consumed bytes become part of the machine's logical history even when it returns NeedMore; the caller never refeeds them. The unconsumed suffix remains caller-owned and is never copied into the parser. NeedMore consumes the supplied chunk after incorporating any partial field state. Acceptance stops exactly at the message boundary; rejection stops at the first decisive error offset. No reference to a chunk survives the call. Pro's illustrative API omitted consumed-length handling; this proposed contract corrects that ambiguity. These are planned semantics, not an implemented API.

For every finite partition π of x, feed chunks until a sticky terminal result or exhaustion, then finish if incomplete. Normalize provisional payload fragments into the accepted value. The result must equal the reference on x: value, consumed length and suffix on success, or error class and logical offset on rejection. On early success the suffix includes unread bytes from the current and subsequent chunks. On rejection later bytes are ignored. NeedMore counts, event-fragment sizes and timing are excluded observations. All-input rejection is a different reference policy and is outside this first one-message contract.

Prove each state transition preserves a relation to the logical accumulated input and parse offset. Require conservation, not just disjointness: the concatenated delivered prefix is partitioned exactly into consumed logical history and caller-owned remainder. Within consumed history, completed fields and the current partial field cover each position once; emitted tentative payload bytes correspond exactly to their history intervals. The reference cursor and executable cursor agree under this relation. Ownership of copied partial input transfers to machine state; caller buffers may then be released. The full logical history is ghost state, not retained executable memory. This does not mean each byte is physically loaded once. Prove arithmetic safety, progress at EOF and early oversize rejection before body-sized allocation.

Declare finite format parameters before proof: maximum partial-header width H, nesting depth D, per-level metadata width K, fixed machine metadata M, and aggregate materialized-value cap C. Count allocated capacity, copied partial fields, deferred values and parser-owned event queues. For the first implementation use fixed storage and synchronous sink calls with no parser-owned queue. Proposed sink-mode bound is M + D*K + H bytes; materializing-mode bound adds C. Constants must come from the actual layout and capacity audit, not be guessed from format syntax. Unconsumed input is never copied. Sink tentative state is excluded from this parser-only bound and measured separately; a joint theorem adds its explicit bound S. Reject layouts or formats exceeding the declared parameters.

Retained-state bounds have two meanings. Materializing output includes the configured value-size cap. A sink mode emits large payload fields incrementally and can bound parser state independently of payload length, but only a bounded-state sink gives bounded end-to-end memory. Events are provisional until full-message acceptance. A sink that hashes a prefix cannot undo it after rejection; its contract must reset or discard tentative state. Irreversible application effects before acceptance are outside the initial guarantee.

Restrict the first library to fixed-width reads, sequence, refinement, tagged choice and bounded length-delimited repetition. No unbounded backtracking or general recursive format support. Model ordered lossless delivery, arbitrary empty/one-byte chunks, stable chunk memory during a call and explicit EOF. Compiler correctness, protocol validity and cryptography remain trusted or outside scope. A proof of a generated specification does not prove RFC fidelity; preserve and independently inspect the format specification. A new DSL is unnecessary if the restricted Vest combinators can be reused.

## Evaluation plan and proposed go/no-go checks

First inspect and reproduce public EverParse3D stream handling: insufficient-input behavior, suspension state, buffer release, partition theorem and memory contract. Inspect current Vest support, including encoded BER/CBOR chunks, separately from transport fragments. Stop if an existing public artifact establishes the same one-message outcomes, conservation and M + D*K + H state bound with buffer release. Record build support, format-specific executable/proof edits and manual setup time to assess integration; no relative-effort threshold is established today. Paper text search is not an adequate novelty test.

Then prove a dependent TLV state machine and its transition composition. Extend to the selected ServerHello envelope only if generic sequencing and length-delimited parsing work without format-specific trusted assumptions. Preserve exact reference semantics and error policy. No wholesale library port is authorized or claimed today.

Compare direct whole-buffer Vest, buffer-all plus Vest, an ordinary stateful Rust implementation, nom's streaming mode and the strongest expressible EverParse3D implementation. A restart-on-incomplete adapter is a useful bad-case control, not the sole competitor. Match output representation, copying, size limits and error behavior. Unsupported baseline features and failed builds are results, not reasons to substitute easier successful examples.

RQ1: does every permitted partition preserve final results? Mechanize the theorem; enumerate partitions of short valid/malformed frames, then use every single split, seeded larger partitions, empty chunks, multiple messages, header splits, truncation and malformed lengths. Tests find implementation/harness mistakes; they do not prove the theorem.

RQ2: is the memory guarantee honest and useful? Measure peak parser-owned bytes and separately sink/output memory, allocations and copied bytes. Test oversize declarations before bodies arrive and release of caller buffers. Compare runtime state against the proved bound. Constant stack alone is insufficient.

RQ3: does compositional proof justify its engineering cost? Measure format-specific proof lines, verification time, trusted declarations, source adaptation, throughput and per-feed latency against stateful baselines. Track one-byte versus large chunks; there must be no repeated-prefix quadratic behavior. A precise execution-work theorem is optional follow-up, not today's primary contribution.

Kill or narrow the direction if prior art supplies the conjunction; parser state or sink memory quietly scales with payload length; a transition drops or duplicates committed bytes; proof requires a format-specific assumption; practical semantics cannot express errors/suffix handling; or the format needs substantial custom unproved code. Establish credible budgets after reproducing baselines.

Likely reviewer objection: this is an adapter for an already verified stream abstraction. The proposal survives only if its explicit suspend/resume contract and compositional state proof close a demonstrable integration gap. Another objection is that bounded buffering follows trivially from format caps; sink-mode ownership and dependent sequencing must exercise a nontrivial result. A simple TLV alone is feasibility evidence, not a paper.
