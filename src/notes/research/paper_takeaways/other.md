# Other

(authored by agents unless marked 🧑)

- [A formally verified compiler back-end](https://arxiv.org/abs/0902.2137): Leroy proves semantic preservation pass by pass for a multi-pass Cminor-to-PowerPC back-end in Coq.
- [Fact-Saboteurs: A Taxonomy of Evidence Manipulation Attacks against Fact-Verification Systems](https://www.usenix.org/conference/usenixsecurity23/presentation/abdelnabi): Taxonomy of evidence-manipulation attacks shows a proof of a checker does not show its evidence repository is unmodified or complete.
- [A Task-Centric Ontology and Deterministic Domain Rules as a Verifiable Core for AI-Assisted Chemistry Problem Solving](https://arxiv.org/abs/2608.26164v1): ChemOntoRule is a task-centric chemistry ontology with deterministic procedures; its 300-problem test set also defined requirements, so results show internal coverage, not generalization.
- [Velosiraptor: Code Synthesis for Memory Translation](https://doi.org/10.1145/3676641.3711998): Synthesis enumerates short control-call sequences from a grammar and checks each candidate with Z3 bit-vector logic against a universal postcondition.
- [Semantic Search over 9 Million Mathematical Theorems](https://arxiv.org/abs/2602.05216): Theorem retrieval over 9.2M statements improves when each theorem gets an LLM-written symbol-free slogan before embedding, and Qwen3 8B reaches Hit@20 0.450 versus 0.198 for ChatGPT 5.2.
- [Vεrity: Verifiable Local Differential Privacy](https://www.usenix.org/conference/usenixsecurity26/presentation/bell-clark): Vεrity makes randomized response verifiable so malicious users cannot bias the output beyond what an honest run gives, while keeping one-shot reporting.
- [The Output-Space Hypothesis: Enumerative Equivalence Checking for Tensor Programs](https://arxiv.org/abs/2609.19611): Tensor-program bugs are sparse in inputs but dense in output locations, so checking a sampled output location first found 218 of 226 inequivalence bugs.
- [Metha: Network Verifiers Need To Be Correct Too!](https://www.usenix.org/conference/nsdi21/presentation/birkner): Metha generates structurally valid device configurations from a topology to find silent model errors in network verifiers.
- [PAL*M: Property Attestation for Large Generative Models](https://arxiv.org/abs/2601.16199): Property attestation for generative models in confidential VMs uses TDX quotes and incremental multiset hashing of datasets, with a Tamarin model of the protocol.
- [A Verified Confidential Computing as a Service Framework for Privacy Preservation](https://www.usenix.org/conference/usenixsecurity23/presentation/chen-hongbo): Formal "Being Forgotten" requirements (secret confinement and erasure) are defined for enclave programs independently of any specific TEE hardware.
- [Projectional Decoding: Towards Semantic-Aware LLM Generation](https://doi.org/10.1145/3803437.3805571): Projectional decoding keeps a partial semantic model during generation and raises CLEVR program validity on Qwen3 4B from 4.33% to 73.67%, though no run reaches perfect validity.
- [InSPECtor: Improving SLEIGH Specification Veracity via Proxy](https://www.usenix.org/conference/usenixsecurity26/presentation/chesser): InSPECtor tests SLEIGH processor specs by generating instructions from the spec and diff-executing them against hardware, since verifying code against a wrong spec proves nothing about the processor.
- [Garbage Collection Makes Rust Easier to Use: A Randomized Controlled Trial of the Bronze Garbage Collector](http://arxiv.org/abs/2110.01098v2): A randomized trial of Bronze, an optional garbage collector for Rust, measures learner task performance; the tested version was unsound.
- [Dear CAV, We Need to Talk About Reproducibility](http://arxiv.org/abs/1502.02448v1): Proposes an infrastructure that rebuilds, unit-tests, and benchmarks submitted verification tools so their results are reproducible.
- [Predicting Rankings of Software Verification Competitions](http://arxiv.org/abs/1703.00757v1): Ranks SV-COMP verification tools on a task from prior results, learning a full ranking rather than only the winner.
- [ProSpeCT: Provably Secure Speculation for the Constant-Time Policy](https://www.usenix.org/conference/usenixsecurity23/presentation/daniel): ProSpeCT co-designs hardware and software so constant-time programs leak nothing under speculative execution, addressing Spectre and LVI transient leaks.
- [Incremental units-of-measure verification](http://arxiv.org/abs/2406.02174v1): Units-of-measure checker for Fortran infers missing units with one global constraint system, partitioned at module boundaries for incremental annotation.
- [Verifier-guided discovery of exact high-order mimetic operators with large language models](https://arxiv.org/abs/2609.27922): An LLM proposes only a typed construction program, a deterministic LP compiler fills coefficients, and an independent verifier decides; random proposals passed 13% versus 55% with feedback.
- [Kimina Lean Server: A High-Performance Lean Server for Large-Scale Verification](http://arxiv.org/abs/2504.21230v3): Kimina Lean Server is a pool of Lean REPL workers for RL reward checking; 9,419 proofs take 42m40s on 8 cores and 7m56s on 64, about 1.5-2x faster than baselines in local runs.
- [Inference of Error Specifications and Bug Detection Using Structural Similarities](https://www.usenix.org/conference/usenixsecurity24/presentation/dossche): ESSS infers error specifications from structural similarity of error paths without domain input, reporting 827 potential bugs, 541 probable true positives.
- [PVMark: Enabling Public Verifiability for LLM Watermarking Schemes](https://www.usenix.org/conference/usenixsecurity26/presentation/duan): PVMark adds zero-knowledge proofs so an external verifier can check LLM watermark detection without the owner's secret key.
- [Supporting the monitoring of the verification process of critical systems’software](http://arxiv.org/abs/1512.04782v1): Records evidence to check that verification activities meet a safety standard's assurance level; it verifies the process administratively, not program semantics.
- [Defense-in-Depth Runtime Safety in Move](https://arxiv.org/abs/2606.18064): A dynamic shadow type stack is a runtime defense for Move when the static verifier is complex or is itself a security boundary.
- [Bounded Synthesis of Reactive Programs](https://arxiv.org/abs/1807.09047): Bounded search over program-tree size, reduced to SAT, synthesizes structured reactive programs with loops and variables from LTL, not flat FSMs.
- [Hardware/Software Co-Assurance using the Rust Programming Language and ACL2](https://doi.org/10.4204/EPTCS.359.16): RAR is restricted Rust whose translator turns loops into tail recursion for ACL2, so one source yields software, hardware, and proofs; proof effort is mostly the records and RTL books.
- [Fixed-Point Scaffolding in the Clef Programming Language](http://arxiv.org/abs/2606.02854v3): Compiler design that carries proof annotations through nanopass lowering, requiring translation in two steps to agree with translation in one.
- [Valid Stopping in Adaptive Generator–Verifier Loops](https://www.semanticscholar.org/paper/a9f97f4eea8dc75e1a965e0932aec5020c416dd9): Valid stopping for generator-verifier loops uses index-betting e-values and online e-BH to control the false discovery rate of accepted proposals against a hidden expensive oracle.
- [Arguzz: Testing zkVMs for Soundness and Completeness Bugs](https://www.usenix.org/conference/usenixsecurity26/presentation/hochrainer): Metamorphic product programs and simulated malicious-prover faults found 11 unknown zkVM bugs in three of six tested zkVMs.
- [Don’t Trust the Code, Check Its Effects: Runtime Refinement for Regenerated Systems Code Under an Adversarial Generator](http://arxiv.org/abs/2609.00430v1): Position paper: a fixed handwritten mediator owns every effect of an adversarial generated driver, with sealed tokens binding each proposal to request identity and state version; no proof or measurement.
- [A Survey of Safety and Trustworthiness of Large Language Models through the Lens of Verification and Validation](https://arxiv.org/abs/2305.11391v2): Survey of LLM safety through verification and validation: falsification, formal verification, runtime monitoring, regulation; small-network methods need adaptation for LLMs.
- [Formal Verification, Engineering and Business Value](https://doi.org/10.4204/EPTCS.105.1): Experience report: adoption of automated C/C++ bug finding needs simplicity, workflow-compatible speed and useful output, more than completeness.
- [What is the Difference Between Me and You? Benchmarking the Quality Gap Between Human-Written and AI-Generated Code](https://arxiv.org/abs/2609.12708): Pairs 787,562 human functions with AI implementations of the same docstrings across Python, Java, and C, a controlled baseline for measuring generated-code quality gaps.
- [Automatically Detecting Error Handling Bugs Using Error Specifications](https://www.usenix.org/conference/usenixsecurity16/technical-sessions/presentation/jana): EPEX finds C error-handling bugs by symbolically exploring error paths against error specifications in SSL/TLS libraries.
- [Once is Never Enough: Foundations for Sound Statistical Inference in Tor Network Experimentation](https://www.usenix.org/conference/usenixsecurity21/presentation/jansen): Single-simulation conclusions about Tor are unsound; repeated independent samples with confidence intervals are needed to support performance claims.
- [Safe and usable kernel extensions with Rex](https://arxiv.org/abs/2502.18832): Rex requires a restricted safe Rust with a trusted kernel crate and runtime checks, removing the eBPF language-verifier gap and its verifier rejections.
- [MIRB: Mathematical Information Retrieval Benchmark](https://arxiv.org/abs/2505.15585): MIRB is a 12-dataset math retrieval benchmark whose premise labels are declarations used by successful proofs, with a novel-premises split.
- [Semi-Supervised Verified Feedback Generation](https://arxiv.org/abs/1603.04584v1): Clusters student submissions by strategy, then checks each submission against one instructor-validated submission in its cluster, so one correct reference per cluster suffices.
- [“Threat modeling is very formal, it’s very technical, and also very hard to do correctly”: Investigating Threat Modeling Practices in Open-Source Software Projects](https://www.usenix.org/conference/usenixsecurity25/presentation/kaur): Interviews with 25 open-source developers show threat modeling is hard to do correctly; the study is qualitative and proves nothing.
- [Untrusted Authors, Trusted Answers: A Calculus of Fidelity-Graded Translations](https://www.semanticscholar.org/paper/e85205271f8d831f45546f35c9ab43e310b86fc2): Answers come from translating to decidable targets and comparing projected traces across both sides, but translator and interpreter can share a blind spot, as both decoded MUL as ADD.
- [ZKP Security Tools and Verification: Coverage, Effectiveness, Adoption, and Challenges](https://doi.org/10.48550/arxiv.2607.23752): Six ZKP security tools detect 45.7% of 70 real vulnerabilities on isolated targets but only 19.6% on full codebases.
- [Verify your Labels! Trustworthy Predictions and Datasets via Confidence Scores](https://www.usenix.org/conference/usenixsecurity24/presentation/krauss-verify): LabelTrust flags wrong labels by similarity to expert reference sets, a statistical detector for datasets and predictions.
- [Extract, model, refine: improved modelling of program verification tools through data enrichment](https://doi.org/10.1007/s10270-024-01232-7): ProVerB is a maintained catalogue of 400+ program verification tools with a taxonomy and API-enriched metadata.
- [Finding and Analyzing Crash-Consistency Bugs in Persistent-Memory File Systems](https://arxiv.org/abs/2204.06066): FLYTRAP finds crash-consistency bugs in persistent-memory file systems by testing writes and crash points inside system calls; 18 new bugs confirmed.
- [The Hitchhiker's Guide to Program Analysis: A Journey with Large Language Models](https://arxiv.org/abs/2308.00245): LLMs triage the reports that symbolic execution leaves undecided, rather than replacing static analysis.
- [AGON: Automated Design Framework for Customizing Processors From ISA Documents](https://arxiv.org/abs/2412.20954): AGON turns ISA documents into executable operator functions and synthesizes RTL, reporting 2.35x average speedup over BOOM.
- [Flood and Harvest: The Provable Necessity of Trivia for Generating Valuable Mathematics via the Lens of Language Generation in the Limit](https://doi.org/10.48550/arxiv.2606.14688): A checker can accept formally admissible outputs without judging usefulness; coverage of valuable results then needs more than validity checking.
- [Test-Driven Approaches to Software Engineering with Large Language Models: A Survey of Phases, Tasks, and Agent Skills](https://arxiv.org/abs/2609.12012): A survey of 87 test-driven LLM engineering papers shows tests passing does not establish equivalence or process adherence, and offers a taxonomy of test-conditioned generation and refinement.
- [From Authorial Mathematics to Studio Mathematics: Ecobiontic Forms of Proof after Large Language Models](https://doi.org/10.48550/arxiv.2608.22194): A machine-checked derivation is only one layer of a larger evidence and responsibility system; the paper is conceptual, not empirical.
- [Certified in Theory, Broken in Practice: Assumption Gaps in Cryptographic Model Certification](https://www.usenix.org/conference/usenixsecurity26/presentation/luck): Zero-knowledge soundness on a fixed audit set does not imply the property on fresh data; a model certified above 99 percent on audit data was under 30 percent on fresh samples.
- [An Integrated Development Environment for the Prototype Verification System](https://doi.org/10.4204/EPTCS.310.5): VSCode-PVS brings PVS editing and proof management into VS Code; the contribution is adoption engineering, not a new proof calculus.
- [A Mixed Methods Study on the Implications of Unsafe Rust for Interoperation, Encapsulation, and Tooling](https://arxiv.org/abs/2404.02230): An interview and survey study of unsafe Rust reports self-reported perceptions, not bug rates, and shows that a Box move can invalidate raw pointers in ways C++ developers did not expect.
- [Towards a Common Framework for Autoformalization](https://doi.org/10.1609/aaai.v40i48.42132): Four-part contract for autoformalization: informal language, formal language, a semantic equivalence E, and a computable validator V; define E separately from what the test can check.
- [Synthetic Programming Elicitation for Text-to-Code in Very Low-Resource Programming and Formal Languages](https://arxiv.org/abs/2406.03636): Eudoxus has the LLM write a familiar Python subset that compiles to a very-low-resource target, parsing 30 of 33 tasks versus 6 for baselines, though the intro's percentages conflict with Table 1.
- [Implementing Dependent Type Theory Inhabitation and Unification](https://arxiv.org/abs/2603.01463): Canonical-min is a 185-line Lean unifier claimed sound and complete, but neither property is mechanized.
- [What Challenges Do Developers Face When Using Verification-Aware Programming Languages?](https://arxiv.org/abs/2506.23696): Developer challenges with verification-aware languages cluster in proof elaboration, and 64.5% of surveyed developers struggled to design proof strategies, though the paper's counts are inconsistent.
- [From Dependency to Compositionality: A Neurosymbolic Lifting of LLM Outputs via Combinatory Categorial Grammar](http://arxiv.org/abs/2607.18961v2): Post-hoc CCG reconstruction of LLM outputs gives auditable derivations; the paper says coupling the parser to decoding is only a sketch.
- [ACon^2: Adaptive Conformal Consensus for Provable Blockchain Oracles](https://www.usenix.org/conference/usenixsecurity23/presentation/park): ACon2 gives conformal-consensus guarantees for blockchain oracles under distribution shift and Byzantine sources, with gas measured.
- [Program Synthesis from Polymorphic Refinement Types](http://arxiv.org/abs/1510.08419v3): Synquid synthesizes recursive programs from polymorphic refinement types and solved 64 of 64 benchmarks, but the decidable logic excludes some nested transformations.
- [ProofWright: Towards Agentic Formal Verification of CUDA](https://arxiv.org/abs/2511.12294v2): Verifier instability (17%) and agent failure (9%) limit a 74% safety-verified rate on KernelBench L1, and the other metrics use different denominators.
- [Artificial Intelligence for Mathematical Reasoning: An Integrated Survey of Language Models, Neuro-symbolic Systems, and Verified Discovery](https://doi.org/10.48550/arxiv.2606.08728): A survey argues to choose artifact and verifier together, climbing from numeric answers to formal proofs, and PRMs localize errors but need more labels than ORMs.
- [QED at Large: A Survey of Engineering of Formally Verified Software](https://doi.org/10.1561/2500000045): A survey of verified-software engineering argues for specifying first with inductive relations, separating termination, partial correctness, and adequacy, and choosing deep or shallow embeddings by use.
- [PINE: Efficient Verification of a Euclidean Norm Bound of a Secret-Shared Vector](https://www.usenix.org/conference/usenixsecurity24/presentation/rothblum): PINE proves a secret-shared vector's squared norm is bounded, with statistical zero knowledge and little communication, even against malicious clients.
- [Agentic AI for Software: thoughts from Software Engineering community](https://arxiv.org/abs/2508.17343): A position paper with no evaluation argues specification inference is central to repair agents and proposes agents that interpret proofs and talk to theorem provers.
- [Stochastic Superoptimization](https://arxiv.org/abs/1211.0557): STOKE searches x86 sequences by stochastic search balancing correctness and performance costs, with an SMT validator for promising candidates; the method is incomplete.
- [Taking proof-based verified computation a Few Steps Closer to Practicality](https://www.usenix.org/system/files/conference/usenixsecurity12/sec12-final26_0.pdf): GINGER refines PEPPER's linear-PCP protocol to verify outsourced computation with bounded integers and conditionals, parallelized on CPUs and GPUs.
- [Improving Debugging in Verification-Aware Languages Through Automated Fault Localization: A Case Study in Dafny](https://arxiv.org/abs/2608.05399): Counterexample-based fault localization in Dafny beat contract-derived state tests, but valid tests existed for only 387 of 500 mutants, which limited the comparison.
- [A Trust Ledger and an Execution Check for CPG-Based C-to-Lean 4 Autoformalization: Separating Declined from Silently Incorrect Translations](https://doi.org/10.48550/arxiv.2609.38237): Declined constructs (labeled holes) and silently mishandled constructs need separate accounting: 60.7% of SQLite's functions are hole-free, but only 24.8% are call-closed.
- [Towards Verifiable Transformers: Solver-Checkable Circuit Explanations](http://arxiv.org/abs/2605.24033v2): Bounded solver verification of extracted transformer circuits over declared finite domains; the paper says it is not end-to-end verification of language models.
- [ObliCheck: Efficient Verification of Oblivious Algorithms with Unobservable State](https://www.usenix.org/conference/usenixsecurity21/presentation/son): ObliCheck verifies oblivious algorithms by symbolic execution with state merging and reports a 50,300x speedup over conventional symbolic execution.
- [Engineering as Code: Bringing Software Engineering Methodology to Engineering Design](https://doi.org/10.1007/s10664-023-10407-1): Thesis: representation infrastructure, not algorithmic capability, bottlenecks engineering design; the piki prototype shows feasibility only.
- [Your Simulation Runs but Solves the Wrong Physics: PDE-Grounded Intent Verification for LLM-Generated Multiphysics Simulation Code](https://www.semanticscholar.org/paper/22f9c65a67048f79cabcb82f48e6acbfe18e8a49): Running multiphysics code can solve the wrong physics, and a deterministic PDE-level check with bounded refinement raises DeepSeek V4 Flash mean intent fidelity from 0.599 to 0.782.
- [TypePilot: Leveraging the Scala Type System for Secure LLM-generated Code](https://doi.org/10.26615/978-954-452-101-1-011): TypePilot uses Scala ADTs, refined types, and sealed traits in a three-agent pipeline to remove vulnerabilities in LLM code, but its evaluation is manual on simple tasks with no repeat counts.
- [F-IDEs with Features and VCs Designed to Assist Human Reasoning When Verification Fails](https://doi.org/10.4204/EPTCS.349.4): RESOLVE F-IDE design: a failed verification should link to source, show small context, and be explorable by rule; evidence is design plus counts, with no user study or proof-time data.
- [Validating Solidity Code Defects using Symbolic and Concrete Execution powered by Large Language Models](https://doi.org/10.4204/EPTCS.427.7): Pipeline combining Slither, LLM-written tests and Forge or Kontrol execution; the authors state that no complete implementation exists yet.
- [SecSMT: Securing SMT Processors against Contention-Based Covert Channels](https://www.usenix.org/conference/usenixsecurity22/presentation/taram): Characterizes contention-based covert channels across an SMT pipeline and evaluates partitioning mitigations; it is empirical, not a noninterference proof.
- [ATLAS: AI-Assisted Threat-to-Assertion Learning for System-on-Chip Security Verification](http://arxiv.org/abs/2603.01170v2): An LLM pipeline turns CWE knowledge into SystemVerilog assertions for OpenTitan: it detects 39 of 48 CWEs, with correct properties for 33 of those 39, but it covers hardware only.
- [The Secrets Must Not Flow: Scaling Security Verification to Large Codebases](https://doi.org/10.1109/sp63933.2026.00026): Diodon proves a small protocol core refines its model and checks the large application with whole-program static analyses, because a verified core alone misses leaks such as logging keys.
- [Assay: Claims That Decay With the Code. Content-Addressed Evidence Graphs for Accountable AI-Assisted Software Delivery](https://arxiv.org/abs/2609.36170): Assay binds agent claims to a Merkle hash of the dependency cone and marks them stale when it changes, though regex import extraction can miss dynamic imports.
- [Toward Practical Deductive Verification: Insights from a Qualitative Survey in Industry and Academia](https://arxiv.org/abs/2510.20514): An interview study of 30 practitioners finds criticality drives the choice to verify and modular proofs and smaller SMT context are valued, but the evidence is self-report only.
- [Trust the Spec, Not the Code - A Specification-First, AI-Assisted Case Study in Online Banking](https://arxiv.org/abs/2609.07365): A single-author ChatGPT banking case study has no tool check any proof and the generated code is never read, so its value is spec tightening, not proving code.
- [Lessons Learned From Microkernel Verification — Specification is the New Bottleneck](https://doi.org/10.4204/EPTCS.102.4): Verisoft XT's microkernel work shows specification is the new bottleneck, with a three-phase formalize, annotate, verify loop, and concurrency must be made explicit in requirements.
- [Maintaining a Library of Formal Mathematics](https://arxiv.org/abs/2004.03673): Semantic linters inspect elaborated Lean declarations and metadata, catching convention and simplifier issues that type checking misses in mathlib.
- [RESOLVE: Language-Agnostic Validation of GPU Kernels Through Testing, Reduction, and Proof](https://doi.org/10.48550/arxiv.2610.05683): RESOLVE checks GPU kernels for determinism with memory-hash comparisons and proves a reduced kernel and its reference meet one tight real-valued spec, but a clean test campaign shows determinism, not race freedom.
- [Position: Natural Language Should Not Fully Replace Formal Languages](https://doi.org/10.48550/arxiv.2607.20432): Formal language beats natural language only above an information threshold, sigma* = H(Y) + R_formal - Delta_trans, under one-shot assumptions; the paper recommends a hybrid interface.
- [ProFactory: Improving IoT Security via Formalized Protocol Customization](https://www.usenix.org/conference/usenixsecurity22/presentation/wang-fei): A typed DSL with staged verification turns IoT protocol specs into checked C; 31 DSL lines replace hundreds of C lines for L2CAP, and a required max parameter-list length precludes CVE-2017-1000251.
- [A Contemporary Survey of Large Language Model Assisted Program Analysis](https://arxiv.org/abs/2502.18474): A survey of LLM-assisted program analysis that classifies verification inputs into code, specifications, formal methods, and error information.
- [Prezta: Provable Remote Execution of Zero-Trust Authorization using SNARKs](https://www.usenix.org/conference/usenixsecurity26/presentation/wei-zhongjing): Moves policy evaluation into a client zkVM that proves a signed policy outputs 1; security rests on SNARK knowledge soundness.
- [What’s in a Proof? Analyzing Expert Proof-Writing Processes in F* and Verus](https://arxiv.org/abs/2508.02733v1): A telemetry study of eight experts finds specification-first proof writing with temporary assume(false) holes, and experts split goals into independently checkable subgoals.
- [AXLE: A Cloud Infrastructure for Lean 4 Theorem Proving Utilities](http://arxiv.org/abs/2606.26442v1): A hosted Lean verification service's strict check rejects sorry, extra axioms, and weakened statements, since compiling alone is not enough, at 0.97 s median versus 10.1 s for SafeVerify.
- [Relational Network Verification](https://doi.org/10.1145/3651890.3672238): Compiles ECMP paths into a DAG and then into automata to check network snapshot changes against regex-based relational specs.
- [Formal Mathematical Reasoning: A New Frontier in AI](https://arxiv.org/abs/2412.16075): A position paper: LLM plus proof assistant gives soundness and feedback, but passing the checker does not show fidelity, and neither BLEU nor compile success tracks human judgment.
- [Invariant-Guided Logical Testing of Open RAN Controllers](https://www.usenix.org/conference/usenixsecurity26/presentation/yang-tianchang): Infers likely invariants from benign runs, uses critical ones as bug oracles, and all of them as fuzzing feedback, without formal specs.
- [APKeep: Realtime Verification for Real Networks](https://www.usenix.org/conference/nsdi20/presentation/zhang-peng): APKeep verifies networks incrementally by updating only the predicates affected by each change.
- [WAVED: Principled Identification of Off-Path Exploitable Weak Verifications within the TCP/IP Protocol Suite](https://www.usenix.org/conference/usenixsecurity26/presentation/zhao-yizhou): WAVED measures an off-path attacker's required knowledge by counting input bytes strongly constrained on a path, flagging weak checks before risky operations.
- [Characterizing and Bridging the Diagnostic Gap in eBPF Verifier Rejections](https://arxiv.org/abs/2607.02748): eBPF verifier logs name where checking stopped, not where the proof was lost, and rebuilding the lost proof from the level-2 log is the fix, since raw logs give models 0-37% one-shot success.
- [REFACTOR: Learning to Extract Theorems from Proofs](https://arxiv.org/abs/2402.17032): REFACTOR learns to extract reusable theorems from Metamath proof graphs as node classification, with the best model recovering the human-chosen theorem on 19.6% of held-out proofs.
- [Establishing Best Practices for Building Rigorous Agentic Benchmarks](https://arxiv.org/abs/2507.02825): An agentic benchmark checklist finds 7 of 10 benchmarks have task-validity issues, such as 24% of SWE-bench-Verified top-50 positions wrong because tests miss edge cases.
