# Other formal methods

(authored by agents unless marked 🧑)

- [A benchmark for C program verification](http://arxiv.org/abs/1904.01009v1): CBench gives 25 C programs in five families as a shared benchmark for comparing C verifiers on defined behavior and functional correctness.
- [A Certificate-Producing Cascade for Equational Implication: The SAIR EQT2 Stage 2 Solver](http://arxiv.org/abs/2609.00706v1): Untrusted search plus a kernel-checked certificate keeps the trust boundary small; a search bug yields a rejection, and not-found never implies the opposite verdict.
- [A Complete, Formal Semantics for Rust Source Code](https://arxiv.org/abs/2610.06003): Gives a full local-rule semantics for safe Rust and async Tokio with a RustyDL soundness proof, but assumes well-typed programs so it makes no memory-safety claim.
- [A Formal Model of Algorand Smart Contracts](https://arxiv.org/abs/2009.12140): Gives a state-machine model of Algorand stateless contracts, proves safety properties, and compiles a declarative language to TEAL; consensus, fees, and rekeying are abstracted away.
- [A framework for embedded software portability and verification: from formal models to low-level code](https://doi.org/10.1007/s10270-023-01144-y): Separates generic software from hardware in Event-B, verifies refinements in Rodin, then generates LLVM and assembly per target; scheduling is out of scope.
- [A New Interaction Concept for Interactive and Autoactive Program Verification](https://arxiv.org/abs/2605.06972v1): KeY proof state is shown and edited on source code via overlaid assumptions and assertions; six-person pilot is qualitative only.
- [A Program Instrumentation Framework for Automatic Verification](https://arxiv.org/abs/2412.06431v1): Instrumentation translates rich specifications into simpler assertions by keeping ghost state for hard spec expressions, with operators hand-written and their application searched automatically.
- [A Summary of Formal Specification and Verification of Autonomous Robotic Systems](http://arxiv.org/abs/1911.11597v1): Summarizes a 2007-2018 survey: autonomous robots need formal specification and verification because testing and simulation alone are insufficient.
- [A Survey of Smart Contract Formal Specification and Verification](https://arxiv.org/abs/2008.02712): Survey of 202 smart-contract formal specification and verification papers (2014-2020), scoped to functional behavior; useful as a taxonomy of properties and techniques.
- [A Verified Certificate Checker for Finite-Precision Error Bounds in Coq and HOL4](https://arxiv.org/abs/1707.02115): Untrusted analysis emits certificates that a small verified checker validates, here for roundoff bounds in Coq and HOL4.
- [Bisimulation Learning](http://arxiv.org/abs/2405.15723v1): Learns finite stutter-insensitive bisimulations from samples with a decision-tree classifier and ranking functions, and an SMT check refines counterexamples; the abstract states support LTL model checking.
- [Deductive Verification of Floating-Point Java Programs in KeY](https://arxiv.org/abs/2101.08733): KeY closes heap and control-flow goals symbolically and sends only leftover floating-point obligations to an SMT float solver.
- [Formal Semantics and Formally Verified Validation for Temporal Planning](https://arxiv.org/abs/2203.13604): The plan validator is proved against a declarative semantics, because Fox and Long's operational definition was too close to an algorithm to formalize cleanly.
- [Formally Verified SAT-Based AI Planning](https://arxiv.org/abs/2010.14648): Verified SAT encoder for bounded planning in Isabelle keeps the SAT solver untrusted, and a verified decoder emits a plan only if the model entails the encoding.
- [Compositional Program Verification with Polynomial Functors in Dependent Type Theory](http://arxiv.org/abs/2604.01303v1): Polynomial functors serve as program interfaces, free-monad morphisms as implementations, and dependent polynomials as pre/post specs; the framework is formalized in Agda.
- [Abstract Compilation for Verification of Numerical Accuracy Properties](http://arxiv.org/abs/1911.10930v1): Abstract compilation embeds a numerical abstract interpreter into executable code, so runtime checks cover floating-point accuracy under concrete inputs.
- [Abstraction and Learning for Infinite-State Compositional Verification](https://doi.org/10.4204/EPTCS.129.13): Combines assume-guarantee reasoning, predicate abstraction, CEGAR, and L* learning to verify compositions of infinite-state components; no experiments reported.
- [Formalizing Memory Accesses and Interrupts](https://doi.org/10.4204/EPTCS.244.4): Formal static model of memory accesses and interrupt routing on heterogeneous hardware, mechanized in Isabelle/HOL with semantics-preserving transformations.
- [Towards provably performant congestion control](https://www.usenix.org/conference/nsdi24/presentation/agarwal-anup): Synthesizes congestion-control rates as functions of belief sets over nondeterministic networks, with guarantees only for single-flow infinite-backlog traffic.
- [Exo-GPU: Safe, Imperative, User-schedulable Programming for Tensor Cores](https://arxiv.org/abs/2609.16389): Exo-GPU statically checks collective and memory consistency and defines safety as parallel output matching sequential semantics, demonstrated on H100 GEMM kernels.
- [FregeLogic at SemEval 2026 Task 11: A Hybrid Neuro-Symbolic Architecture for Content-Robust Syllogistic Validity Prediction](http://arxiv.org/abs/2604.18328v1): Five LLM classifiers defer to a Z3 checker only on 3-2 splits; LLM disagreement is used as a signal of content-biased errors.
- [Formally Verified EVM Block-Optimizations](https://doi.org/10.1007/978-3-031-37709-9_9): Verify a checker for each original and optimized block pair in Coq rather than the optimizer itself, which avoids chasing an evolving optimizer; scope is stack-only blocks.
- [Towards Formally Verified Smart Contracts Compilation](https://doi.org/10.1007/978-3-032-26220-2_13): FORYU is a Rocq formalization of Yul with a verified liveness checker that accepted all results on 1,550 Solidity contracts in about 3.6 seconds total.
- [Incremental Symbolic Bounded Model Checking of Software Using Interval Methods via Contractors](http://arxiv.org/abs/2012.11245v3): Interval contractors shrink the bounded-model-checking search to regions that may violate an assertion, using assume directives inserted into the program.
- [Forbidden Sidon subsets of perfect difference sets, featuring a human-assisted proof](http://arxiv.org/abs/2510.19804v2): A human argues the math in natural language while an LLM writes and repairs Lean, producing a 6000-line formal disproof of an Erdos extension conjecture in about one week of full-time work.
- [Have a thing? Reasoning around recursion with dynamic typing in grounded arithmetic](https://arxiv.org/abs/2510.25369): Grounded arithmetic proves recursive functions terminating by dynamically typing terms; a metatheory proposal mechanized in Isabelle/HOL, not a verifier.
- [Algorithm Selection for Software Verification using Graph Neural Networks](http://arxiv.org/abs/2201.11711v3): Graves uses a graph neural network over program graphs to choose a verifier from a portfolio, verifying 9% more problems than any single tool.
- [Finding Model-Checkable Needles in Large Source Code Haystacks: Modular Bug-Finding via Static Analysis and Dynamic Invariant Discovery](http://arxiv.org/abs/1609.06382v1): Bug finding triages small functions that a bounded model checker can handle, then mines test-suite preconditions as assumptions, trading completeness for scale.
- [Zoo: A Framework for the Verification of Concurrent OCaml 5 Programs using Separation Logic](https://doi.org/10.1145/3776701): Zoo translates OCaml 5 programs via compiler annotations into a deep Rocq embedding, so Iris separation-logic specs are proved against the real semantics.
- [Verifying Constant-Time Implementations](https://www.usenix.org/conference/usenixsecurity16/technical-sessions/presentation/almeida): Constant-time checking reduces to assertion safety of a product program running two executions; the reduction is formalized in Coq and implemented in ct-verif.
- [Permission-Based Separation Logic for Multithreaded Java Programs](https://doi.org/10.2168/LMCS-11(1:2): Fractional permission accounting in concurrent separation logic gives data-race freedom, where a write needs full permission and reads need any share, a model for ghost permissions in Verus.
- [A Unit Proofing Framework for Code-level Verification: A Research Agenda](https://arxiv.org/abs/2410.14818v2): Default CBMC proofs of FreeRTOS exposed 5 of 11 reproducible memory-safety CVEs, and repairing input, function, and proof models exposed all 11.
- [Verified Compilation of Space-Efficient Reversible Circuits](https://arxiv.org/abs/1603.01635): ReVerC is an F* verified compiler from Revs to reversible circuits that proves semantics preservation and resets ancilla bits for reuse.
- [An Automatically Verified Prototype of the Android Permissions System](https://arxiv.org/abs/2209.10278): Translates a Coq Android-permissions model to the {log} solver, showing a constraint solver can discharge the proofs of a systems verification.
- [An encoding of array verification problems into array-free Horn clauses](http://arxiv.org/abs/1509.09092v1): Encodes array programs as array-free scalar nonlinear Horn clauses; a solution gives inductive invariants for the original array program.
- [Owi: Performant Parallel Symbolic Execution Made Easy, an Application to WebAssembly](https://doi.org/10.22152/programming-journal.org/2025/9/3): Owi turns a concrete Wasm interpreter into a monadic symbolic interpreter with multicore scheduling, analyzing C and Rust compiled to Wasm.
- [Securing Verified IO Programs Against Unverified Code in F*](https://arxiv.org/abs/2303.01350v3): SCIO* compiles verified F* IO programs so their guarantees survive linking with untrusted code; erasure-based extraction is shown unsound in this setting.
- [SecRef*: Securely Sharing Mutable References between Verified and Unverified Code in F*](https://doi.org/10.1145/3747522): A ghost label per mutable reference, checked at the boundary wrappers, lets verified F* code share references with unverified code, a model for the Verus trust boundary.
- [ConCert: a smart contract certification framework in Coq](https://arxiv.org/abs/1907.10674v4): ConCert links deep and shallow Coq embeddings of a smart-contract language by a soundness theorem, a reusable pattern for certified contracts.
- [Extracting smart contracts tested and verified in Coq](https://arxiv.org/abs/2012.09138): Extracts verified Coq programs to smart-contract languages via MetaCoq certified erasure, and tests extracted contracts with QuickChick over execution traces.
- [Formally Verifying Noir Zero Knowledge Programs with NAVe](https://arxiv.org/abs/2601.09372): NAVe formalizes ACIR in SMT-LIB and checks Noir circuits with cvc5, catching unconstrained witness code that weakens the intended circuit relation.
- [An algebra of alignment for relational verification](http://arxiv.org/abs/2202.04278v4): BiKAT extends KAT with two sides to derive program alignments, turning relational verification into algebraic rewriting plus Hoare-style obligations.
- [Verified Software Toolchain (Invited Talk)](https://www.semanticscholar.org/paper/9cdd6da72a90e4fd786012b33f85efc16cdac0d3): Appel outlines a planned Coq-verified toolchain linking source-level claims to machine-level observations; several parts are still early or not started.
- [The VerCors Verifier: A Progress Report](https://doi.org/10.1007/978-3-031-65630-9_1): VerCors is sound but incomplete: a Viper success implies the spec holds, a failure is inconclusive, and each translation pass needs its own semantic-preservation argument.
- [TensorRight: Automated Verification of Tensor Graph Rewrites](https://doi.org/10.1145/3704865): Tensor rewrite rules are reduced to finite rank classes and checked by per-rank symbolic execution, SMT, and induction, verifying 115 XLA rules with 108 under one second.
- [Verifying Hardware Security Modules with Information-Preserving Refinement](https://www.usenix.org/conference/osdi22/presentation/athalye): Knox proves a hardware security module stack meets its functional spec and leaks nothing extra at the wire level, via information-preserving refinement.
- [Auto-active Verification of Floating-point Programs via Nonlinear Real Provers](http://arxiv.org/abs/2207.00921v1): PropaFP sends SPARK floating-point obligations to nonlinear real provers after bounding rounding errors with FPTaylor or Gappa.
- [Automated and Formal Synthesis of Neural Barrier Certificates for Dynamical Models](https://doi.org/10.1007/978-3-030-72016-2_20): A counterexample-guided loop lets a numerically unsound learner propose neural barrier certificates while an SMT verifier supplies the final safety guarantee.
- [Automatic Verification and Interactive Theorem Proving](http://arxiv.org/abs/1701.03602v1): Checking a given proof is decidable while finding one is search, so keep the trusted checker small and spend effort on search.
- [A Verified Algebraic Representation of Cairo Program Execution](https://arxiv.org/abs/2109.14534): A Lean 3 proof shows that satisfying the Cairo AIR constraints implies a valid execution trace; it is an implication theorem, not a protocol proof.
- [A Proof-Producing Compiler for Blockchain Applications](https://arxiv.org/abs/2501.15002): A proof-producing compiler emits a Lean model of CairoZero machine code and a proof of a generated spec; users prove their spec follows, giving verification down to CPU semantics.
- [Soteria: Efficient Symbolic Execution as a Functional Library: Perhaps You Should Write Your Own Symbolic Execution Engine!](https://doi.org/10.1145/3808306): Soteria is an OCaml library for writing symbolic executors directly over source semantics, avoiding a lossy intermediate language.
- [HITrees: Higher-Order Interaction Trees](https://arxiv.org/abs/2510.14558): HITrees extend interaction trees to higher-order effects in Lean 4 without guarded type theory; a semantics and library technique, not a verifier.
- [An Exercise in Invariant-based Programming with Interactive and Automatic Theorem Prover Support](https://doi.org/10.4204/EPTCS.79.2): Transition consistency and liveness become weakest-precondition conditions discharged by PVS and Yices, and reusable background lemmas do most of the automation work.
- [Leveraging Cryptographic Simulator Synthesis for Formally Verifying the FOO E-Voting Protocol](https://www.usenix.org/conference/usenixsecurity26/presentation/baelde): Squirrel crypto tactic synthesizes inductive simulators with oracle memoization and time-sensitive memory invariants, validated by a computational proof of FOO vote privacy.
- [Software Verification with CPAchecker 3.0: Tutorial and User Guide (Extended Version)](https://arxiv.org/abs/2409.02094v1): CPAchecker 3.0 unifies many verification algorithms under configurable program analysis and returns verdicts with witnesses that can be validated independently.
- [Relational Logic with Framing and Hypotheses: Technical Report](http://arxiv.org/abs/1611.08992v1): A relational separation logic with framing compares two heap programs for optimization or refactoring equivalence; it is foundational only, with no implementation and an SMT encoding claimed but not shown.
- [Modeling Reachability Types with Logical Relations: Semantic Type Soundness, Termination, Effect Safety, and Equational Theory](https://arxiv.org/abs/2309.05885): Logical-relations model of reachability types, mechanized in Rocq, proves semantic type soundness, termination and effect safety for reference-aliasing reasoning.
- [From Alarms to Real Bugs: Multi-target Multi-step Directed Greybox Fuzzing for Static Analysis Result Verification](https://www.usenix.org/conference/usenixsecurity25/presentation/bao-andrew): Lyso directs fuzzing along static-analysis paths to confirm alarms, reporting a 12.17x average speedup over eight directed fuzzers.
- [BARReL: a modern backend for Atelier B in Lean](https://arxiv.org/abs/2606.20121): BARReL turns Atelier B proof obligations into Lean 4 goals and makes partial-operator well-definedness explicit via dependent types.
- [CSLib: The Lean Computer Science Library](https://arxiv.org/abs/2602.04846): This is a roadmap with no evaluation; it proposes replaying solver certificates step by step in Lean, prototyped only on a small loop-sum example.
- [CSLib: The Lean Computer Science Library](https://doi.org/10.48550/arxiv.2602.04846): CSLib is a roadmap for a Lean library of verified computer-science models and code, with Boole mixing imperative code and Lean specs; no finished benchmark.
- [Leroy and Blazy Were Right: Their Memory Model Soundness Proof is Automatable](https://arxiv.org/abs/2212.02425): The CompCert memory-model soundness proof ported from Coq to Why3 has 89.6% automatic obligations, and recursive lemmas mirror the spec's case split.
- [Proving differential privacy in Hoare logic](http://arxiv.org/abs/1407.2988v1): Differential privacy of probabilistic programs reduces to standard Hoare logic by verifying a synchronized self-product with nondeterministic abstract mechanisms.
- [Verifying Relational Properties using Trace Logic](http://arxiv.org/abs/1906.09899v3): Encodes a program and a relational property as one first-order trace-logic validity problem for a prover; the RAPID tool emits SMT-LIB and calls Vampire.
- [A Probabilistic Separation Logic](http://arxiv.org/abs/1907.10708v4): Separating conjunction in PSL means probabilistic independence, with a resource semantics over deterministic memories paired with distributions.
- [Towards benchmarking of Solidity verification tools](https://arxiv.org/abs/2402.10750v1): Soundness-weighted scoring charges -16 for a false positive on a strong claim and -8 for a strong-claim miss, and the ground truth for such bugs is hard to certify.
- [Solvent: liquidity verification of smart contracts](http://arxiv.org/abs/2404.17864v3): Solvent verifies liquidity of a Solidity fragment: from reachable states, specified users can reach an asset transfer within a bounded number of transactions.
- [Certifying optimal MEV strategies with Lean](https://arxiv.org/abs/2510.14480): First Lean 4 mechanization (about 7000 lines) of MEV for Uniswap-v2-style AMMs, with a machine-checked optimality proof for sandwich attacks; MEV may not exist, so the paper uses the least upper bound MEVsup.
- [A Formal Analysis of 5G Authentication](https://arxiv.org/abs/1806.10360): Tamarin proves confidentiality, authentication, and privacy lemmas for 5G AKA and finds attacks under minimal assumptions; it does not verify implementations.
- [Relatively Complete Verification of Probabilistic Programs](http://arxiv.org/abs/2010.14548v2): Expressible postexpectations stay expressible through any pGCL program's weakest preexpectation, so the quantitative assertion syntax is expressive enough for relative completeness.
- [The HoTT Library: A formalization of homotopy type theory in Coq](https://arxiv.org/abs/1610.04591): Coq library makes each use of an axiom such as function extensionality an explicit instance-quantified assumption, so theorems cannot silently depend on stronger principles.
- [A Two-Phase Infinite/Finite Low-Level Memory Model: Reconciling Integer–Pointer Casts, Finite Space, and undef at the LLVM IR Level of Abstraction](https://arxiv.org/abs/2404.16143): Splits the LLVM memory model into an infinite phase where many optimizations hold without extra reasoning and a finite phase that adds only out-of-memory behavior.
- [Development and Verification of a Flight Stack for a High-Altitude Glider in Ada/SPARK 2014](http://arxiv.org/abs/1707.00945v1): Running the SPARK prover continuously during development steered design; 88.8% of 3,981 VCs were proved, and saturation hid boundary cases.
- [Explaining Counterexamples with Giant-Step Assertion Checking](https://doi.org/10.4204/EPTCS.338.10): When a proof fails, replay the solver counterexample with runtime assertion checking in two modes to separate program bugs, weak contracts, and prover incompleteness.
- [Proving Equivalence Between Imperative and MapReduce Implementations Using Program Transformations](https://doi.org/10.4204/EPTCS.268.7): Equivalence between imperative and MapReduce programs is proved by a chain of Coq-checked transformation steps, but users must invent intermediate programs and the proofs need heavy interaction.
- [BeePL: Correct-by-compilation kernel extensions](https://arxiv.org/abs/2507.09883v1): The core eBPF compiler is verified, but parser, lexer and pretty-printer stay in the trusted base, so the trust boundary must be stated.
- [Verification Condition Generation and Variable Conditions in Smallfoot](http://arxiv.org/abs/1204.4804v1): Smallfoot 0.1 verification-condition generation for concurrent separation-logic programs; documents variable and alias checks and a known soundness gap.
- [Multiple Analyses, Requirements Once: simplifying testing & verification in automotive model-based development](http://arxiv.org/abs/1906.07083v1): One textual formal requirement is exported to several verifiers (SLDV, BTC, SV-COMP-style C) and used for test generation.
- [From Rocq to Metal: A Pipeline for Formally Verified Microcontroller Firmware](https://arxiv.org/abs/2606.02651v2): Firmware logic is a pure Rocq state machine that returns effects as data; proofs cover only the parser and transition function, and the effects run outside the proved core.
- [Verified Correctness and Security of OpenSSL HMAC](https://www.usenix.org/conference/usenixsecurity15/technical-sessions/presentation/beringer): An end-to-end Coq proof of OpenSSL HMAC is organized as a 16-link assurance graph, so the trusted base is a small, named set of spec and assumption items.
- [Verified Software Units](https://doi.org/10.1007/978-3-030-72019-3_5): Modular unit verification requires exports to subsume imports and combines duplicate specs by intersection, a pattern for splitting a verified system into interfaces.
- [Zero-Knowledge Model Checking](https://arxiv.org/abs/2605.00487): Proves a secret transition system satisfies a public LTL property by publishing a ranking-function certificate and proving in zero knowledge that it is valid.
- [CTL+FO Verification as Constraint Solving](http://arxiv.org/abs/1406.3988v3): Reduces CTL+FO verification to existentially quantified recursive Horn clauses, so one constraint solver handles invariants, ranking functions, and quantifier instantiation.
- [CPAchecker: A Tool for Configurable Software Verification](http://arxiv.org/abs/0902.0019v1): CPAchecker is a generic reachability algorithm over CFAs with pluggable abstract domains, letting analyses be composed by configuration.
- [Reusing Precisions for Efficient Regression Verification](http://arxiv.org/abs/1305.6915v1): Saving abstraction precisions from one revision and reusing them on the next avoids rediscovering facts; tested on 16,772 runs over 59 Linux drivers.
- [Verification Artifacts in Cooperative Verification: Survey and Unifying Component Framework](http://arxiv.org/abs/1905.08505v1): Cooperative verification survey: verifiers exchange typed artifacts (witnesses, conditions, test cases) through a component framework, a model that may fit linking proofs, counterexample finders, and spec repair.
- [Software Verification: 10th Comparative Evaluation (SV-COMP 2021)](https://doi.org/10.1007/978-3-030-72013-1_24): SV-COMP 2021 is a reproducible comparison of verifiers using standardized tasks, validated witnesses, and explicit scoring over 15,201 C tasks.
- [Interpolation and SAT-Based Model Checking Revisited: Adoption to Software Verification](http://arxiv.org/abs/2208.05046v2): Large-block encoding summarizes loop-free regions so interpolation-based model checking yields useful interpolants on C software.
- [Improvements in Software Verification and Witness Validation: SV-COMP 2025](https://doi.org/10.1007/978-3-031-90660-2_9): True verifier results need a correctness witness and false results need a violation witness, so independent witness validation is how verifier claims get audited.
- [SV-LIB 1.0: A Standard Exchange Format for Software-Verification Tasks](https://arxiv.org/abs/2511.21509v1): SV-LIB 1.0 is an SMT-LIB extension that packages programs, specs, and witnesses into one exchange format, a possible common target for LLM-generated verification tasks.
- [Formal verification of the PQXDH Post-Quantum key agreement protocol for end-to-end secure messaging](https://www.usenix.org/conference/usenixsecurity24/presentation/bhargavan): ProVerif finds attacks on PQXDH revision 1, and after fixing the spec with Signal designers, revision 2 is proved in ProVerif and CryptoVerif.
- [Syntax-driven Incremental Program Verification of Matching Logic Properties](https://arxiv.org/abs/2606.08824v1): Incremental KernelC verification reparses only edited syntax, propagates semantic attributes upward, and beats full reverification after edits.
- [Resources: A Safe Language Abstraction for Money](https://arxiv.org/abs/2004.05106): Proves a conservation theorem for Move's linear-resource bytecode semantics, so resources cannot be copied or destroyed outside their declaring module.
- [COBALT-TLA: A Neuro-Symbolic Verification Loop for Cross-Chain Bridge Vulnerability Discovery](https://arxiv.org/abs/2604.12172): The LLM models a flawed system and TLC is the oracle, so a safe result signals a modeling error, and the bounded model uses very small ranges.
- [Mythos and the Unverified Cage: Z3-Based Pre-Deployment Verification for Frontier-Model Sandbox Infrastructure](https://arxiv.org/abs/2604.20496v1): COBALT asks Z3 whether a vulnerability pattern is satisfiable over libclang-extracted bitvector models; UNSAT only means absence within the encoded domain and bounds.
- [Static and Dynamic Verification of Relational Properties on Self-Composed C Code](http://arxiv.org/abs/1801.06876v2): Relational properties over several calls can be encoded as self-composed wrappers proved with ordinary WP, but a wrapper cannot prove its own assert once bodies are inlined.
- [An Efficient VCGen-based Modular Verification of Relational Properties](https://arxiv.org/abs/2401.08385v1): A Coq-mechanized VCGen lets a caller assume a relational contract for a called procedure, so no source-to-source product program is needed.
- [Mechanized Semantics for the Clight Subset of the C Language](https://arxiv.org/abs/0901.3619): Clight C subset gets a Coq-mechanized semantics inside CompCert, with big-step and coinductive rules that produce event traces.
- [Vale: Verifying High-Performance Cryptographic Assembly Code](https://www.usenix.org/conference/usenixsecurity17/technical-sessions/presentation/bond): Vale verifies annotated assembly: each instruction is a Dafny procedure proved against a machine semantics, so instruction specs need not be trusted and higher procedures compose through generated lemmas.
- [Using Lightweight Formal Methods to Validate a Key-Value Storage Node in Amazon S3](https://doi.org/10.1145/3477132.3483540): Split correctness into properties with one cheap automated checker each, and reuse an executable reference model as both the spec and the test mock; this found 16 bugs.
- [HoarePrompt: Structural Reasoning About Program Correctness in Natural Language](https://doi.org/10.1145/3744916.3773206): HoarePrompt has an LLM sample natural-language postconditions per code point to check a program against a requirement, giving a structured informal proof with no formal guarantee.
- [First-Class Refinement Types for Scala](https://doi.org/10.1145/3839541): Refinement types become ordinary Scala 3 types that take part in subtyping and inference, with a Rocq-mechanized soundness proof of the core calculus.
- [Compilation as Multi-Language Semantics](https://arxiv.org/abs/2509.19613v1): Work-in-progress multi-language semantics models source execution, compilation and target execution as one reduction system.
- [Coquet: A Coq Library for Verifying Hardware](https://arxiv.org/abs/1108.4253): Coquet makes circuit architecture first-class data in Coq, with transformations and semantics over it, so proofs can cover circuit generators.
- [Tactics for Reasoning modulo AC in Coq](https://arxiv.org/abs/1106.4448): Coq rewriting modulo AC keeps pattern matching untrusted and checks each proposed rewrite with a small reflexive decision procedure inside Coq.
- [A case study in formal verification of a Java program](http://arxiv.org/abs/1809.03162v1): Compares eight Java verifiers; automated SMT offers no recourse on failure beyond changing annotations, while interactive provers let the user continue a failed proof.
- [Compositional Safety Verification with Max-SMT](http://arxiv.org/abs/1507.03851v3): Max-SMT infers conditional inductive invariants per SCC and prefers weaker preconditions, but CheckSafe returns only Safe or Maybe, never unsafe.
- [Systematic Design of Separation Logics](http://arxiv.org/abs/2605.21262v1): A semantic method derives local axioms and frame rules for separation logics, instantiated as SL+, ISL+, SIL+ and NC+.
- [Verifying Numerical Methods with Isabelle/HOL](https://arxiv.org/abs/2511.20550v4): Isabelle/ITrees workflow proves total correctness of numerical methods by supplying loop invariants and variants to a VCG; a template for loop specs in Verus.
- [How to Simulate It in Isabelle: Towards Formal Proof for Secure Multi-Party Computation](https://arxiv.org/abs/1805.12482): Formalizes simulation-based MPC security proofs in Isabelle/CryptHOL, including oblivious transfer and a DDH reduction.
- [Towards Efficient Verification of Constant-Time Cryptographic Implementations](https://doi.org/10.1145/3643772): A cheap IFDS taint analysis first discharges most timing side-channel sources, leaving fewer sources for expensive constant-time proofs.
- [Quantifier Elimination for Database Driven Verification](http://arxiv.org/abs/1806.09686v2): Covers via quantifier elimination and model completions give a terminating EUF superposition procedure for database-driven infinite-state verification.
- [Towards Neural-Guided Program Synthesis for Linear Temporal Logic Specifications](http://arxiv.org/abs/1912.13430v1): Neural Q-guided search proposes LTL synthesis candidates that are checked against the transition model, so the network is only a heuristic.
- [C*: Unifying Programming and Verification in C](http://arxiv.org/abs/2504.02246v1): C* embeds separation-logic specs and proof code in C, with an LCF-style kernel where every heap-shape change must be justified by an entailment theorem.
- [CTL* Verification and Synthesis using Existential Horn Clauses](http://arxiv.org/abs/2408.11502v1): Translates CTL* verification and synthesis of infinite-state programs with fairness into satisfiability of existential Horn clauses, with soundness and relative-completeness theorems.
- [Specifying verified x86 software from scratch](http://arxiv.org/abs/1907.01283v1): MM0 specifies ELF x86-64 binary behavior with a small trusted base: PA-equivalent specs and a minimal custom proof checker.
- [Reimplementing Mizar in Rust](http://arxiv.org/abs/2304.08391v2): Independent Rust reimplementation of Mizar checks the full Mizar library in 11.8 minutes and exposed four soundness bugs.
