# LLM agents, benchmarks, evaluation

(authored by agents unless marked 🧑)

- [A DbC Inspired Neurosymbolic Layer for Trustworthy Agent Design](https://arxiv.org/abs/2402.00854): Wraps each LLM call in Design-by-Contract checks with bounded error-guided remediation; reports no measured verification rate, so it is a design proposal only.
- [A Domain-Specific Harness for End-to-End Automation of Optimization Research](http://arxiv.org/abs/2608.07407v1): AutoOPT pairs a general LLM with expert methodology and a human approval gate across numerical design, analytic proof discovery, Lean verification and write-up; two convergence proofs are machine-checked in Lean 4.
- [A Solver-in-the-Loop Framework for Improving LLMs on Answer Set Programming for Logic Puzzle Solving](https://arxiv.org/abs/2512.17093): Solver-labeled training data and solver-guided best-of-N with backtracking let an LLM learn to emit ASP encodings for logic puzzles.
- [Specification-first convergence with an AI coding agent: a case study of dismantling a core architectural invariant across 189 files in a 717k-line codebase with no test oracle and no human code review](https://www.semanticscholar.org/paper/af489dd2737dae878a33d72b9d9bead2b0634905): One agent, guided by a frozen behavioral spec over five phases, removed a core lifetime invariant across 189 files of a 717k-line TypeScript codebase with no test oracle; the evidence is one case.
- [Physics-Audited Agentic Discovery in Scientific Machine Learning](https://arxiv.org/abs/2607.07379): PA-SciML reports a surrogate as verified only under declared physics checks, domain, and tolerance, which is conditional verification rather than a proof.
- [Mathematical Discovery in the Wild: AI-Guided Proofs in Banach Space Theory](http://arxiv.org/abs/2607.17388v1): LLM workflows, including Codex agents over a filesystem, produced proofs of five new Banach-space results that humans then verified and refined.
- [Advocate for Complete Benchmarks for Formal Reasoning with Formal/Informal Statements and Formal/Informal Proofs](https://arxiv.org/abs/2507.04719): Benchmark items should bundle informal and formal statements and proofs, machine-check every proof, and report proof lines and solver time, since Verus checks contracts but not prose alignment.
- [AI IDEs or Autonomous Agents? Measuring the Impact of Coding Agents on Software Development](https://doi.org/10.1145/3793302.3793589): Repository-level causal study finds autonomous coding-agent adoption raises velocity but also static-analysis warnings (about 18%) and cognitive complexity (about 39%).
- [Agent-Driven Verification of Memory Safety for liblzma Decoder Components with VST](https://arxiv.org/abs/2608.29716): Agents wrote 27 closed VST proofs for liblzma decoder code, but termination and caller-callee contract compatibility remain unproved.
- [Agentic Proof Automation: A Case Study](https://arxiv.org/abs/2601.03768): Off-the-shelf agents reached 87% success on 189 Lean proof tasks, but 16% needed human intervention, the labels came from one annotator, and proof repair was the bottleneck.
- [Agentic Proving for Program Verification](https://arxiv.org/abs/2605.23772v1): A compiler-in-the-loop Claude Code agent proves CLEVER Lean specs at about $2 per solve, but CLEVER's isomorphism score is unreliable, so spec and proof quality need separate scoring.
- [AgentLTL: A Trace-Verification Framework for Measuring, Enforcing, and Training Procedural Compliance in Tool-Using LLM Agents](http://arxiv.org/abs/2607.02599v1): AgentLTL checks agent tool-call traces against FO-LTL procedure constraints deterministically, giving a compliance score usable for enforcement and training.
- [Semantic Intent Fragmentation: A Single-Shot Compositional Attack on Multi-Agent AI Pipelines](https://arxiv.org/abs/2604.08608): A benign-looking request can decompose into subtasks that jointly violate policy; a whole-plan verifier can close the gap before the first agent dispatch.
- [AgentModernize: Preserving Business Logic in Legacy Modernization with Multi-Agent LLMs and Behavioral Specification Graphs](https://arxiv.org/abs/2605.17535): Multi-agent legacy modernization makes business rules explicit in a behavior graph before code generation; it claims no formal equivalence, only tests on eight synthetic scenarios.
- [AI with Authority, from Application to Silicon](https://arxiv.org/abs/2608.21356): One human directs five long-running Claude agents for 37 days, exchanging kernel-checked claims under six required invariants R1-R6, though the author disclaims generalizability.
- [TreeThink: A Modular Tree Search Library for Mathematical Reasoning with LLMs](http://arxiv.org/abs/2607.11258v2): TreeThink is reusable async tree-search infrastructure that separates LLM proof-step proposal from Lean, Rocq, and Isabelle verifier calls.
- [Maestro Order: A Model-Agnostic Orchestration Harness](http://arxiv.org/abs/2606.23983v1): Maestro Order is a decompose-ensemble-verify harness for unreliable solvers, where each accepted independent check multiplies correctness odds by beta/alpha; all numbers come from Monte Carlo simulation, not real LLMs.
- [Formal Methods Meet LLMs: Auditing, Monitoring, and Intervention for Compliance of Advanced AI Systems](https://doi.org/10.1145/3805689.3812339): LTL progression monitors give 3-valued verdicts on black-box LLM agents, sound under perfect labeling, and each violation comes with a witness trace.
- [SWE-Bench+: Enhanced Coding Benchmark for LLMs](https://arxiv.org/abs/2410.06992v2): Passing tests does not mean an issue was fixed: 32.67% of SWE-Agent patches that passed SWE-bench leaked the solution in issue text, and 31% passed only through weak tests.
- [The Rise of AI-Native Software Engineering: Implications for Practice, Education, and the Future Workforce](https://arxiv.org/abs/2606.12986): A review of 48 studies finds productivity evidence contradictory, and work shifts toward specifying intent, supervising agents, and checking outcomes.
- [Trustworthy AI Software Engineers](https://arxiv.org/abs/2602.06310): Trustworthiness should be checked by reviewing selective evidence and justifications, not raw agent outputs.
- [AlgoVeri: An Aligned Benchmark for Verified Code Generation on Classical Algorithms](https://arxiv.org/abs/2602.09464v2): AlgoVeri gives 77 algorithms in Dafny, Verus, and Lean 4 with aligned specs, so pass-rate gaps reflect the toolchain or model.
- [Rewarding Novel Deductions: Solver-guided Process Supervision for Logical Reasoning](https://arxiv.org/abs/2609.34660v2): An RL reward from Z3 labels each reasoning step as valid, novel, tautological, or contradictory, so the model is paid for solver-checked new deductions.
- [ChipMEM: Verification-Grounded Memory for EDA Agents](https://arxiv.org/abs/2609.27067): Agent memory stores a learned skill only when a deterministic harness returns PASS, and failure statistics are Beta-smoothed with the LLM planner advisory only.
- [A Reality Check of Language Models as Formalizers on Constraint Satisfaction Problems](https://arxiv.org/abs/2505.13252): On constraint problems, LLM-written solver programs lose to direct LLM solving in most model-dataset pairs, and formalization fails worst on the most constrained problems.
- [Next-Token Prediction Task Assumes Optimal Data Ordering for LLM Training in Proof Generation](https://arxiv.org/abs/2411.00863): Next-token training assumes each step's supervision precedes its use; placing the key insight late hurts proof-generation learning, and no general optimal order is known.
- [Orchestrating LLM Agents for Scientific Research: A Pilot Study of Multiple Choice Question (MCQ) Generation and Evaluation](https://arxiv.org/abs/2602.18891): A human coordinated several LLM agents to build 1,071 SAT Math questions, judged by a 24-criterion rubric and two LLM judges in a pilot study.
- [QED: An Open-Source Multi-Agent System for Generating Mathematical Proofs on Open Problems](https://arxiv.org/abs/2604.24021): A multi-agent pipeline solved 5 of 18 expert-posed open projects, but the verifier numbers are over accepted candidates only and some projects had prior human proofs.
- [OptiRepair: Closed-Loop Diagnosis and Repair of Supply Chain Optimization Models with LLM Agents](https://arxiv.org/abs/2602.19439): An LLM agent repairs infeasible LPs using IIS-guided diagnosis, then checks domain rationality rules; the diagnosis loop is the reusable feedback mechanism.
- [APE-Bench: Evaluating Automated Proof Engineering for Formal Math Libraries](https://arxiv.org/abs/2504.19110): A benchmark accepts an agent's Lean repository edit only if it compiles and satisfies the instruction within declared scope.
- [Proving at Scale for Universal Algebra](https://arxiv.org/abs/2610.02500): LLM agents find finite identity bases for all semigroups of order 6 and below, with counter-model screening refuting 76 candidates before Lean, and a referee agent rebuilds results from source.
- [GRID: Grammar-Railed Decoding for Enterprise SQL Generation](https://arxiv.org/abs/2607.11951): GRID hard-masks illegal tokens during LLM SQL decoding using an incremental LALR(1) parser and cached masks, so output is grammar- and schema-valid.
- [A Neuro-Symbolic Approach to Strategy Synthesis for Strategic Logics](https://arxiv.org/abs/2606.17962): An LLM proposes strategies and a model checker certifies them; only verifier-accepted strategies are returned, a generate-and-certify pattern.
- [Thinking Machines: Mathematical Reasoning in the Age of LLMs](https://arxiv.org/abs/2508.00459v2): Survey: proving is more brittle than coding because one wrong tactic invalidates the whole proof state, so prover-in-the-loop tactic generation is the dominant pattern.
- [ATLAS: Automated Toolkit for Large-Scale Verified Code Synthesis](https://arxiv.org/abs/2512.10173v2): Training data for Dafny is generated with a frozen contract, and a fine-tuned 7B model raises DafnySynthesis pass@5 from 15.8% to 65.8%.
- [AutoCodeSherpa: Symbolic Explanations in AI Coding Agents](https://arxiv.org/abs/2507.22414v2): A bug report becomes an executable symbolic explanation: input condition, infection conditions, and output condition checked against sampled executions.
- [Automated Proof Generation for Rust Code via Self-Evolution](https://arxiv.org/abs/2410.15756v3): A verifier-filtered self-training loop (SAFE) raised Verus proof pass@1 on VerusBench from 11.5% for raw GPT-4o to 43.2% for a fine-tuned open model.
- [Automating Formal Verification with Agent-Guided Tree Search](https://arxiv.org/abs/2605.27485): A restart-per-round LLM baseline filled 24.6% of 423 Lean sorry holes, and parsing only the first JSON block discarded later self-corrections, which appeared in 53.9% of Sonnet 4.6 replies.
- [Autonomous Mathematical Discovery in an Open-World Multi-Agent Environment](https://arxiv.org/abs/2608.23691): Six LLM agents in an open-world Station ran construction problems and published papers; selected theorems were then checked in Lean outside the environment.
- [AxDafny: Agentic Verified Code Generation in Dafny](https://arxiv.org/abs/2606.32007): A Dafny agent counts a candidate only if the original requires/ensures survive, no assume/axiom/verify-false appears, and an LLM reviewer finds no cheating, with verifier diagnostics fed back over 20 attempts.
- [Recontextualization Mitigates Specification Gaming without Modifying the Specification](https://arxiv.org/abs/2512.19027): Train on completions sampled under a prompt that discourages cheating but train under a permissive prompt, which cuts reward gaming without changing the flawed reward.
- [ProofNet: Autoformalizing and Formally Proving Undergraduate-Level Mathematics](http://arxiv.org/abs/2302.12433v1): ProofNet provides 371 Lean 3 formal and informal statement-proof triples from undergraduate texts, where few-shot Codex with mathlib retrieval reaches 16.1% accuracy.
- [When Passing Tests Hides Vulnerabilities: An Empirical Study of Silent Failures in Agentic Systems](https://arxiv.org/abs/2609.10548): Agent patches can pass compilation and unit tests yet fail static security analysis or exploit tests, so functional tests are weak evidence.
- [PatchOptic for Shared-State LLM Workflows with Projected Views and Verified Structured Updates](http://arxiv.org/abs/2607.05483v1): Each workflow step declares a projected read view, a write region, and a patch source; a verifier checks structured patches against full state before commit, but semantic errors stay uncovered.
- [Scaling Self-Play with Self-Guidance](https://arxiv.org/abs/2604.20209): A frozen guide scoring problem quality, multiplied into the conjecturer reward, stops reward hacking in Lean self-play; without it the conjecturer produces very long disjunctions.
- [Towards a Probabilistic Framework for Analyzing and Improving LLM-Enabled Software](http://arxiv.org/abs/2501.06370v2): Treat LLM output as a distribution over meaning classes; a concentrated but misaligned top class fools certainty-based hallucination detection.
- [Failure Modes of Large Language Models on Research-Level Mathematics: A Taxonomy and an Empirical Characterisation](https://arxiv.org/abs/2606.24902): LLM research-math proofs fail in four modes: citation fabrication, premise smuggling, silent reformulation, local-to-global gaps; Gemini 2.5 Flash got 0 of 8 answers correct.
- [More Claims, Less Evidence: Bounded Verification of AI-Generated Digital Knowledge Artifacts](http://arxiv.org/abs/2610.05547v1): Passing a random audit of b claims raises artifact reliability only as far as the posterior PVP allows, which falls as artifact size grows at fixed budget.
- [Conflict-Aware Fusion: Mitigating Logic Inertia in Large Language Models via Structured Cognitive Priors](https://arxiv.org/abs/2512.06393): Models that score 1.0 on base rule sets fall to 0.0 under contradictory facts, so they do not track structural logic changes reliably.
- [Scalable, Symbiotic, AI and Non-AI Agent Based Parallel Discrete Event Simulations](https://arxiv.org/abs/2505.23846): Non-AI agents audit and verify each small-language-model agent action in a parallel simulation engine, correcting intermediate results.
- [Pseudo-Formalization for Automatic Proof Verification](http://arxiv.org/abs/2605.20531v3): A single LLM with no fine-tuning checks natural-language proof modules, trading the correctness guarantee of formal proof for applicability to mathematics lacking formal libraries.
- [Kevin: Multi-Turn RL for Generating CUDA Kernels](https://arxiv.org/abs/2507.11948): Kevin trains a model with multi-turn RL to write CUDA kernels; reward needs correctness before speedup, and best-of-16 reaches 82% correctness.
- [Putnam 2025 Problems in Rocq using Opus 4.6 and Rocq-MCP](https://arxiv.org/abs/2603.20405): Claude Opus 4.6 with Rocq tools solved 10 of 12 Putnam 2025 problems in one run costing about $1,760, and 95% of its tokens were cache reads.
- [SciCoQA: Quality Assurance for Scientific Paper-Code Alignment](https://arxiv.org/abs/2601.12910): Synthetic code-diff discrepancies gave recall that tracked recall on real discrepancies (r = 0.94), so synthetic injection is a cheap proxy for testing LLM paper-code mismatch detection.
- [Teaching LLMs Program Semantics via Symbolic Execution Traces](https://arxiv.org/abs/2605.06184): LLMs judge bug-free C well but miss violations (4 of 14 models find under 50%); the proposed fix is continued pretraining on symbolic-execution traces, with the training effect not shown in the excerpt.
- [Benchmarking Agents for Proving Theorems in Quantum Algorithms and Quantum Information](https://arxiv.org/abs/2607.21533): Lean 4 theorem-completion benchmarks score agents by difficulty-weighted acceptance, with best results 60.4/100 on QAlg-Bench and 59.6/100 on QIT-Bench, and difficulty is frozen before runs.
- [Progress on Software Verification: SV-COMP 2022](https://doi.org/10.1007/978-3-030-99527-0_20): SV-COMP 2022 covers 15,648 C and 586 Java tasks and is a template for reproducible verifier benchmarking with witness validation and resource accounting.
- [interwhen: A Generalizable Framework for Steering Reasoning Models with Test-time Verification](https://arxiv.org/abs/2602.11202v3): Verifying a reasoning trace during generation, rolling back to the last checked prefix on violation, and abstaining after more than five corrections; the guarantee holds only modulo state-extraction errors.
- [Agentic AI in the Software Development Lifecycle: Architecture, Empirical Evidence, and the Reshaping of Software Engineering](https://arxiv.org/abs/2604.26275): SWE-bench Verified rose from 1.96% to 78.4% in under three years; time-savings figures are compiled from cited reports, not measured here.
- [Beyond Code Generation: Reliability, Verification, and Cost Economics in the Agentic Software Development Lifecycle](https://arxiv.org/abs/2609.04681): Candidate-code throughput rises faster than reliable release throughput, so the paper proposes the production-qualified change as the unit of output.
- [Automated Multi-Agent Workflows for RTL Design](http://arxiv.org/abs/2509.20182v1): Tool feedback decides when to escalate reasoning for Verilog: escalate when the fraction of failing candidates exceeds a threshold set from failure percentiles.
- [Diagnosing with Insights: Structured Analysis of Agent Failures via Behavioral Abstractions](https://arxiv.org/abs/2609.02371): AgentScope builds a reasoning-action graph from agent traces and checks invariants to localize the failing step and failure type.
- [The Tactician’s Web of Large-Scale Formal Knowledge](https://arxiv.org/abs/2401.02950v2): Tactician exports Coq libraries as semantic graphs, splits data by dependency hash to avoid train-test leakage from derived definitions, and records 4.6M proof transitions.
- [Broken by Default: A Formal Verification Study of Security Vulnerabilities in AI-Generated Code](https://arxiv.org/abs/2604.05292v2): 55.8% of 3,500 LLM-generated artifacts have a Cobalt-found vulnerability, 1,055 are proven by Z3 SAT with replayed exploit witnesses, and prompt wording barely changes the rate.
- [Euclid-MCP: A Model Context Protocol Server for Deterministic Logical Reasoning via Prolog](https://arxiv.org/abs/2607.21412): Euclid-MCP separates an untrusted LLM translator from a small trusted Prolog kernel that decides queries and returns proof trees, so the model never declares a spec proved.
- [Risk-Controlled Lean-as-Judge for Natural-Language Mathematical Reasoning](http://arxiv.org/abs/2605.28365v1): Failed or missing Lean proofs are weak evidence, so a predeclared threshold on coverage diagnostics decides when a formal answer may be accepted.
- [Generative transformations and patterns in LLM-native approaches for software verification and falsification](https://arxiv.org/abs/2404.09384): A survey of 111 LLM verification papers gives a six-category transformation taxonomy and recurring patterns such as Generate and Fix, but its literature ends mid 2024.
- [The Impact of GenAI on the Future of Requirements Engineering](https://arxiv.org/abs/2609.05667): As agents make implementation cheap, requirements work shifts to specifying, curating, and verifying; this is a non-systematic survey, so treat claims as opinion.
- [ESAA-Security: An Event-Sourced, Verifiable Architecture for Agent-Assisted Security Audits of AI-Generated Code](https://arxiv.org/abs/2603.06365): Event-sourced audits make AI-assisted security review evidence-based: agents emit intents, an orchestrator validates them, and an append-only log supports replay.
- [Large Language Monkeys: Scaling Inference Compute with Repeated Sampling](http://arxiv.org/abs/2407.21787v3): Repeated sampling raises coverage steadily with sample count, and with an automatic checker coverage becomes success rate, e.g. SWE-bench Lite rises from 15.9% at one attempt to 56% at 250.
- [Agent Hunt: Bounty Based Collaborative Autoformalization With LLM Agents](https://arxiv.org/abs/2603.06737): Four coding agents wrote a 121k-line Megalodon library in about 2 days 15 hours, but the speed comparison is uncontrolled and no semantic audit was done.
- [Towards Automated Functional Equation Proving: A Benchmark Dataset and A Domain-Specific In-Context Agent](https://arxiv.org/abs/2407.14521): Strategy-first prompting with per-state failure memory solves most simple functional-equation problems in Lean; the hard tier is the real test.
- [SAGE: Symbolic Action-Gating and Editing for LLM Task Planners](https://arxiv.org/abs/2609.34268): SAGE gates LLM planner actions with a deterministic symbolic precondition check before execution and repairs only the failed suffix, raising step success up to 0.11.
- [Vul4Py: Benchmarking Automated Vulnerability Repair in Python with Paired Exploit and Functional Oracles](http://arxiv.org/abs/2608.00692v1): Accepting patches by exploit tests alone over-credits them, since a paired functional suite rejected 12.6% of exploit-passing patches in a 100-instance Python benchmark.
- [Building A Proof-Oriented Programmer That Is 64% Better Than GPT-4o Under Data Scarsity](https://arxiv.org/abs/2502.11901): PoPilot fine-tunes Qwen2.5-Coder-14B on synthetic F* data where the verifier alone filters examples, a possible recipe when a verified language has little training data.
- [Cogentic: Multi-Agent Orchestration for Automated Proof Discovery](https://arxiv.org/abs/2609.40324): Cogentic runs a prove-verify loop with parallel provers, adversarial dual checking, and a verified ledger, using O(100) Gemini calls for most open problems; five results were later checked by experts.
- [r2py: AI-Assisted Conversion of R Statistical Packages to Python](https://arxiv.org/abs/2608.16911): Ports R packages to Python by treating the trusted R code as reference and comparing outputs at declared tolerances, a translation-validation pattern usable for a Verus port.
- [Reinforcement Learning with Verifiable Physics: Post-training LLMs with Continuous Rewards](https://arxiv.org/abs/2607.10474): RLVP trains a model to write numerical PDE solvers with rewards from execution, reference error, and PDE residual; code is the action and physics is the verifier.
- [Can LLMs Enable Verification in Mainstream Programming?](https://arxiv.org/abs/2503.14183v1): Splitting generation into six information modes isolates where LLM verification breaks, and counting a task solved if any of five runs verifies measures coverage, not per-attempt accuracy.
- [Can Open-Weight LLMs Produce Kernel-Verified Coq Proofs? A Pilot Study](https://arxiv.org/abs/2608.05420): Open-weight LLM Coq proofs count only if the Coq kernel and coqchk accept them, so plausible tactic text is not success.
- [Evaluating Frontier LLMs on PhD-Level Mathematical Reasoning: A Benchmark on a Textbook in Theoretical Computer Science about Randomized Algorithms](https://arxiv.org/abs/2512.13978): Benchmark of frontier LLMs writing LaTeX proofs for Randomized Algorithms exercises, graded by an LLM verifier with sampled human review.
- [LLMs Know When They Know, but Do Not Act on It: A Metacognitive Harness for Test-time Scaling](https://arxiv.org/abs/2605.14186): A retry rule fitted on model self-assessment allocates extra reasoning budget only to questions worth retrying; this is a control policy, not a proof technique.
- [MechMath Agent Team: LLM Driven Agents for Mathematical Research](http://arxiv.org/abs/2607.04394v1): A multi-agent math harness where only the Lean kernel judges validity, agents hand off through files, and recurring failures become stored negative constraints; the evidence is case studies only.
- [Pushing the Boundaries of Natural Reasoning: Interleaved Bonus from Formal-Logic Verification in Language Models](https://arxiv.org/abs/2601.22642v2): Interleaving natural-language reasoning with Z3 or SAT checks helps RL-trained models, but 39.3% of correct-answer chains still contain formally disproved steps, so correct answers do not certify valid steps.
- [Can Large Language Models Help Students Prove Software Correctness? An Experimental Study with Dafny](https://arxiv.org/abs/2506.22370): Students using ChatGPT on Dafny exercises performed significantly better, but gains depend on prompt quality.
- [CoqPyt: Proof Navigation in Python in the Era of LLMs](https://arxiv.org/abs/2405.04282v1): A Python client over the Coq LSP records goals before each step and the terms used, so training inputs use available terms and targets use the terms actually used.
- [MultiPL-E: A Scalable and Extensible Approach to Benchmarking Neural Code Generation](https://arxiv.org/abs/2208.08227): MultiPL-E builds 18-language benchmarks by translating only signatures, tests, and types so the model writes bodies, a pattern that could emit Verus contracts with bodies left to the model.
- [Mechanism-level routing failure in LLMs over Lean-verified algebraic structures](http://arxiv.org/abs/2607.04534v1): LLMs often misidentify the proof mechanism behind Lean-verified theorems, and naming the certificate family in the prompt raises template accuracy by 10 to 14 points.
- [Why Do Multi-Agent LLM Systems Fail?](https://arxiv.org/abs/2503.13657): MAST taxonomy of 14 multi-agent LLM failure modes from 1,642 annotated traces; task-verification failures form one category.
- [Lean-ing on Quality: How High-Quality Data Beats Diverse Multilingual Data in AutoFormalization](http://arxiv.org/abs/2502.15795v1): Hand-curated backtranslation is the paper's proposed route to better Lean autoformalization data; the excerpt gives the method but no measured gain.
- [Think with Self-Decoupling and Self-Verification: Automated RTL Design with Backtrack-ToT](https://arxiv.org/abs/2511.13139): VeriBToT generates Verilog by backtracking tree-of-thought with module self-decoupling and self-verification; each node holds RTL and a testbench.
- [LLM-Based FORM Code Generation with Verification-Driven Fine-Tuning](https://arxiv.org/abs/2609.23367): The Form binary acts as an execution oracle that validates 4,633 generated examples used to fine-tune a small model.
- [IaC-Guard-V: A Verification Framework for LLM-Generated Infrastructure-as-Code Repairs](https://arxiv.org/abs/2609.28488v1): Verifies LLM infrastructure-as-code repairs with three binary checks: syntactic validity, target-issue resolution, and zero regressions; minimality is reported but does not decide the verdict.
- [Verification Reward Model for Reinforcement Learning in Chip Design Verification](https://arxiv.org/abs/2609.22347v1): Position paper: proposes a verification reward model using frozen contracts and a protected evaluator to train LLMs for hardware verification; reports no results.
- [Premise Order Matters in Reasoning with Large Language Models](http://arxiv.org/abs/2402.08939v3): Premise order alone changes LLM deductive accuracy by up to 20 to 30 points, because models follow the presented rule order and invent facts when a rule is not yet applicable.
- [Towards Mitigating API Hallucination in Code Generated by LLMs with Hierarchical Dependency Aware](https://doi.org/10.1145/3696630.3728569): Project-specific API calls hallucinate at 85.25% versus 12.75% for third-party APIs, and decoding constrained to a trie of valid API names is the paper's fix.
- [Language Models For Generalised PDDL Planning: Synthesising Sound and Programmatic Policies](https://arxiv.org/abs/2508.18507): LLM-written PDDL policies stay sound by replacing inapplicable actions and returning only goal-checked plans, but completeness and termination are not guaranteed.
- [Rethinking Fine-Tuning when Scaling Test-Time Compute: Limiting Confidence Improves Mathematical Reasoning](https://arxiv.org/abs/2502.07154): Cross-entropy fine-tuning hurts pass@N at large N through overconfidence; Direct Coverage Optimization trains for pass@N directly, but the paper never evaluates a Verus-style verifier.
- [SmartPoC: Generating Executable and Validated PoCs for Smart Contract Bug Reports](https://arxiv.org/abs/2511.12993v3): SmartPoC generates, repairs, and executes exploit tests, using differential verification as an execution-grounded oracle.
- [Solver-Informed RL: Grounding Large Language Models for Authentic Optimization Modeling](http://arxiv.org/abs/2505.11792v3): Solver execution (syntax, feasibility, objective, structure) gives rewards for RL on optimization modeling, with instance-enhanced self-consistency for data selection.
- [Learning to Coordinate Symbolic Tools: LLM Agents for Verified Sum-of-Squares Certificates](https://arxiv.org/abs/2608.00326): LLM agents with exact symbolic tools find sum-of-squares certificates; the hard part is the sequential search path, not the local tool calls.
- [A Design Theory for AI-Assisted Software Development Derived from Christopher Alexander’s Theory of Form](https://arxiv.org/abs/2605.13357): Machines check spec, test and program agreement while humans judge whether the spec fits the world; passing checks does not prove correctness.
- [JURY-RL: Votes Propose, Proofs Dispose for Label-Free RLVR](http://arxiv.org/abs/2604.25419v1): Label-free RL lets rollouts vote and sends only the plurality answer to a Lean verifier, so unverified plurality is penalized without gold labels.
- [Learning to Generate Formally Verifiable Step-by-Step Logic Reasoning via Structured Formal Intermediaries](http://arxiv.org/abs/2603.29500v1): PRoSFI rewards each structured formal claim that a prover verifies, not only the final answer, so invalid intermediate deductions get penalized.
- [PairCoder++: Pair Programming as a Universal Paradigm for Verified Code-Driven Multimodal and Structured-Artifact Generation](https://arxiv.org/abs/2607.01883): A Driver agent writes code and a Navigator agent reviews it against compiler, test, and render evidence, switching roles on persistent errors; evaluated on 17 benchmarks.
- [Recursive Self-Improvement in AI: From Bounded Self-Refinement to Autonomous Research Loops](https://arxiv.org/abs/2607.07663v2): A survey of 1,250 papers separates bounded self-refinement against a fixed external evaluator from open-ended self-improvement with no fixed anchor.
- [SCAFFOLD-CEGIS: Preventing Latent Security Degradation in LLM-Driven Iterative Code Refinement](https://arxiv.org/abs/2603.08520): Repeated LLM edits drift from security specs, with 43.7% of chains exceeding baseline vulnerability count by iteration 10, and anchored invariants plus rollback stop the drift.
- [Barbarians at the Gate: How AI is Upending Systems Research](https://arxiv.org/abs/2510.06189v3): ADRS loop (LLM proposes algorithms, simulator or system evaluates, selected results feed back) shows LLM search can improve systems code when performance is measurable.
- [SysMoBench: Evaluating AI on Formally Modeling Complex Real-World Systems](https://arxiv.org/abs/2509.23130v3): SysMoBench scores LLM-written TLA+ models of real systems by behavioral conformance and warns that TLC running successfully does not show the model describes the system.
