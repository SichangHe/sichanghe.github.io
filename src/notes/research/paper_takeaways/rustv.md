# Rust and Verus verification

(authored by agents unless marked 🧑)

- [Symbolic Execution Meets Multi-LLM Orchestration: Detecting Memory Vulnerabilities in Incomplete Rust CVE Snippets](http://arxiv.org/abs/2605.00034v1): Turns incomplete Rust CVE snippets into compilable FFI wrappers for KLEE; Kani, Prusti, Creusot, and Haybale compiled none of the 31 files.
- [Forte: A sensitivity type system for imperative Rust](http://arxiv.org/abs/2609.30254v1): Forte makes sensitivity tracking sound by using exclusive &mut to strongly update environments, checked by Flux with leaf theorems in Verus.
- [Mitigating False Positives in Static Memory Safety Analysis of Rust Programs via Reinforcement Learning](http://arxiv.org/abs/2605.04000v2): RL policy triages Rudra Rust static-analysis warnings and uses cargo-fuzz for selective dynamic validation; 74.4 percent of 4,879 manually labeled warnings were false positives.
- [An approach for modularly verifying the core of Rust’s atomic reference counting algorithm against the (Y)C20 memory consistency model](https://doi.org/10.5381/jot.2026.25.1.a3): Modular proof method for relaxed atomics applied to Rust Arc; tied resources and atomic specs are sound for C20 and the stronger YC20 model.
- [Yuga: Automatically Detecting Lifetime Annotation Bugs in the Rust Language](http://arxiv.org/abs/2310.08507v3): Yuga is a static bug detector, not a proof checker, for incorrect Rust lifetime annotations; it finds 16 of 23 vulnerable RustSec functions.
- [RustAssure: Differential Symbolic Testing for LLM-Transpiled C-to-Rust Code](https://arxiv.org/abs/2510.07604v1): A zero symbolic-output distance S3 means equal output values, not equivalent functions, and Claude-3.5-Sonnet transpilations compiled least often at 48.3%.
- [Predicate Abstraction for Linked Data Structures](https://arxiv.org/abs/1505.02298): Art infers refinements for linked structures from user templates by separating heap shape from SMT-decidable data predicates.
- [Verifying Rust Programs with SMACK](https://www.semanticscholar.org/paper/350795523676e071a64d8d60acd30252db2c7eec): SMACK reaches Rust through rustc, LLVM, and a Boogie translation checked by Corral; verification is only bounded by loop and recursion unrolling, and the trusted base is large.
- [Verifying Safe Clients of Unsafe Code and Trait Implementations in Rust](https://www.semanticscholar.org/paper/417738a0b6b1e2772bd3947e5d53cabbd8e6033a): Idea: encode an unsafe trait's safety obligation as a postcondition that each impl must verify; the thesis prototypes only the trait chapter, and interior mutability and contract derivation are design only.
- [Linear Haskell: practical linearity in a higher-order polymorphic language](https://doi.org/10.1145/3158093): Attaches linearity to function arrows, enabling safe in-place mutation and resource protocols without splitting types into linear and non-linear variants.
- [Borrowable Fractional Ownership Types for Verification](https://doi.org/10.1007/978-3-031-50521-8_11): Borrowable fractional ownership types verify programs with aliased references by splitting ownership fractions, a reference-free model of Rust borrows for Verus.
- [SafeFFI: Efficient Sanitization at the Boundary Between Safe and Unsafe Code in Rust and Mixed-Language Applications](http://arxiv.org/abs/2510.20688v1): SafeFFI sanitizes raw-to-safe pointer crossings in Rust, cutting checks up to 98%, though optional heap checks miss some concurrent deallocation cases.
- [Verifying Extract Method Refactoring in Rust](https://doi.org/10.1145/3758316.3765486): Zero-annotation equivalence check for Rust extract-method refactorings: Charon, Aeneas, and Coq show results and effect traces match under the call-site precondition; the evidence is 10 cases.
- UtManager: a verified Rust buddy physical memory allocator: A manual Verus proof of a buddy allocator found a real bug in allocation paths, and its key invariant ties free-list membership to bitmap bits and parent bits to child bits.
- [RustMap: Towards Project-Scale C-to-Rust Migration via Program Analysis and LLM](https://arxiv.org/abs/2503.17741v1): RustMap splits C into dependency-aware units, translates them with an LLM, and passes original tests; coverage is limited to code the tests execute.
- [Can LLMs Reason Like Automated Theorem Provers for Rust Verification? VCoT-Bench: Evaluating via Verification Chain of Thought](https://arxiv.org/abs/2603.18334v2): VCoT-Lift turns a Z3 proof of a verified Verus program into Verus assertions and lemmas, and VCoT-Bench scores whether models rebuild that chain, not just whether verification passes.
- [Session Types for the Transport Layer: Towards an Implementation of TCP](https://doi.org/10.4204/EPTCS.401.3): Session types for a TCP subset in Rust types: rustc checks message order via consumed continuation tokens, but only compliance with the chosen model, not TCP's own properties.
- [TYPEPULSE: Detecting Type Confusion Bugs in Rust Programs](http://arxiv.org/abs/2502.03271v1): Static analyzer for unsafe Rust pointer conversions (as, transmute), built from 26 type-confusion bugs in 32 RUSTSEC reports.
- [&inator: Correct, Precise C-to-Rust Interface Translation](https://doi.org/10.1145/3808270): Solving ownership, mutability, and lifetime choices jointly with Z3 yields Rust interface types for C programs, instead of running those analyses in sequence.
- [A Framework for Debugging Automated Program Verification Proofs via Proof Actions](https://doi.org/10.1007/978-3-031-65627-9_17): ProofPlumber applies 17 untrusted source-rewriting actions to debug failing Verus proofs, each one a repair a developer would do by hand.
- [Revisiting Borrow Checking with Abstract Interpretation](https://doi.org/10.5381/jot.2026.25.1.a14): Recasts Rust borrow checking as abstract interpretation over a language-agnostic IR (MIMIR), giving path-sensitive checks of aliasing and initialization.
- [Combining Type Checking and Formal Verification for Lightweight OS Correctness](https://arxiv.org/abs/2501.00248v1): Rust types handle cheap invariants and Prusti handles the rest in a lightweight OS, catching an overlapping-frame allocator bug that stayed dormant for over four years.
- [Compositional Reasoning for Side-effectful Iterators and Iterator Adapters](https://arxiv.org/abs/2210.09857v1): Modular Prusti specs for side-effectful Rust iterators use ghost predicates for produced values and completion, so clients can reason about arbitrary adapter chains.
- [Linear effects, exceptions, and resource safety: a Curry-Howard correspondence for destructors](https://doi.org/10.48550/arXiv.2510.23517): Curry-Howard account of linear types with destructors and exceptions, formalizing resource-safety reasoning for drops like those in Rust.
- [Corten - Foundational Verification of Rust Programs](https://arxiv.org/abs/2609.04372v1): Corten verifies Rust in Rocq on Iris via syntax-directed weakest-precondition rules, each giving an under-approximation; the paper shows the claim only by examples.
- [Crux, a Precise Verifier for Rust and Other Languages](https://arxiv.org/abs/2410.18280v1): Crux-MIR is a bounded bit-precise symbolic verifier for Rust in which symbolic unit tests act as bounded theorems and every panic counts as a failed assertion.
- [SafeDrop: Detecting Memory Deallocation Bugs of Rust Programs via Static Data-Flow Analysis](http://arxiv.org/abs/2103.15420v2): Path-sensitive MIR data-flow analysis finds Rust deallocation bugs, with 1.0% to 110.7% compile overhead on nine CVEs.
- [rCanary: Detecting Memory Leaks Across Semi-automated Memory Management Boundary in Rust](https://arxiv.org/abs/2308.04787): rCanary statically finds leaks where Rust values move to manual destruction, using MIR, bit vectors, and Z3; it reports 19 leaks in 1,200+ crates.
- [Is unsafe an Achilles’ Heel? A Comprehensive Study of Safety Requirements in Unsafe Rust Programming](http://arxiv.org/abs/2308.04785v1): A 19-property taxonomy of unsafe Rust safety requirements (12 preconditions, 7 postconditions) serves as a contract vocabulary for specs and analyzers.
- [Fearless Unsafe. A More User-friendly Document for Unsafe Rust Programming Base on Refined Safety Properties.](https://arxiv.org/abs/2412.06251v2): Derives 22 safety properties from std unsafe APIs and splits unsafe-API requirements into preconditions and postconditions, delivered as a rust-analyzer hover.
- [Verifying Rust Implementation of Page Tables in a Software Enclave Hypervisor](https://doi.org/10.1145/3620665.3640398): Verifying 2,130 lines of Rust page-table code in Coq took about 3 person-years and 15,100 proof lines, with per-interface layered specs so each layer relies only on lower-layer specs.
- [PinChecker: Identifying Unsound Safe Abstractions of Rust Pinning APIs](https://arxiv.org/abs/2504.14500v2): PinChecker searches for call sequences that move pinned values in safe Rust abstractions; it finds counterexamples only, so a failed search is not a soundness proof.
- [Translating Large-Scale C Repositories to Idiomatic Rust](http://arxiv.org/abs/2511.20617v1): Rustine translates whole C repositories to Rust with 100% compilation and 87% passing assertions, but the evidence is tests, not proofs, and many raw pointer operations remain.
- [Specifying and Verifying Higher-order Rust Iterators](https://doi.org/10.1007/978-3-031-30820-8_9): Creusot specifies nondeterministic, infinite, interruptible Rust iterators using prophecy values for mutable references, and needs no separation logic because non-aliasing holds.
- [Vérification déductive de programmes Rust](https://theses.hal.science/tel-04517581v1): Creusot translates Rust MIR to Why3; the thesis argues a verifier can leverage the borrow checker's guarantees, with the RustHornBelt account and iterator specifications.
- [Vérification déductive de programmes Rust (Deductive verification of Rust programs)](https://theses.hal.science/tel-04517581v1): Thesis on Creusot: translates Rust MIR to MLCFG and Why3, uses the borrow checker to avoid memory-safety proofs, and targets under one spec line per code line.
- [Using a Prophecy-Based Encoding of Rust Borrows in a Realistic Verification Tool](https://openalex.org/W4414486737): Creusot prophecy encoding of Rust mutable borrows: ghost code can read a prophecy and prove false, so the paper proposes a prophetic logic fence rather than banning prophecies in ghost code.
- [RustyDL: A Program Logic for Rust](https://arxiv.org/abs/2602.22075): RustyDL is a dynamic-logic program logic for safe Rust on rustc HIR, but its soundness proof is ongoing work and its evidence is one binary search example.
- [Recursive Data Structures in SPARK](https://doi.org/10.1007/978-3-030-53291-8_11): SPARK gets Rust-like ownership for heap pointers, reasoned about first-order through Why3 VCs; cycles and shared substructures are excluded, and reborrowing only goes deeper.
- [Taming stateful computations in Rust with typestates](https://doi.org/10.1016/j.cola.2022.101154): A typestate macro makes rustc reject wrong call order, though it checks only that states are reachable and productive, and the evidence is toy examples.
- [Towards Translating Real-World Code with LLMs: A Study of Translating to Rust](http://arxiv.org/abs/2405.11514v3): Differential fuzzing with cross-language state mapping gives strong evidence of C-to-Rust equivalence without target tests, but it is heuristic, not a proof.
- [Is Rust Used Safely by Software Developers?](https://doi.org/10.1145/3377811.3380413): Under 30% of 15,097 crates use unsafe directly, yet 38% look locally safe while depending on unsafe crates, so a verified top-level function still trusts its dependency edges.
- [SafeTrans: LLM-assisted Transpilation from C to Rust](https://doi.org/10.1145/3786180.3788317): Pairing generic compiler-feedback repair with few-shot error-specific instructions improves C-to-Rust translation across 2,653 CodeNet programs.
- [The Usability of Advanced Type Systems: Rust as a Case Study](http://arxiv.org/abs/2301.02308v1): A survey of Rust usability finds ownership and lifetimes impose a steep learning curve, plausibly a lower bound for verified Rust.
- Fewer Assumptions by Design: reusable DLL verification guidance: Interactive Verus work on 11 doubly linked lists shows stronger shared specs cut trusted assumes; the final version verifies 45 items but still leaves 11 assumes.
- [Leveraging Rust Types for Program Synthesis](https://doi.org/10.1145/3591278): Rust ownership rules out duplicated and invented values, so synthesis from types has a smaller search space, and specs can state only functional behavior.
- [Finding a Crab in the C: Assured Translation via Comparative Symbolic Execution](https://arxiv.org/abs/2605.12731v1): COZY compares C and Rust binaries with comparative symbolic execution; the developer labels each flagged difference as intentional or erroneous, and outside those labels the binaries are formally equivalent.
- [Verified Rust Monitors for Lola Specifications](http://arxiv.org/abs/2012.08961v1): A Lola-to-Rust compiler's proof rests on a ring buffer matching an unbounded ghost sequence within the memory bound, and Viper forgets loop-mutated facts, so invariants must restate them.
- [Flux: Liquid Types for Rust](https://doi.org/10.1145/3591283): Flux adds indexed refinement types to Rust so bounds checks become ordinary typed calls, but it proves only lightweight properties and rests on a Stacked Borrows soundness argument.
- Forte: sensitivity proofs for imperative Rust: Forte checks how much outputs change under private input changes using Rust borrows, refinement types, and Verus proofs, but trusts primitive Rust bodies by inspection.
- [Scylla: Translating an Applicative Subset of C to Safe Rust](https://doi.org/10.1145/3798229): Scylla translates a structured C subset to safe Rust after the programmer refactors C into Mini-C; the paper is a translation technique, not a functional verifier.
- [RefinedRust: A Type System for High-Assurance Verification of Rust Programs](https://doi.org/10.1145/3656422): RefinedRust verifies safe and unsafe Rust in Coq via Iris; a simplified Vec takes 120 lines of Rust and 76 lines of annotation, while concurrency, traits, and closures are unsupported.
- [Bringing Foundational Verification to Real-World Rust Code](https://doi.org/10.1145/3839484): RefinedRust gains traits, closures, and iterators; loops need an explicit Hist variable of emitted elements, which Verus trait specs must also write out.
- [Raw Pointer Rewriting with LLMs for Translating C to Safer Rust](http://arxiv.org/abs/2505.04852v3): LLMs eliminated 2,255 raw pointers across 28 c2rust projects by lifting them to safe types under per-pointer repair loops, at about $1.13 per project.
- [PermRust: A Token-based Permission System for Rust](http://arxiv.org/abs/2506.11701v1): PermRust uses zero-sized permission tokens in Rust types to restrict per-library resource access; a concept and proof of concept with no evaluation.
- [Applying Modern Verification Techniques to a Root-of-Trust Bootloader](https://doi.org/10.1145/3764860.3768324): Retrofits Verus onto a DICE root-of-trust bootloader to partially verify secure context erasure, under stated assumptions about ownership, compiler, linker, and assembly.
- [An Interactive Debugger for Rust Trait Errors](https://doi.org/10.1145/3729302): Argus visualizes Rust trait-inference trees to localize trait errors; it does not verify functional contracts.
- [Rust2Viper: Building a Static Verifier for Rust](https://www.semanticscholar.org/paper/cd7109eba28fb08ccdbd2e5cbf2c9e69fd878255): Rust2Viper lets users write only functional contracts while the translator synthesizes permission specs from Rust types and borrows, reducing ownership boilerplate.
- [Verification of a Rust Implementation of Knuth's Dancing Links using ACL2](https://doi.org/10.4204/EPTCS.393.13): A restricted Rust subset translated to ACL2 gives about 160 theorems for Dancing Links, but the proof concerns the translated model, not compiled Rust.
- [When Lifetimes Liberate: A Type System for Arenas with Higher-Order Reachability Tracking](https://arxiv.org/abs/2509.04253): A reachability type system with one reference type and three allocation modes is mechanized in Rocq with type and memory safety proofs; there is no Rust implementation or performance result.
- [Benefits of Applying Software Design Patterns to Backend Rust Applications](http://arxiv.org/abs/2607.02744v1): Typestate and newtype refactorings move invariant enforcement into the Rust compiler in backend components; functional correctness is explicitly out of scope.
- [Aeneas: Rust verification by functional translation](https://doi.org/10.1145/3547647): Aeneas translates safe Rust (LLBC) into pure functional code using region types, removing memory reasoning for programs without interior mutability or unsafe.
- [Formal Verification of Rust Programs by Functional Translation](https://theses.hal.science/tel-05004605v1): Aeneas translates borrow-checked Rust into pure functional code for F*, Coq, HOL4, and Lean, erasing uniquely owned references and returning &mut values as value and continuation pairs.
- [RustPruner: A Program Slicing Tool for Rust Programs](https://doi.org/10.18293/seke2024-118): Slicing Rust code down to the Kani-proof dependencies cut verification time on four OS projects while keeping results consistent, though there is no formal preservation proof.
- [A Hybrid Approach to Semi-automated Rust Verification](https://doi.org/10.1145/3729289): Split Rust proofs at the safety boundary: Creusot proves safe code while Gillian-Rust proves unsafe code, with ownership predicates bridging the two, as a proof-of-concept.
- [Borrowing Safe Pointers from Rust in SPARK](http://arxiv.org/abs/1805.05576v1): SPARK pointer ownership borrows Rust's per-path permission lattice and checks alias safety at every sequence point, though the proof is only sketched.
- [Thetis: A Booster for Building Safer Systems Using the Rust Programming Language](https://doi.org/10.3390/app132312738): Thetis classifies unsafe Rust sites into five categories (raw-pointer dereference, unsafe calls, unsafe trait impls, mutable statics, union fields) so each site can be counted.
- [Unlocking a New Rust Programming Experience: Fast and Slow Thinking with LLMs to Conquer Undefined Behaviors](https://arxiv.org/abs/2503.02335v1): RustBrain repairs Miri-detected undefined behavior by generating candidate repairs and validating them with replacement, assertion, and modification agents; 94.3% pass with GPT-4 on the Miri dataset.
- [An Executable Operational Semantics for Rust with the Formalization of Ownership and Borrowing](http://arxiv.org/abs/1804.07608v2): RustSEM expresses ownership and borrowing as five graph invariants checked at the memory level, and well-formedness implies exclusive mutation.
- [Kani: A Model Checker for Rust](https://doi.org/10.1145/3832783.3834499): Kani model checks Rust via CBMC, where proofs depend on harness coverage, assumptions, and unwind bounds, so an unwinding failure is inconclusive and assume(false) makes proofs vacuous.
- [Ravencheck: Effectively-Propositional Reasoning for Rust](https://doi.org/10.1145/3814987.3814991): Ravencheck keeps verification conditions in an effectively propositional fragment so solver outcomes are predictable, a design alternative to Verus rather than a Verus feature.
- [A Rust-to-Lean Verification Pipeline with AI Provers: An Experience Report](http://arxiv.org/abs/2605.30106v2): Rust to Lean via Charon and Aeneas, with math specs proved manually or by AI provers; AI closed 2 of 6 theorems on one case, 4 were left as sorry, and the sample is small.
- [Rusty Variation: Deadlock-free Sessions with Failure in Rust](https://doi.org/10.4204/EPTCS.304.4): Rusty Variation encodes session types in Rust with failure, aiming at deadlock freedom; a mechanized proof of the Rust implementation remains future work.
- [Formal account of ghost snapshots in a verification tool for Rust](https://doi.org/10.5281/zenodo.20425557): Creusot ghost snapshots are unsound with prophecy-based mutable borrows unless restricted, and a Rocq model proves the restricted version sound.
- [Cocoon: Static Information Flow Control in Rust](https://doi.org/10.1145/3649817): Cocoon enforces noninterference via Rust types and procedural macros as an effect system, with no declassification and no correctness proof.
- [Solving VeriContest with a Lean-Backed Rust Verifier](https://arxiv.org/abs/2610.03994): Rust-Prover translates safe Rust via Aeneas into Lean, turning each Verus-style #[spec] function into a theorem solved by fixed tactics and agents.
- [SquirrelFS: Using the Rust Compiler to Check File-System Crash Consistency](https://arxiv.org/abs/2406.09649): Rust typestate can check file-system persistence ordering at compile time but not functional correctness, and a wrong-address flush slipped through because transition bodies are unverified.
- [Generic Refinement Types](https://doi.org/10.1145/3704885): Generic refinement types parameterize contracts by predicates while keeping SMT checking decidable; implemented in Flux, with predicate parameters solved by Horn clauses that must occur positively.
- [Lessons Learned So Far From a Community Effort to Verify the Rust Standard Library (work-in-progress)](https://arxiv.org/abs/2510.01072): The Verify-std effort found no confirmed safety bugs, and only 361 of 9,078 unsafe core functions have Kani contracts, so annotated does not mean verified.
- [Linear Types for Large-Scale Systems Verification](https://doi.org/10.1145/3527313): Linear Dafny uses linear types to drop common-case alias reasoning while SMT handles the rest; 91% of the VeriBetrKV implementation is linear, with 28% fewer proof lines.
- [Translating C To Rust: Lessons from a User Study](http://arxiv.org/abs/2411.14174v2): In a user study of C-to-safe-Rust translation, 31 of 33 students' translations compiled, but none was equivalent to the C code under fuzzing (68% of tests differ on average).
- [VARIES: Verification Harness Synthesis and Efficient Scheduling for Unsoundness Detection in Rust Libraries](https://doi.org/10.1145/3832783.3837450): An API dependency graph seeds bounded Kani harnesses for public safe Rust APIs that wrap unsafe code, finding state-dependent unsoundness that single-call seeds miss.
- [Automatic Linear Resource Bound Analysis for Rust via Prophecy Potentials](https://arxiv.org/abs/2502.19810): RaRust infers linear resource bounds for well-typed Rust using prophecy potentials, with a soundness theorem against a borrow-calculus model.
- [Towards Practical, End-to-End Formally Verified X.509 Certificate Validators with Verdict](https://www.usenix.org/conference/usenixsecurity25/presentation/lin-zhengyao): A Rust and Verus X.509 validator has about 13k verified lines, and 79% of the unverified part needs no trust, with requires and ensures spec/exec refinement as the core pattern.
- [Integrating Rules and Semantics for LLM-Based C-to-Rust Translation](http://arxiv.org/abs/2508.06926v1): Rule-augmented retrieval, structured summarization and error-driven repair for C-to-Rust translation, evaluated on 515 xCodeEval samples and 100 HW-Bench functions.
- [Towards Reliable C-to-Rust Translation with Rule-Guided Reasoning and Reinforcement Learning](http://arxiv.org/abs/2607.19966v1): TRAVEL combines rule-guided MCTS with RL rewards for reasoning quality and test feedback to improve C-to-Rust semantic fidelity.
- [RustHorn: CHC-based Verification for Rust Programs](https://doi.org/10.1145/3462205): RustHorn reduces Rust to CHCs by modeling each mutable reference as current and final values, with no memory model; the proof covers only the core calculus, not the MIR prototype.
- [RustHornBelt: a semantic foundation for functional verification of Rust programs with unsafe code](https://doi.org/10.1145/3519939.3523704): RustHornBelt machine-checks the soundness of prophecy-based mutable borrows, where a borrow is (current, prophesied final), but it is not an automated verifier.
- [Pure Borrow: Linear Haskell Meets Rust-Style Borrowing](http://arxiv.org/abs/2604.15290v4): Pure Borrow adds Rust-style borrowing to Linear Haskell; two central metatheory properties remain conjectures.
- [A Study of Undefined Behavior Across Foreign Function Boundaries in Rust Libraries](http://arxiv.org/abs/2404.11671v8): Jointly interpreting Rust MIR and LLVM IR found 46 undefined-behavior bugs in 37 crates across FFI boundaries, showing that plain Miri misses UB triggered in foreign code.
- [Enabling Memory Safety of C Programs using LLMs](https://arxiv.org/abs/2404.01096): Dependency-ordered bottom-up rewriting of C into Checked C lets each prompt carry only direct dependencies and earlier interface edits.
- [Safety and Security Critical Systems with Rust](https://doi.org/10.1007/s11265-026-02011-x): Rust's guarantees hold only within safe code and a correct toolchain; certification still needs process evidence and qualified libraries.
- [C2SaferRust: Transforming C Projects into Safer Rust with NeuroSymbolic Techniques](https://arxiv.org/abs/2501.14257v2): C2SaferRust uses c2rust for compilable unsafe Rust, then has an LLM rewrite units of at most 150 lines in reverse topological order, beating no-chunking and random order in 9 of 15 settings.
- [Thrust: A Prophecy-Based Refinement Type System for Rust](https://doi.org/10.1145/3729333): Thrust verifies safe Rust with refinement types, prophecy variables, and CHC solving, and since two &mut references never alias, writes through the selected one update precisely, which Flux cannot do.
- [RustSFQ: A Domain-Specific Language for SFQ Circuit Design](https://arxiv.org/abs/2502.11848): RustSFQ uses Rust ownership so each SFQ wire is consumed exactly once, and the compiler rejects multi-receiver wires.
- [TRACTOR Benchmark for Evaluating C to Rust Translators](http://arxiv.org/abs/2609.25121v1): TRACTOR's correctness check is test-vector equivalence against the clang-compiled C binary, not a proof, and no translator results are reported.
- [sigma-rs: A Modular Approach for Keyed-Verification Anonymous Credentials](https://www.usenix.org/conference/usenixsecurity26/presentation/orru): SIGMA-RS is a four-crate Rust stack for keyed-verification anonymous credentials that enforces misuse resistance through types and prover-state discipline.
- [Oxide: The Essence of Rust](https://arxiv.org/abs/1903.00982v4): Oxide formalizes Rust's borrow checker as a substructural type system where ownership is use-once and a unique use conflicts with any overlapping loan.
- [ACE: Towards A High-Assurance Isolated Virtualization Environment for RISC-V](https://arxiv.org/abs/2505.12995v2): ACE is a Rust RISC-V security manager designed for verification; only page management is verified so far, and a page token wraps unsafe allocation with exclusive region ownership.
- [Remonter les barrières pour ouvrir une clôture: Inférence de spécification des clôtures pour la preuve de programmes Rust avec COMA](https://inria.hal.science/hal-04859517v1): Creusot infers closure pre- and postconditions from closure bodies using a coma barrier that separates interface from implementation, so short closures need no barrier and no user contract.
- [A Lightweight Formalism for Reference Lifetimes and Borrowing in Rust](https://doi.org/10.1145/3443420): FR is a small flow-sensitive calculus for Rust borrowing with a handwritten soundness proof; it covers lexical lifetimes only, with no unsafe, no NLL, and no loops.
- [RustMC: Extending the GenMC stateless model checker to Rust](https://arxiv.org/abs/2502.06293v1): RustMC explores concurrent Rust executions via GenMC and finds races and assertion violations in modeled executions, not deductive proofs of contracts.
- [Place Capability Graphs: A General-Purpose Model of Rust's Ownership and Borrowing Guarantees](https://doi.org/10.1145/3763122): Place capability graphs model Rust ownership and borrowing from MIR and borrow-checker results with capability nodes, modeling accepted programs rather than replacing the borrow checker.
- [Programming with permissions in Mezzo](https://doi.org/10.1145/2500365.2500598): Mezzo's duplicable and affine permissions track aliasing and ownership, ruling out representation exposure and data races in an ML-style language.
- [Ownership in low-level intermediate representation](https://arxiv.org/abs/2408.04043v3): OSEA-IR keeps selected Rust ownership facts in a low-level IR by adding per-address borrow stacks, so verification conditions avoid the cost of a full address map.
- Alerus: verifying probabilistic Rust with error credits: Alerus is a Verus library for probability bounds using error credits as ghost permission for bounded failure; two trusted axioms, Err-Rand-Exp and Err-Thin-Air, carry the reasoning.
- [Secure Parsing and Serializing with Separation Logic Applied to CBOR, CDDL, and COSE](https://arxiv.org/abs/2505.17335v2): PulseParse builds verified parser and serializer combinators in F*/Pulse, and EverCBOR emits verified C and safe Rust for CBOR and COSE.
- [Characterizing Unsafe Code Encapsulation In Real-world Rust Systems](http://arxiv.org/abs/2406.07936v1): Interior unsafe is sound only if the safe wrapper validates inputs, constructors, and global state; the compiler cannot establish this.
- [Annotating and Auditing the Safety Properties of Unsafe Rust](https://arxiv.org/abs/2504.21312v2): A safety-tool audit of Rust std covers 96.1% of 516 public unsafe APIs with parameterized safety tags, and 27 APIs received 61 fixes, all merged.
- [Reasoning about Interior Mutability in Rust using Library-Defined Capabilities](https://arxiv.org/abs/2405.08372): Library-defined capabilities let clients reason about UnsafeCell APIs without unsound framing; the trusted annotations are assumed, not checked.
- Refactoring and Equivalence in Rust: Expanding the REM Toolchain with a Novel Approach to Automated Equivalence Proofs: REM2.0 extracts methods in Rust and checks equivalence via Charon, Aeneas, and Coq; 33 of 40 advanced-feature cases compile after extraction.
- [Resource Specifications for Resource-Manipulating Programs](https://arxiv.org/abs/2304.12530v2): Resource specs in Prusti build conservation in and transfer resources across frames by pre and postconditions, replacing frame-heavy state specs for asset-moving code.
- [A Practical Analysis of Rust's Concurrency Story](http://arxiv.org/abs/1904.12210v1): A Rust concurrent hashmap study shows which type-system mechanisms prevent data races and where unsafe code is needed; it has no formal verification.
- [From C to Idiomatic Rust: A Ship-of-Theseus Agentic Translation](http://arxiv.org/abs/2607.28835v2): A Ship-of-Theseus translation runs c2rust first and then rewrites one function at a time, using compiled tests as a behavioral oracle, not as a proof of semantic equivalence.
- Scaling Verification of Cryptographic Software with Aeneas, Rust, and Lean: SymCrypt case study: 16.7 KLOC of Rust verified via Aeneas into 237,160 lines of Lean; AI-written proofs are untrusted because Lean checks them, and side channels are out of scope.
- [SmartC2Rust: Iterative, Feedback-Driven C-to-Rust Translation via Large Language Models for Safety and Equivalence](http://arxiv.org/abs/2409.10506v3): SmartC2Rust segments C at logical-block boundaries, translates with carried metadata, and repairs from compiler and test feedback until its self-check flags pass; default model is Claude 3.7 Sonnet.
- [Search-Based Multi-Trajectory Refinement for Safe C-to-Rust Translation with Large Language Models](http://arxiv.org/abs/2505.15858v3): LAC2R refines C2Rust output with MCTS over LLM rewrite trajectories, accepting candidates only if they compile and pass a fixed test suite, which checks equivalence only on those tests.
- [Rust’s Type Checker Implementation Is Unsound: An Empirical Study on Soundness Bugs in rustc](http://arxiv.org/abs/2608.28713v1): An empirical study finds 30 soundness bugs where rustc accepts programs it should reject, across lifetimes, traits, and type inference.
- [OwlC: Compiling Security Protocols to Verified, Secure, High-Performance Libraries](https://www.usenix.org/conference/usenixsecurity25/presentation/singh): OwlC's trusted spec compiler emits a Verus spec from interaction trees, and an untrusted implementation compiler emits Rust that Verus verifies against it.
- [Sound Borrow-Checking for Rust via Symbolic Semantics](https://doi.org/10.1145/3674640): Proves LLBC and its symbolic abstraction LLBC# sound against a heap language by composing simulations LLBC#, LLBC, HLPL, PL.
- [Sound Borrow-Checking for Rust via Symbolic Semantics (Long Version)](https://arxiv.org/abs/2404.02680v2): Aeneas's LLBC symbolic semantics acts as a sound borrow checker, proved by forward simulation through LLBC# to LLBC to PL with a sound join for branches and loops.
- [Automating Deductive Verification for Weak-Memory Programs (extended version)](https://arxiv.org/abs/1703.06368): Encodes C11 weak-memory logics (RSL, FSL, FSL++) into Viper, enabling unbounded verification where the user writes only program-logic specifications.
- [Prusti: Deductive Verification for Rust (Keynote)](https://doi.org/10.1145/3427761.3432348): Prusti verifies Rust functional correctness from Rust's type information plus user specs, without a separate program logic.
- [Anvil: Verifying Liveness of Cluster Management Controllers](https://www.usenix.org/conference/osdi24/presentation/sun-xudong): Anvil verifies liveness of Kubernetes controllers in Verus: once desired state stops changing, the cluster eventually matches it, and the controller model is proved, not trusted.
- [Surveying the Rust Verification Landscape](https://arxiv.org/abs/2410.01981): Proposes verifying safety properties of the Rust standard library and compares tools and human factors.
- [PropProof: Free Model-Checking Harnesses from PBT](https://doi.org/10.1145/3611643.3613863): PropProof turns Rust proptest harnesses into Kani harnesses with no code changes; it found 2 defects in AWS PROST, including an i64::MIN overflow that random testing misses.
- [Crust: A Bounded Verifier for Rust (N)](https://www.semanticscholar.org/paper/4f23104f00d382cf20184f5f1c14bf959d2b2f6b): Crust bounds-checks unsafe Rust libraries by translating to C and checking with CBMC over synthesized bounded call sequences, a bounded guarantee rather than unbounded safety.
- [ConSORT: Context- and Flow-Sensitive Ownership Refinement Types for Imperative Programs](https://arxiv.org/abs/2002.07770): ConSORT uses fractional ownership refinement types so a unique reference allows precise strong updates while aliases are restricted to top refinement, avoiding allocation-site summaries.
- [Towards verifying unsafe Rust programs against Rust’s pointer-aliasing restrictions](https://arxiv.org/abs/2603.28326v1): Work in progress claims RefinedRust, Verus, and Gillian-Rust ignore aliasing rules and are unsound; this is the authors' claim, not independently assessed.
- [Tunable Automation in Automated Program Verification](https://arxiv.org/abs/2512.03926v1): Verus broadcast groups let library authors ship automation levels that users tune per module or proof block; this is not a soundness result, and imported lemmas still need proved bodies.
- [Verifying the Rust Standard Library](https://doi.org/10.1007/978-3-032-28079-4_19): A community challenge program with 29 challenges and 450+ PRs found no single tool discharges all VCs and found no new memory-safety vulnerability in the Rust standard library.
- Verus linear ghost types: ownership as a proof mechanism: Verus treats the Rust borrow checker as trusted and does not run Z3 when Rust rejects aliasing, so error diagnostics should be staged by type, mode, and precondition.
- Verus systems foundation: proof architecture, automation, and realistic limits: Verus for systems code works best with small obligations, a view function from concrete structure to abstract sequence, pure spec functions, and narrow triggers diagnosed before raising timeouts.
- VerusBelt: sound proof types and the limits of Verus's foundation: VerusBelt is a semantic soundness proof for a significant Verus subset in Iris and Rocq, but its link to Verus's actual translation is manual, not proved.
- [Reducing the Costs of Proof Synthesis on Rust Systems by Scaling Up a Seed Training Set](https://arxiv.org/abs/2602.04910): VeruSyn fine-tunes on 6.9M synthetic verified Verus programs (5.7M direct, 1.2M after debugging); self-synthesis stops when 95% of recent programs are duplicates.
- [KRust: A Formal Executable Semantics of Rust](http://arxiv.org/abs/1804.10806v1): An executable K semantics of a Rust subset generates an interpreter, debugger, and verifier from one definition, covering ownership and borrows but not closures, concurrency, or unsafe code.
- [UnsafeCop: Towards Memory Safety for Real-World Unsafe Rust Code with Practical Bounded Model Checking](https://doi.org/10.1007/978-3-031-71177-0_19): Reusing unit tests as Kani harnesses and adding 21 new ones covered 89 of 110 public functions reaching unsafe code in about 23 person-hours, though this is bounded checking, not proof.
- [HarnessLLM: Rust Verification Harness Generation with Large Language Models](http://arxiv.org/abs/2607.22161v1): HarnessLLM generates Kani harnesses for Rust functions with unsafe blocks or panics from existing tests; 294 of 294 are valid, and Kani found 6 memory-safety issues in pdf-rs, but it is bounded, not deductive.
- [RustCompCert: A Verified and Verifying Compiler for a Sequential Subset of Rust](http://arxiv.org/abs/2602.07455v1): RustCompCert is a verified frontend from Rustlight to Clight plus the CompCert backend, with an unverified parser; it is ongoing work.
- [Memory-Safety Challenge Considered Solved? An In-Depth Study with All Rust CVEs](https://arxiv.org/abs/2003.03296): All Rust memory-safety CVE bugs except one compiler bug need unsafe code, and 52 come from unsound generic or trait code, so verification must specify unsafe libraries and FFI.
- [VERT: Verified Equivalent Rust Transpilation with Large Language Models as Few-Shot Learners](https://arxiv.org/abs/2404.18852v2): VERT uses a trusted Wasm-to-Rust reference transpilation as an oracle to check LLM-produced safe Rust translations.
- [GhostCell: separating permissions from data in Rust](https://doi.org/10.1145/3473597): GhostCell separates permission from data with a brand lifetime and token, enabling safe Rust structures with internal sharing; soundness is proved by extending RustBelt.
- [UnsafeChecker: Finding Soundness Bugs in Rust Safe Abstractions](http://arxiv.org/abs/2609.09641v1): UnsafeChecker uses abstract interpretation over MIR to find soundness bugs in Rust safe abstractions, detecting 32 of 46 RustSec CVEs, as scoped bug finding, not a soundness theorem.
- [Fuzz Driver Synthesis for Rust Generic APIs](http://arxiv.org/abs/2312.10676v2): Synthesizes Rust fuzz drivers by choosing concrete type arguments for generic APIs; 23 bugs found across 29 libraries, 18 of them related to generic APIs.
- [Ownership guided C to Rust translation](https://arxiv.org/abs/2303.10515): Crown retypes c2rust raw pointers into safe Rust by solving ownership-monotonicity constraints with SAT, avoiding full alias analysis but rejecting some schemes rustc accepts.
- [Broadly Enabling KLEE to Effortlessly Find Unrecoverable Errors in Rust](https://doi.org/10.1145/3639477.3639714): PanicCheck wraps Rust verification tools and KLEE to find unrecoverable errors without manually written harnesses.
- [Petri Nets-based Methods on Automatically Detecting for Concurrency Bugs in Rust Programs](https://doi.org/10.1145/3849803): Program Petri nets model Rust concurrency through MIR to detect deadlock, data race, and atomicity patterns, with soundness claimed only for a defined subset.
- [Two Birds One Stone: Effective Static Detection of Resource and Communication Deadlocks in Rust Programs](https://arxiv.org/abs/2401.01114v3): RcChecker statically detects Rust resource and condition-variable deadlocks via a signal-lock graph; Verus could specify the graph, but MIR analysis needs its own proof.
- [Asterinas: A Linux ABI-Compatible, Rust-Based Framekernel OS with a Small and Sound TCB](https://arxiv.org/abs/2506.03876v1): Asterinas Rust OS separates unsafe framework code from safe services; its memory-safety TCB is about 14 percent of the codebase.
- [Fine-Tuning Qwen3-27B for C-to-Rust Code Translation: A Three-Stage Curriculum of Pretraining, Debugging-Aware SFT, and Task-Specific SFT](http://arxiv.org/abs/2608.13681v1): Qwen3-27B C-to-Rust in three stages, including SFT on verifier-error repairs that change only proof annotations; 87.2% success, but no ablation isolates any stage.
- [VeriSMo: A Verified Security Module for Confidential VMs](https://www.usenix.org/conference/osdi24/presentation/zhou): VeriSMo is a Verus-verified Rust security module on AMD SEV-SNP with two proof layers: a machine model for a hostile hypervisor and an implementation layer using ownership and tracked permissions.
- [SACTOR: LLM-Driven Correct and Idiomatic C to Rust Translation with Static Analysis and FFI-Based Verification](http://arxiv.org/abs/2503.12511v3): Validates C-to-Rust output by linking it into the original C build via FFI and running end-to-end tests, which is testing-based soft equivalence.
