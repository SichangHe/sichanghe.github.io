# Specification generation and quality

(authored by agents unless marked 🧑)

- [3DGen: AI-Assisted Generation of Provably Correct Binary Format Parsers](https://arxiv.org/abs/2404.10362): An LLM writes a short checkable 3D DSL instead of C, EverParse compiles it to verified C, and the parser proof is reused rather than generated per protocol.
- [A Specification Logic for Programs in the Probabilistic Guarded Command Language (Extended Version)](https://arxiv.org/abs/2205.04822): Defines probabilistic dynamic logic for pGCL programs as a specification language; the proof system it aims at is future work, not delivered.
- [A Tale of 1001 LoC: Potential Runtime Error-Guided Specification Synthesis for Verifying Large-Scale Programs](https://arxiv.org/abs/2512.24594): Preguss has an LLM write ACSL contracts and loop annotations until Frama-C/WP proves every analyzer-reported runtime error impossible, so each alarm becomes the verification goal.
- [Practical Range Refinement Types with Inference](https://arxiv.org/abs/2607.00824): Range refinement types are inferred by backward dataflow, and a forward checker validates each candidate, so an unsound guess is harmless; the Verus analogue is candidate invariants checked by the proof checker.
- [LLM Assisted Coding with Metamorphic Specification Mutation Agent](https://arxiv.org/abs/2511.18249): CodeMetaAgent uses metamorphic relations inside the generation loop to mutate specs and tests, improving consistency; it diversifies tests rather than formally verifying code.
- [The CAISAR Platform: Extending the Reach of Machine Learning Specification and Verification](http://arxiv.org/abs/2506.12084v2): CAISAR lets users write high-level ML model properties in Why3 and dispatches them to several robustness verifiers, narrowing the spec-to-check embedding gap.
- [Hermes: Unlocking Security Analysis of Cellular Network Protocols by Synthesizing Finite State Machines from Natural Language Specifications](https://www.usenix.org/conference/usenixsecurity24/presentation/al-ishtiaq): Synthesizes communicating FSMs from 4G/5G natural-language standards, model-checks them, and finds 3 new vulnerabilities; extraction reaches 81-87% accuracy against gold FSMs.
- [AlphaVerus: Bootstrapping Formally Verified Code Generation through Self-Improving Translation and Treefinement](https://arxiv.org/abs/2412.06176): A verifier only guarantees that code meets the supplied spec, and assume(false) passes Verus, so the spec and its critique remain the trusted part.
- [Specifying a Realistic File System](https://doi.org/10.4204/EPTCS.196.1): AFS specifies a flash file system as a nondeterministic monad whose choice is a union of outcomes; the Verus analogue is a ghost spec function returning the set of allowed outcomes.
- [Contract Based Verification of Non-functional Requirements for Embedded Automotive C Code](https://arxiv.org/abs/2605.21532v2): Makes the module interface a checked artifact (entry functions, entry order, permitted external calls), motivated by untrusted subcontractor or LLM code; 6 principles become 17 rules.
- [Faults in Our Formal Benchmarking: Dataset Defects and Evaluation Failures in Lean Theorem Proving](https://arxiv.org/abs/2606.29493): A checked proof certifies only the formal statement the kernel received, and benchmark formalization faults such as omitted hypotheses are a larger risk than proof errors.
- [An Empirical Evaluation of Pre-trained Large Language Models for Repairing Declarative Formal Specifications](https://arxiv.org/abs/2404.11050v2): LLM repair of faulty Alloy specs was checked by the Alloy Analyzer, and a dual-agent variant turns analyzer reports into at most two sentences of repair advice.
- [An Empirical Study of LLM-Generated Specifications for VeriFast](https://arxiv.org/abs/2606.26490v1): LLM-written VeriFast auxiliary specs preserve behavior in over 91% of outputs but verify only 31.4% (855 of 2,727), with Gemini 2.5 Pro best at 39.7%.
- [ANCORA: Learning to Question via Manifold-Anchored Self-Play](https://arxiv.org/abs/2604.27644v2): One policy plays spec proposer and implementer, rewarded only by the Verus verdict; sparse valid outputs collapse plain RL, and iterative SFT on verified rollouts lifts Dafny2Verus pass@1 from 0.4% to 26.6%.
- [Weakening Goals in Logical Specifications](http://arxiv.org/abs/2510.15718v1): Counterexample-guided weakening finds a property between the desired and critical specs when a change breaks verification; demonstrated on propositional logic only.
- [LASA: Enhancing SoC Security Verification with LLM-Aided Property Generation](http://arxiv.org/abs/2506.17865v1): GPT-4o generates SoC security properties and SVAs refined by JasperGold feedback and a vacuity screen, but the paper reports no classification error rate and no RAG ablation.
- [Aria: An Agent For Retrieval and Iterative Auto-Formalization via Dependency Graph](http://arxiv.org/abs/2510.04520v2): Aria auto-formalizes math statements into Lean and counts success only if they compile and pass semantic approval, so faithfulness of the statement is the bottleneck.
- [Assured Automatic Programming via Large Language Models](https://arxiv.org/abs/2410.18494v2): Program-proof co-evolution repairs (code, spec, test) tuples from one NL intent, splitting facts into hard and soft intent, with the verifier checking every candidate.
- [Autoformalization with Large Language Models](https://arxiv.org/abs/2205.12615): Codex autoformalizes 25.3% of sampled competition math perfectly, and missing relevant prompt examples made it invent nonexistent syntax.
- [Automatic Generation of Formal Specification and Verification Annotations Using LLMs and Test Oracles](https://arxiv.org/abs/2601.12845v1): An LLM adds Dafny annotations to unchanged code and verifies 108 of 110 tasks, with static test asserts as spec oracles, but the result shows Dafny satisfaction, not requirement completeness.
- [SpecPylot: Python Specification Generation with Large Language Models](https://doi.org/10.1145/3803437.3806427): An LLM writes icontract specs and CrossHair checks them; only a REFUTED result with a concrete counterexample drives refinement, and PASSED is not a proof.
- [From Helpful to Trustworthy: LLM Agents for Pair Programming](https://doi.org/10.1145/3803437.3804875): Preliminary AutoReSpec (72 programs) and AutoJML (120 programs) results; trust should come from external evidence, with the developer confirming the spec matches intent.
- [AssertionForge: Enhancing Formal Verification Assertion Generation with Structured Representation of Specifications and RTL](https://arxiv.org/abs/2503.19174): Builds a knowledge graph from a hardware spec and parsed RTL, then has an LLM write SystemVerilog assertions that Cadence Jasper checks.
- [VeriScale: Adversarial Test-Suite Scaling for Verifiable Code Generation](https://arxiv.org/abs/2605.22368): Adversarial test expansion shows sparse tests overestimate LLM verifiable code generation: on Verina Plus, gpt-5.5's code score falls from 96.83 to 86.24 and its spec score from 68.78 to 44.44.
- [Improving Dynamic Specification Inference with LLM-Generated Counterexamples](https://arxiv.org/abs/2604.10761): LLM-written counterexample tests attack dynamically inferred Java postconditions, raising precision from 67.83% to 74.17% while recall stays at 54.57%.
- [Fulminate: Testing CN Separation-Logic Specifications in C](https://doi.org/10.1145/3704879): Syntactic restrictions that make CN separation-logic specs provable also make them executable, so one spec serves both runtime testing and static proof.
- [LLMs as verification oracles for Solidity](http://arxiv.org/abs/2509.19153v2): GPT-5 classifies natural-language Solidity properties with 92% accuracy and F1 on 667 tasks, with no unknown answers and counterexample transactions for bugs.
- [Working Document - Formalising Software Requirements with Large Language Models](https://arxiv.org/abs/2506.14627v2): A verified contract proves only the requirement as encoded, so a human must confirm the contract matches intent, and a review of 94 papers catalogs the field.
- [Leveraging LLMs for Formal Software Requirements: Challenges and Prospects](https://www.semanticscholar.org/paper/ca89f3d1febfe099bc396707f3e2b168c1556576): Small, well-scoped assertions verify more reliably than full contracts, so an LLM should first generate small ensures or assert clauses and let verifier feedback drive refinement.
- [Beyond Postconditions: Can Large Language Models infer Formal Contracts for Automatic Software Verification?](https://arxiv.org/abs/2510.12702v1): LLMs can infer preconditions as well as postconditions from docstrings, since postcondition-only specs admit invalid inputs and cause false alarms.
- [Can LLMs Write Correct TLA+ Specifications? Evaluating Natural-Language-to-TLA+ Generation](https://arxiv.org/abs/2606.05792): Open-weight LLMs rarely write TLA+ that passes TLC; the best open strategy passes only 8.6% of runs, and few-shot wins mainly on parsing.
- [TLA+-Bench: An Execution-Grounded Benchmark and Dataset for Natural-Language to TLA+ Specification Generation](https://arxiv.org/abs/2607.23425): Execution-grounded TLA+ benchmark: a mutation probe replacing the safety invariant with TRUE shows many TLC-passing outputs are not substantive, so pass rates overcount.
- [Formalizing and validating properties in Asmeta with Large Language Models (Extended Abstract)](http://arxiv.org/abs/2603.15375v1): A feasibility demo shows an LLM can help turn informal requirements into Asmeta temporal properties checked via NuSMV; there is no integrated system or evaluation.
- [Automated Repair of Unrealisable LTL Specifications Guided by Model Counting](https://doi.org/10.1145/3583131.3590454): AuRUS repairs unrealisable LTL assume-guarantee specs by changing assumptions and guarantees, scored by similarity; it repaired all benchmark specs.
- [Natural Language to First-Order Logic LLM-based Autoformalization](https://arxiv.org/abs/2610.12030v1): Ontology quality for NL-to-FOL autoformalization is unmeasured, and one sentence admits several formulas with different commitments, so intended meanings must be fixed before judging faithfulness.
- [Towards Trace-based Deductive Verification (Tech Report)](http://arxiv.org/abs/2211.09487v2): Trace contracts specify events and intermediate states that pre/postconditions cannot, with a soundness-proved symbolic-execution calculus for recursive procedures.
- [From Informal to Formal – Incorporating and Evaluating LLMs on Natural Language Requirements to Verifiable Formal Proofs](https://arxiv.org/abs/2501.16207): Full proof generation from NL requirements reached 7.7% pass@1, while proof completion reached 18.3%, so partial-artifact tasks are easier than whole ones.
- [Deductive Verification of Smart Contracts with Dafny](http://arxiv.org/abs/2208.02920v1): Carry a global invariant in every method's requires and ensures so the verifier checks it across any call sequence; no Dafny-to-EVM compiler exists, so the EVM step is assumed.
- [Mitigating hallucinations and omissions in LLMs for invertible problems: An application to hardware logic design automation](https://arxiv.org/abs/2512.03053): Round-trip check: a human spec is encoded to Verilog by one LLM, decoded back by a different LLM, and compared, which exposes forward, inverse, or spec errors but cannot catch matching wrong specs.
- [FormalSpecCpp: A Dataset of C++ Formal Specifications created using LLMs](https://arxiv.org/abs/2502.15217): C++ specification dataset made by LLM-translating verified Dafny programs to C++; testing and partial review do not establish semantic equivalence.
- [BODHI: Precise OS Kernel Specification Inference](https://arxiv.org/abs/2605.23931): A 519-line C-to-Python translation guide lifts Pass@1 by 11.0 to 31.8 points across nine models for LLM kernel-spec inference, though results come from one greedy run.
- [SpecLoop: An Agentic RTL-to-Specification Framework with Formal Verification Feedback Loop](https://arxiv.org/abs/2603.02895v1): SpecLoop writes RTL to prose spec, reconstructs RTL, and checks equivalence with Yosys EQY to bounded depth; a pass shows the spec is detailed enough, not complete or faithful.
- [NL2TL: Transforming Natural Languages to Temporal Logics using Large Language Models](https://arxiv.org/abs/2305.07766): Replacing concrete atomic propositions with placeholders lets an NL-to-STL model learn only logical structure, which transfers across domains with about 95-97% atomic-proposition accuracy.
- [Trusta: Reasoning about Assurance Cases with Formal Methods and Large Language Models](https://arxiv.org/abs/2309.12941): Trusta checks assurance cases with Z3 and MONA; machine-generated cases match human ones at only 50-80% similarity.
- [Enhancing LLM-based Specification Generation via Program Slicing and Logical Deletion](https://arxiv.org/abs/2509.09917v2): Generating ACSL specs per program slice, and deleting failing clauses before whole-function verification, avoids discarding correct clauses whose preconditions are not yet generated.
- [Beyond Basic Specifications? A Systematic Study of Logical Constructs in LLM-based Specification Generation](https://arxiv.org/abs/2602.00715): Repairing LLM-written ACSL specs from verifier diagnostics yields more verified programs but costs more runtime, tested on 49 Frama-C programs across six models.
- [CodeSpecBench: Benchmarking LLMs for Executable Behavioral Specification Generation](https://arxiv.org/abs/2604.12268): CodeSpecBench tests LLM-written executable pre/postconditions on 2,494 LeetCode tasks and 500 SWE-bench issues, scored by valid/invalid inputs and trigger/regression tests.
- [Judging Is Not Enumerating: Silent Omissions in LLM-Authored Acceptable Sets](http://arxiv.org/abs/2608.01000v1): When LLMs author an acceptable set rather than judge candidates, they mostly omit members, and the omissions resist audit.
- [Can Large Language Models Model Programs Formally?](https://arxiv.org/abs/2604.01851): TLC runnability and state similarity can score LLM-written TLA+ models of Python programs, but the oracle models are not proven to match their source programs.
- [Prove2Me: An Open Collaborative Platform for Scaling Math Formalization](http://arxiv.org/abs/2608.28433v2): The kernel certifies a proof of the stated statement, not that the statement is faithful; Prove2Me audits only headline goals, definitions, and milestone lemmas via blind read-back.
- [ReForm: Reflective Autoformalization with Prospective Bounded Sequence Optimization](http://arxiv.org/abs/2510.24592v3): Autoformalization is rewarded for a critique step only when the critique finds real semantic gaps, because compiling Lean statements alone allows unfaithful specs.
- [SpecFirst: Behavioral Specification Elicitation as a First-Class Step in Agent-Based Program Synthesis from Scratch](https://arxiv.org/abs/2607.27167): Having an agent probe a black-box binary and write a behavioral spec file before coding raised test pass rates by 6.9 to 21.3% relative across four models on ProgramBench.
- [ClarifySTL: An Interactive LLM Agent Framework for STL Transformation through Requirements Clarification](https://arxiv.org/abs/2605.01209): An agent asks users to clarify vague and ambiguous requirements before translating to STL, and its ambiguity detector reaches 91.0% F1.
- [Passing Proofs That Prove Nothing: Deciding Postcondition Vacuity, Precondition Satisfiability, and Contract Completeness for Rust and Kani](https://doi.org/10.5281/zenodo.21865170): A passing Kani proof can constrain nothing; postcondition vacuity is decided by havocing one arbitrary return value, and the check is mechanized in 20 Lean theorems.
- [Clover: Closed-Loop Verifiable Code Generation](https://arxiv.org/abs/2310.17807): Clover accepts a code, annotation, and docstring triple only if six pairwise checks pass, including regenerating code from the annotations to catch trivially weak specs.
- [Combining LLM Code Generation with Formal Specifications and Reactive Program Synthesis](https://arxiv.org/abs/2410.19736): Split code into formal reactive synthesis for control and LLM-filled data terms, which reaches 61.5% at 10 conditions where LLM-only reaches 0%, but the user must still check the spec.
- [Combining Mechanical and Agentic Specification Inference for Move](https://arxiv.org/abs/2605.10005): For Move specs, the agent should propose loop invariants before weakest-precondition runs, since weakest-precondition output first gave vacuous specs that misled the model.
- [Contract-Aware Rescue of a Drifted Isabelle Development: The Double-Tank Case Study](https://arxiv.org/abs/2608.18822): A successful build does not show the verification task was preserved, so LLM-proposed proof edits need protection of statements and definitions, not only a passing build.
- [FaithformBench: Benchmarking Faithfulness of Mathematical Chain-of-Thought Autoformalisation](https://arxiv.org/abs/2608.10916): Silent correction: an autoformalizer can turn x in R into x in N, making a false conclusion provable, so each formal step is tested with a perturbed invalid twin.
- [nl2spec: Interactively Translating Unstructured Natural Language to Temporal Logics with Large Language Models](https://doi.org/10.1007/978-3-031-37703-7_18): Translating natural language to temporal logic as user-editable fragment pairs lets users fix ambiguity locally, instead of rewriting the whole formula.
- [Local refinement typing](https://arxiv.org/abs/1706.08007): Fusion infers SMT-checked intermediate refinement types from exported signatures, reducing the annotations a programmer must write.
- [Towards Formal Verification of LLM-Generated Code from Natural Language Prompts](https://arxiv.org/abs/2507.13290v2): The verifier checks the LLM output against a user-reviewed formal query, and only the human can decide whether that query matches intent.
- [Can LLMs help find Ambiguities in Protocol Specifications?](https://arxiv.org/abs/2609.38752): An LLM reads protocol prose for ambiguity while a deterministic scaffold supplies coverage, using communicating finite state machines to define gaps and forks.
- [Contract Strengthening through Constrained Horn Clause Verification](https://doi.org/10.4204/EPTCS.373.3): Strengthen valid contracts with a CHC-based analysis so callers verify; Stainless times out on rev with the weak contracts and proves both after strengthening.
- [Reducing the Number of Annotations in a Verification-oriented Imperative Language](http://arxiv.org/abs/1011.3407v1): Pest is a verification-oriented language designed so programs verify more easily; students verified sorting and search with it, qualitatively, with no benchmark.
- [A framework for assessing the capabilities of code generation of constraint domain-specific languages with large language models](https://arxiv.org/abs/2603.05278): For OCL and Alloy generation, validate in stages so syntax is separated from semantics, since prompt-template comparisons were inconclusive.
- [Djinnlang: Higher-Level Programming by Unambiguous Specification with an LLM in the Compiler](https://arxiv.org/abs/2609.23954): Djinnlang requires constraints to determine the output uniquely, so the LLM must prove the relation is deterministic, not merely satisfiable.
- [Proving the Coding Interview: A Benchmark for Formally Verified Code Generation](https://doi.org/10.1109/llm4code66737.2025.00014): Lean theorem statements are filtered by unit tests and Plausible property testing, but these are filters, not proof that the statements are the intended specs.
- [FVSpec: Real-World Property-Based Tests as Lean Challenges](https://doi.org/10): Mining 7,413 property-based tests from 497 repos yields 2,623 Lean specs, but these tests may omit preconditions or encode bugs, so they are not ground truth.
- [Predicate Subtypes in VerCors](https://doi.org/10.4204/eptcs.444.6): VerCors rewrites predicate subtypes such as NonNull and Index(len) into ordinary contracts, but strict arithmetic checks can fail on intermediate subexpressions like (x-2)+2.
- [ModelForge: Using GenAI to Improve the Development of Security Protocols](https://arxiv.org/abs/2506.07010v1): ModelForge uses a fine-tuned LLM to translate natural-language protocol specs into CPSA input, so the CPSA model finder supplies the checking step.
- [Enchanting Program Specification Synthesis by Large Language Models Using Static Analysis and Program Verification](https://doi.org/10.1007/978-3-031-65630-9_16): AutoSpec has an LLM synthesize ACSL specs bottom-up over a call and loop graph, with Frama-C WP checking each round, and reports 199 of 251 tasks solved, but only for C.
- [Can Large Language Models Transform Natural Language Intent into Formal Method Postconditions?](https://doi.org/10.1145/3660791): GPT-4 writes postconditions from NL; plain true is correct but scores 0 on bug-completeness, so judge specs by how many mutants they reject, not by passing tests alone.
- [Fidelity Probes for Specification-Code Alignment](https://doi.org/10.1007/): An LLM answers behavior probes from the spec alone, compared with answers derived from code; disagreements split into contradictions and coverage gaps.
- [Evaluating LLM-driven User-Intent Formalization for Verification-Aware Languages](https://arxiv.org/abs/2406.09757): Test-as-Hoare-triple scores LLM postconditions, but it passes a vacuous ensures true, so completeness needs output mutation as a second metric.
- [Executable JavaScript as a Checkable Specification Language: A JS-SAM Case Study on SysMoBench](https://arxiv.org/abs/2607.13092v1): Executable model specs can pass syntax, bounded exploration, and invariant checks, yet replay only 21.4% to 89.3% of real spinlock trace windows, so trace conformance is the stronger test.
- [Characterizing Paraphrase-Induced Failures in Lean 4 Autoformalization](https://arxiv.org/abs/2604.23135): Meaning-preserving rewording changes autoformalizer output: frontier surface consistency is 19-50% on ProofNet#, and some rewrites change meaning, so rewrite rules need meaning-preservation references.
- [Scenic: a language for scenario specification and scene generation](https://doi.org/10.1145/3314221.3314633): Scenic is a probabilistic language for scenario specification that generates test sets and emphasizes hard cases for perception systems.
- [Agentic Specification Generator for Move Programs](https://arxiv.org/abs/2509.24515): Per-clause-class LLM agents with Move Prover feedback produced 300 of 357 verifiable specs, but 33% of generated clauses were absent from expert specs.
- [Fyan: A Human--AI Harness with Semantic Auditing for Document-Level Formalization](https://arxiv.org/abs/2609.39228): Fyan pairs slots of informal and formal statements and scores unpaired source slots as omissions, because a proof assistant checks the theorem, not its fidelity to the source.
- [Grammars of Formal Uncertainty: When to Trust LLMs in Automated Reasoning Tasks](http://arxiv.org/abs/2505.20047v1): Estimates a PCFG over many sampled SMT-LIB outputs; structural uncertainty decides when to accept, abstain, or review an LLM-generated artifact.
- [Herald: A Natural Language Annotated Lean 4 Dataset](http://arxiv.org/abs/2410.10878v2): Herald extracts theorem structure from Mathlib, generates NL-FL pairs, and validates them with the Lean compiler plus back-translation and NLI checks.
- [IronSpec: Increasing the Reliability of Formal Specifications](https://www.usenix.org/conference/osdi24/presentation/goldweber): A passing proof can hide a wrong spec, so an automatic sanity checker flags unconstrained inputs and outputs, and mutation testing tests the spec independently of the implementation.
- [Natural Language Specifications in Proof Assistants](https://arxiv.org/abs/2205.07811): A prototype parses a fragment of English into Coq propositions, letting a user write a natural-language spec as a proof goal.
- [Trustworthy Formal Natural Language Specifications](https://doi.org/10.1145/3622758.3622890): A categorial grammar in Lean 4 parses natural-language requirements into terms with inspectable certificates, guarding against mistranslated formal claims.
- [Specify What? Enhancing Neural Specification Synthesis by Symbolic Methods](https://arxiv.org/abs/2406.15540v2): Frama-C analysis output shapes LLM ACSL contracts: path examples give abstract postconditions, while EVA alarms give range preconditions that may just suppress alarms.
- [Seeking Specifications: The Case for Neuro-Symbolic Specification Synthesis](http://arxiv.org/abs/2504.21061v1): Feeding Frama-C symbolic outputs (PathCrawler, EVA) into DeepSeek-R1 prompts steers ACSL function-contract synthesis, a neuro-symbolic spec method.
- [ObSynth: An Interactive Synthesis System for Generating Object Models from Natural Language Specifications](https://doi.org/10.48550/arxiv.2210.11468): ObSynth turns a natural-language app description into an editable object model via few-shot GPT-3 prompts, keeping a human in the editing loop.
- [An Evaluation Benchmark for Autoformalization in Lean4](http://arxiv.org/abs/2406.06555v1): 101 formal/informal mathlib4 theorem pairs measure how GPT-3.5, GPT-4, and Gemini Pro autoformalize statements into Lean 4.
- [Autoformalizer with Tool Feedback](https://arxiv.org/abs/2510.06857v1): Autoformalizer with tool feedback runs a Lean syntax check first, then an LLM consistency judge ensemble; the judges ignore the proof, so a compiling and judged-consistent statement can still be wrong.
- [EquivSVA: A Formally Verified Dataset of Behavioral Assertions Across Equivalent RTL Implementations](https://doi.org/10.48550/arxiv.2609.26751): EquivSVA organizes assertion data by behavior family, with four equivalent RTL implementations each, to test whether generated SVA express behavior rather than one RTL.
- [Formal Specifications from Natural Language](https://arxiv.org/abs/2206.01962): A fine-tuned LM translates English into regex, FOL, and LTL, beating prior regex SOTA by 6 points; outputs are checked by comparison, not proven.
- [Neurosymbolic Auditing of Natural-Language Software Requirements](https://arxiv.org/abs/2605.13817): Formalizing NL requirements into one SMT model yields consistency, vacuity, violatability, and redundancy checks, which are review signals, not verdicts on the requirements.
- [Automated Repair of Declarative Software Specifications in the Era of Large Language Models](https://doi.org/10.48550/arxiv.2310.12425): One-shot ChatGPT repair of Alloy specs with no verifier feedback trails ARepair, ICEBAR, BeAFix, and ATR overall but fixes bugs no other tool fixes, and fix comments matter most.
- [A Type System for Extracting Functional Specifications from Memory-Safe Imperative Programs](https://doi.org/10.1145/3485512): Heapster extracts a pure functional spec from memory-safe C via permission types the user writes per function; loops need reachability hints, and array bounds checks become possible-error terms in the spec.
- [Beyond Code Generation: Assessing Code LLM Maturity with Postconditions](https://arxiv.org/abs/2407.14118): Postcondition generation on EvalPlus separates same failures from semantic equivalence, and metric denominators must stay separate: problems for some metrics, mutants for others.
- [CASP: An Evaluation Dataset for Formal Verification of C Code](https://doi.org/10.1007/978-3-032-07132-3_5): CASP offers 506 Frama-C-verified C-plus-ACSL pairs for spec-to-code evaluation, and regex mining only finds candidates; it cannot show a spec is valid.
- [Sage: Formalization with Semantic Correction](https://www.semanticscholar.org/paper/693e219a8682693cd7e72ec451de263764280429): Autoformalization must separate assertions from open questions, since encoding a question as a claim or an existential changes what the prover is asked to do.
- [Stratified Consistency Distillation for Natural Language Formalization](https://doi.org/10.5281/zenodo): Sampling translations, clustering them by Z3 equivalence, and training only on pseudo-labels chosen by semantic entropy distills a frontier NL-to-SMT translator into a 7B model.
- [SecGoal: A Benchmark for Extracting Formalizable Security Goals from Protocol Documents](https://www.semanticscholar.org/paper/70979bedd64af3c6462f69151a8da5cc2a972827): A benchmark of 391 security-goal statements and 131 formal properties from 15 protocol documents; the task is specification extraction, not proof.
- [Verifiable Auto-Formalization of Mathematics Using a Relaxed Natural Formal Language](https://www.semanticscholar.org/paper/11d48d4fd4027b057897318302f829c1757342b5): Relaxed NFL keeps natural math notation, elaborates it to Core NFL, and generates verification conditions; the evaluation measures only generation, not proof discharge.
- [Automatic Assertion Mining in Assertion-Based Verification: Techniques, Challenges, and Future Directions](http://arxiv.org/abs/2601.02248v1): A survey of hardware assertion miners warns they overgenerate, duplicate, conflict, and miss corner cases, so mined assertions must still be checked.
- [Spec2Vision: Contract-Guided Delivery of AI-Generated Computer Vision Pipelines](https://github.com/annony-ml-llm/Spec2Vision.git): Explicit CV task contracts with bounded repair reach 81/85 strict deliveries; removing compatibility scaffolding drops this to 58/85.
- [Automated formalisation of informal specifications by combining LLMs and grammar-based language processing](https://doi.org/10.1007/s10664-026-10914-3): An LLM rewrites Java requirements into grammar-compatible sentences, raising JML derivation coverage from 23% for grammar alone to over 90% of sentences.
- [Neuro Symbolic Reasoning for Planning: Counterexample Guided Inductive Synthesis using Large Language Models and Satisfiability Solving](https://arxiv.org/abs/2309.16436): CEGIS with an LLM learner and Z3 verifier, shown only on block-world planning; the paper has no theorems and no other experiment.
- [Multilingual Mathematical Autoformalization](http://arxiv.org/abs/2311.03755v2): Back-translating formal libraries into informal text and training on reversed pairs yields an autoformalizer, though only 16 to 18% of joint-model outputs were acceptable to two raters after minor correction.
- [Limits to Verification and Validation of Agentic Behavior](http://arxiv.org/abs/1604.06963v2): Defines a deontology as a set of Good histories and requires viability: after any Good history, some action keeps it Good.
- [Can Large Language Models Autoformalize Kinematics?](http://arxiv.org/abs/2509.21840v1): An LLM formalizes kinematics problems for KeYmaera X through a parser-feedback repair loop capped at three repairs, and the cap is not shown sufficient.
- [PolicyKG: An Agentic LLM Pipeline for Translating Institutional Policies into SHACL Knowledge Graphs](https://doi.org/10.1145/1143120.1143123): Agentic LLM stages extract policy text, classify deontic rules, formalize FOL, and deterministically emit SHACL-validated knowledge graphs under a fixed stage order.

- [Supporting Software Formal Verification with Large Language Models: An Experimental Study](https://arxiv.org/abs/2507.04857v1): SpecVerify has two LLM stages from requirement to C assertions checked by ESBMC; 46 of 58 generated properties matched manual ones (79.31%), and the pipeline ran without human review.
- [AUTO CEDAR: An Agentic Framework for Verifier-Guided Access Control Policy Synthesis](https://arxiv.org/abs/2607.03656): AUTO CEDAR fixes floors, ceilings, and liveness slices before any LLM policy search, and the model cannot edit them, so a synthesis theorem bounds accepted policies.
- [Kernel Contracts: A Specification Language for ML Kernel Correctness Across Heterogeneous Silicon](https://arxiv.org/abs/2604.22032): Kernel contracts state precision, shape, ordering, tolerance, and exceptional values, so disagreeing kernels are judged by the contracts they claim.
- [Advancing Natural Language Formalization to First Order Logic with Fine-tuned LLMs](https://arxiv.org/abs/2509.22338v2): Predicate extraction is the main NL-to-FOL bottleneck, since a gold predicate list raises exact match from 35.8% to 63.5% while a tokenizer extension gains under 1 point.
- [Auditing Framework APIs via Inferred App-side Security Specifications](https://www.usenix.org/conference/usenixsecurity23/presentation/vyas): Bluebird infers API sensitivity from app-side checks, combining NLP with static analysis of the calling apps.
- [First Experiments with Neural Translation of Informal to Formal Mathematics](https://arxiv.org/abs/1805.06502): Early seq2seq autoformalization reaches 65.73% exact match on Mizar pairs, but it measures string match, not proof checking, and its synthetic pairs come from a formal corpus.
- [KerSpecGen: Co-piloting formal Kernel specification synthesis with refined knowledge graphs and large language models](https://doi.org/10.1371/journal.pone.0338821): KerSpecGen generates Isabelle/HOL seL4 specs from requirements through a knowledge graph, but its output is never executed or verified, only scored by similarity and experts.
- [Preguss: It Analyzes, It Specifies, It Verifies](https://arxiv.org/abs/2508.14532): This position paper splits runtime-error verification into analysis, LLM spec synthesis, and deductive proof of units, but no implementation was evaluated.
- [FormalRx: Rectify and eXamine Semantic Failures in Autoformalization](http://arxiv.org/abs/2607.04655v1): FormalRx diagnoses autoformalization with an aligned flag, an error category, a location, and a corrected statement, from a 28-category taxonomy.
- [Know Your Limits : On the Faithfulness of LLMs as Solvers and Autoformalizers in Legal Reasoning](https://arxiv.org/abs/2606.16118): LLM legal reasoning is often unfaithful to the solver: scope laundering reports entailment where the solver gives neutral, in 15.3% to 52.5% of cases, so check results against the formal input.
- [When Specifications Conflict: A Symmetry-Based Framework for Measuring LLM Preferences](https://arxiv.org/abs/2607.28384): When a formal spec conflicts with an NL spec, LLMs follow the formal one at 87.45% and io examples are followed less, so formal artifacts dominate in prompts.
- [Automatic Generation of Specifications using Verification Tools](http://tuprints.ulb.tu-darmstadt.de/5910): Thesis: auto-generates loop invariants and method contracts for KeY via abstract interpretation with symbolic execution; widening forces termination, and the fixed point is sound by construction.
- [Hypothesis-Disciplined Multi-Agent Automated Formalization of Asymptotic Statistical Theory](https://arxiv.org/abs/2606.20642): Compiling does not show a theorem matches its source: an audit with verbatim quotes classifies each hypothesis as in-source, implied, or potential drift.
- [Model-Driven Discipline for Multi-Agent LLMs: Requirement-to-Verification Generation of Traceable System Models](https://doi.org/10.48550/arxiv.2607.16708): LLM agents gained syntactic validity from requirement models to checked behavior models, but execution gains were inconsistent across models, so syntax is the only robust win.
- [Towards Deriving Verification Properties](http://arxiv.org/abs/1903.04159v1): English tenets, a goal tree, and domain implications yield LTL properties for model checking; richer logics are harder to verify.
- [StepFun-Formalizer: Unlocking the Autoformalization Potential of LLMs Through Knowledge-Reasoning Fusion](https://doi.org/10.1609/aaai.v40i40.40691): Autoformalization training data was selected by Lean syntax checks and equivalence voting over 16 candidates, giving about 183K pairs with no reported human correctness check.
- [VIVERRA: Text-to-Code with Guarantees](https://www.semanticscholar.org/paper/9a9e8f60bbfed6802605efa0bd1d0ce28a411d46): VIVERRA has an LLM write C with assertions checked by bounded model checkers; the guarantee holds only up to loop bound k=5 and does not prove the program matches the task.
- [Doc2Spec: Synthesizing Formal Programming Specifications from Natural Language via Grammar Induction](https://doi.org/10.1145/3798217): Turning API documentation into formal specs through staged agents with deterministic checks, where removing any single stage dropped precision to 0.06 to 0.26, so every stage is necessary.
- [NL2AGBench: Benchmarking LLM Auto-Formalization for AlphaGeometry](https://arxiv.org/abs/2608.28481): Auto-formalization is judged by execution: AlphaGeometry must run and yield a valid spec, and 54 few-shot examples lift every model that scored above 0.
- [FMC: Formalization of Natural Language Mathematical Competition Problems](https://arxiv.org/abs/2507.11275v1): FMC is a training-free NL-to-Lean statement pipeline reaching 93.39% compile and 81.74% consistency after error-feedback retries, at a cost of 161M tokens.
- [Towards Automated Formal Verification of Backend Systems with LLMs](https://arxiv.org/abs/2506.10998): Scala backend to Lean needs the DB state as an explicit parameter, and a proof shows logic is correct only if translation and theorem statements preserve intent.
- [Reasoning without Gold Standards: A Proxy-Judge Theory of Autoformalization](http://arxiv.org/abs/2606.09449v1): A reference-free proxy judge checks a vector of per-axis properties and repairs the failed axis, with geometric convergence under bounded judge noise.
- [LLM-Assisted Formalization Enables Deterministic Detection of Statutory Inconsistency in the Internal Revenue Code](https://doi.org/10.1145/3594536.3595163): LLM formalizes a tax statute into Prolog while a deterministic engine detects inconsistency, separating probabilistic formalization from checking.
- [Verification-Guided Specification Synthesis with Large Language Models for Intrusion Detection Rules](http://arxiv.org/abs/2608.22889v1): An LLM proposes a Python predicate for each attack, and a deterministic compiler emits the IDS rule.
- [Lean Atlas: An Integrated Proof Environment for Scalable Human-AI Collaborative Formalization](https://arxiv.org/abs/2604.16347): Lean formalizations can type-check yet mean something else, such as an omitted annotation making 3 / 2 = 1.5 infer Nat, so the paper tracks human-verified declarations in a manifest.
- [Integrating Symbolic Execution with LLMs for Automated Generation of Program Specifications](https://arxiv.org/abs/2506.09550v4): SESpec combines symbolic execution, invariant templates, an LLM, and Frama-C to verify 354 of 395 C/ACSL programs, but solves 0 of 3 programs with external or recursive calls.
- [How Powerful Are LLMs in Generating Formal Program Specifications?](https://doi.org/10.48550/arxiv.2608.13077): COINS grades spec quality separately from proof difficulty: a candidate spec fails if a mutant is provably accepted, since positive proofs alone accept overly permissive specs.
- [Generating Precise Format Specification for Network Protocols Through Adversarial LLM Interactions](https://www.usenix.org/conference/usenixsecurity26/presentation/ye): Adversarial interaction between a format spec and a reference parser refines both to a fixed point, which is evidence of agreement, not proof.
- [Higher-Order Specifications for Deductive Synthesis of Programs with Pointers (Extended Version)](https://arxiv.org/abs/2407.09143): Pika functional specs translate to SuSLik, enabling push-button synthesis of C programs with in-place updates and full separation-logic proofs.
- [FormalMATH: Benchmarking Formal Mathematical Reasoning of Large Language Models](https://arxiv.org/abs/2505.02735): Compile-only statements survive at 92.4%, but a semantic check cuts them to 31.7%, so meaning filtering, not compilation, is the bottleneck.
- [Generating Symbolic World Models via Test-time Scaling of Large Language Models](https://arxiv.org/abs/2502.04728): LLMs generate PDDL domains with extra inference compute; VAL checks syntax and plan executability, not that the domain matches intent.
- [Mathesis: Towards Formal Theorem Proving from Natural Languages](https://arxiv.org/abs/2506.07047v1): Mathesis checks semantics separately from the proof, catching drift such as a desired conclusion added as an assumption, and its proof gate rejects vacuous statements.
- [VeriEquivBench: An Equivalence Score for Ground-Truth-Free Evaluation of Formally Verifiable Code](https://arxiv.org/abs/2510.06296): Scores generated Dafny code and specs in both directions, checking that the code satisfies the spec and that the spec's behaviors are realized, over 2,389 problems.
- [An Agile Formal Specification Language Design Based on K Framework](http://arxiv.org/abs/2404.18515v1): ASL is a YAML and K-syntax spec language compiled to K; fewer spec lines than K do not show that the spec expresses intent.
- [Automated Extraction of Protocol State Machines from 3GPP Specifications with Domain-Informed Prompts and LLM Ensembles](https://arxiv.org/abs/2510.14348): SpecGPT extracts protocol state machines from 3GPP specs with LLM ensembles; agreement with a reference does not prove true behavior.
- [DRIFT: Decompose, Retrieve, Illustrate, then Formalize Theorems](http://arxiv.org/abs/2510.10815v4): Decomposing a statement into concept queries with guessed Lean names, then retrieving premises, raised GPT-4.1's ConNF BEq+@10 from 6.76% zero-shot to 62.33%.
- [Beyond Gold Standards: Epistemic Ensemble of LLM Judges for Formal Mathematical Reasoning](https://arxiv.org/abs/2506.10903v2): Ensemble of LLM judges scores logical preservation, consistency, and formal quality of autoformalizations; theorem provers check validity, with no reference formalization.
- [KELPS: A Framework for Verified Multi-Language Autoformalization via Semantic-Syntactic Alignment](https://arxiv.org/abs/2507.08665): KELPS maps NL math to a Knowledge Equation IR of a=b assertions, then converts to Lean, Coq, or Isabelle using expert rules.
- [Beyond Compilation: Evaluating Faithful Natural-Language-to-Lean Statement Formalization](http://arxiv.org/abs/2606.31002v3): Compiling is not faithful: a full agent compiles 87.2% of 227 graduate statements but only 57.7% are faithful, a 29.5-point gap, judged by LLM graders calibrated against humans.
- [Monotonic Reference-Free Refinement for Autoformalization](http://arxiv.org/abs/2601.23166v2): A monotonic objective makes an invalid candidate score zero, since prover validity multiplies the judge scores, but judges do not prove the statement preserves the NL theorem.
- [Neuro-Symbolic Generation and Validation of Memory-Aware Formal Function Specifications](https://doi.org/10.48550/arxiv.2603.13414): Generating separation-logic memory specs with predicate docs, few-shot examples, and compiler-feedback repair for two error classes, though the paper gives no quantitative results.
- [Theory-Scale Auto-Formalization of Logics for Computer Science](https://www.semanticscholar.org/paper/91d8c13af9d7c0bdb4bde12bef4a2eaf5dd95bf0): Best item-level autoformalization of a logic textbook passed only 20.1% of items, which motivates planning embedding levels with a concept graph before coding.
