# Proof and invariant synthesis

(authored by agents unless marked 🧑)

- [A Neurosymbolic Approach to Loop Invariant Generation via Weakest Precondition Reasoning](https://arxiv.org/abs/2512.15816): LLM computes weakest preconditions backwards and OpenJML errors drive repair, reaching 99.5% on 150 Java programs with o4-mini, but no ablation isolates the symbolic module.
- [VERITAS: Verifier-Guided Proof Search for Zero-Shot Formal Theorem Proving](https://arxiv.org/abs/2606.19399): VERITAS keeps structured Lean verifier feedback (syntax, types, goal progress) in the search state instead of pass/fail, and runs Critic-guided MCTS only on Best-of-5 failures.
- [Adaptive Proof Refinement with LLM-Guided Strategy Selection](https://arxiv.org/abs/2510.25103): An LLM picks one of three repair moves per round on failed Rocq proofs while Rocq checks each step, reaching 37.9% on CoqDev and 41.3% on CoqStoq.
- [Property-based Polynomial Invariant Generation using Sums-of-Squares Optimization](http://arxiv.org/abs/1503.07025v1): Sums-of-squares optimization finds a stronger inductive polynomial invariant that implies a user-chosen sublevel-set property when that property is not inductive itself.
- [Advancing Mathematics Research with AI-Driven Formal Proof Search](https://doi.org/10.1126/science.aej2213): The Lean compiler is the oracle while an LLM edits only marked regions, and a validator blocks statement changes, because compiled proofs can still prove a misformalized statement.
- [Agentic Verification of Software Systems](https://doi.org/10.1145/3808164): AutoRocq's GPT-4.1 agent writes Rocq tactic proofs with prover feedback, and the kernel replays them; it proves 198/641 (30.9%) SV-COMP verification conditions with Frama-C invariants as input.
- [Towards a Mathematics Formalisation Assistant using Large Language Models](http://arxiv.org/abs/2211.07524v1): Codex formalises 120 undergraduate theorem statements in Lean at nearly 75% accuracy, and one of twelve proof completions was easy to repair.
- [Verifix: Verified Repair of Programming Assignments](https://arxiv.org/abs/2106.16199): Verifix repairs student C programs by aligning control-flow automata with a reference, checking edges with SMT, and using partial MaxSMT to keep repairs minimal.
- [PROMISE: Proof Automation as Structural Imitation of Human Reasoning](https://arxiv.org/abs/2604.05399v2): Retrieving proof-state transitions (goal plus remaining command suffix) beats lexical lemma retrieval for Isabelle proof search, and the model proposal counts only if the theory builds.
- [ImProver: Agent-Based Automated Proof Optimization](http://arxiv.org/abs/2410.04753v2): A GPT-4o agent rewrites correct Lean proofs for shorter length, and results should be reported as improved accuracy because returning the input already counts as correct.
- [ImProver 2: Iteratively Self-Improving LMs for Neurosymbolic Proof Optimization](https://arxiv.org/abs/2605.22885): Sampling many rewrites of a verified Lean proof, compiling each, and keeping the best valid one beats the original on structural metrics that are proxies, not validated preferences.
- [DeepMath - Deep Sequence Models for Premise Selection](https://arxiv.org/abs/1606.04442): Deep sequence models rank premises for ATPs by embedding conjecture and axiom pairs separately, then predicting which premises lead to E prover proofs.
- [Lemmanaid: Neuro-Symbolic Lemma Conjecturing](https://arxiv.org/abs/2504.04942): The LLM emits lemma templates with abstracted function holes, and a symbolic constraint search fills the holes, so the model never needs theory-specific names.
- [A Framework for the Verification of Certifying Computations](http://arxiv.org/abs/1301.7462v1): Verify a small executable checker and a witness predicate separately, so the algorithm itself need not be verified: the checker is correct and the witness implies the postcondition.
- [ProofNet++: A Neuro-Symbolic System for Formal Proof Verification with Self-Correction](https://arxiv.org/abs/2505.24230v1): After a checker rejects a step, extract the failed proof subtree, propose replacements, verify, and resume; the paper does not name its RL algorithm.
- [Automatic Program Instrumentation for Automatic Verification (Extended Technical Report)](http://arxiv.org/abs/2306.00004v1): Rewriting hard expressions into ghost state before automatic verification is sound: if the instrumented program verifies, the original verifies too.
- [AutoDeduct: A Tool for Automated Deductive Verification of C Code](http://arxiv.org/abs/2501.10889v1): AutoDeduct infers ACSL contracts for C helper functions from an entry-point contract by encoding calls as Horn clauses, checked by Frama-C WP, but loop invariants are not inferred.
- [Models That Prove Their Own Correctness](https://arxiv.org/abs/2405.15722): A model emits an answer, then interacts with a fixed verifier; soundness error bounds acceptance of wrong answers against every prover, not only honest ones.
- [AutoSOUP: Safety-Oriented Unit Proof Generation for Component-level Memory-Safety Verification](http://arxiv.org/abs/2605.10712v1): An LLM generates CBMC unit-proof harnesses for embedded OS components, exposing 40/60 re-injected CVEs, and five acceptance criteria separate harnesses that verify real code from ones that pass vacuously.
- [Pantograph: A Machine-to-Machine Interaction Interface for Advanced Theorem Proving, High Level Reasoning, and Data Extraction in Lean 4](https://arxiv.org/abs/2410.16429v2): Pantograph lets machine agents switch between expression-based and tactic-based Lean proofs and reports which goals are coupled through shared metavariables, which the user must handle.
- [Nazrin: An Atomic Neural Proof Automation Tactic in Lean 4](https://arxiv.org/abs/2602.18767v3): Nazrin turns Lean proofs into atomic tactic traces and learns tactic choice with a graph neural network, but its atomizer does not convert every proof.
- [APOLLO: Automated LLM and Lean Collaboration for Advanced Formal Reasoning](https://doi.org/10.52202/085713-1389): Repairs failed Lean proofs locally by isolating failing sub-lemmas and re-querying the LLM per goal, instead of regenerating whole proofs; Lean's kernel remains the final check.
- [Modular Verification of Recursive Programs](http://arxiv.org/abs/0907.4316v1): Hoare-style proofs for recursive procedures: establish one procedure property, then use it as an assumption for another, giving an acyclic proof dependency graph.
- [Forward Invariant Cuts to Simplify Proofs of Safety](http://arxiv.org/abs/1507.05133v2): Forward invariant cuts let a prover use numerically found invariants to split a safety proof into local certificates; transfer to Verus is by analogy only.
- [Automatically Building Machine-Checked Assurance Cases from C Codebases to Requirements](https://arxiv.org/abs/2609.40119): An LLM-guided VST and Rocq workflow proved memory safety for 299 C functions, and proof failure exposes specs that are too weak or too strong.
- [Amortised Resource Analysis with Separation Logic](https://doi.org/10.2168/LMCS-7%282:17%292011): Credits as resource assertions in separation logic give sound amortised cost bounds, with a Coq-verified VCG and linear constraints that infer annotations.
- [Auto-active Verification of Graph Algorithms, Written in OCaml](https://arxiv.org/abs/2207.09854v1): Cameleer proves graph algorithms in OCaml by validating a certificate with a checker proven equivalent to a logical path predicate, so the producer only needs termination and no exceptions.
- [Automated Lemma Discovery in Agentic Program Verification](https://doi.org/10.1145/3832783.3834356): LemmaNet, an agent on AutoRocq, proves 364/941 (38.7%) verification conditions by discovering helper lemmas, versus 287 (30.5%) for AutoRocq, at $0.12-1.03 per VC.
- [Automated Proving of Shannon-Type Entropy Inequalities via Fine-Tuned Language Models and Guided Tree Search](http://arxiv.org/abs/2606.05729v1): A 0.6B model with guided tree search proves 51 of 60 Shannon-type entropy inequalities, versus 1 of 60 for GPT-5.5 zero-shot.
- [AutoVerus: Automated Proof Generation for Rust Code](https://doi.org/10.1145/3763174): A three-phase multi-agent pipeline adds Verus loop invariants, ranks candidates by verified-function count then error count, and merges a candidate only when the score improves.
- [Proving Theorems using Incremental Learning and Hindsight Experience Replay](https://arxiv.org/abs/2112.10664): Hindsight experience replay on unproved conjectures trains a clause-scoring network that improves first-order theorem proving.
- [Kimina-Prover Preview: Towards Large Formal Reasoning Models with Reinforcement Learning](https://arxiv.org/abs/2504.11354): Kimina-Prover is a Lean whole-proof model trained by SFT then RL on a binary Lean reward, with an expert-iteration autoformalizer supplying problems; 72B reaches 68.85% pass@32 on miniF2F-test.
- [Prover Agent: An Agent-Based Framework for Formal Mathematical Proofs](https://arxiv.org/abs/2506.19923v5): Prover Agent generates auxiliary lemmas when direct proof search fails, reaching 88.1% on MiniF2F with Lean feedback.
- [FVDebug: An LLM-Driven Debugging Assistant for Automated Root Cause Analysis of Formal Verification Failures](https://arxiv.org/abs/2510.15906): FVDebug turns a hardware counterexample into a causal dependency graph, proposes competing hypotheses, and accepts only patches that pass re-verification, though the paper covers hardware only.
- [Baldur: Whole-Proof Generation and Repair with Large Language Models](https://doi.org/10.1145/3611643.3616243): Sampling 64 whole Isabelle proofs from a fine-tuned model proved 40.7% of PISA test theorems in about 35 s, versus 216 s for step-by-step search, excluding proof checking time.
- [An Immune System Inspired Approach to Automated Program Verification](http://arxiv.org/abs/0905.2649v1): A learned model predicts the polynomial shape of a loop invariant, and exact quantifier elimination then computes it; the reported result is qualitative.
- [Learning to Reason in Large Theories without Imitation](https://arxiv.org/abs/1905.10501): Deep RL premise and tactic selection with a GNN learns HOList proofs without human traces by mixing exploration and exploitation lists, and needs a seed of solved theorems to start.
- [A Case Study on the Effectiveness of LLMs in Verification with Proof Assistants](https://doi.org/10.1145/3759425.3763391): GPT-4o proves 49.2% of hs-to-coq and 30.6% of Verdi Rocq theorems with project context, versus 25.7% and 6.6% with no context.
- [Debugging Program Verification Proof Scripts (Tool Paper)](http://arxiv.org/abs/1804.04402v1): psdbg replays KeY proof scripts as a debugger with reverse stepping over an explicit proof object, but the paper has no benchmark or user study.
- [SLAyer: Memory Safety for Systems-Level Code](https://www.semanticscholar.org/paper/708c478c360db384a9c39a87233c66d750d6d90a): SLAyer proves memory safety of 10K-30K line C code without annotations by searching separation-logic invariants with an SMT-backed prover, returning Safe, Possibly Unsafe, or Exhausted.
- [LLM Library Learning Fails: A LEGO-Prover Case Study](https://arxiv.org/abs/2504.03048): LEGO-Prover's learned lemma library showed no direct reuse, and its accuracy gains vanished at equal compute, so library-learning claims need direct reuse measurements.
- [Boosting k-Induction with Continuously-Refined Invariants](https://doi.org/10.1007/978-3-319-21690-4_42): k-induction on unbounded loops gets stronger invariants from a concurrent data-flow generator, and only invariants the generator proved itself are injected for soundness.
- [Verified Code Transpilation with LLMs](https://arxiv.org/abs/2406.03003): Verified lifting has an LLM propose a Python program summary that a prover checks equal to the source for all states, so the source program acts as the spec.
- [Graph2Tac: Online Representation Learning of Formal Math Concepts](https://arxiv.org/abs/2401.02949): Graph2Tac's online k-NN over a shared graph of definitions and proof states beat offline models once at least 10 new dependencies appeared and lifted unseen-package pass rate from 17.4% to 26.1%.
- [Refining Existential Properties in Separation Logic Analyses](http://arxiv.org/abs/1504.08309v1): A CEGAR-like backward and forward refinement recovers witness values, such as list-contains facts, that finite abstraction erased.
- [Exploiting Pointer Analysis in Memory Models for Deductive Verification](http://arxiv.org/abs/1811.12515v1): Feeds a static pointer-analysis memory partition into the Frama-C WP memory model, cutting effort on one sorting case; soundness is conjectured, not proved.
- [Bourbaki: Self-Generated and Goal-Conditioned MDPs for Theorem Proving](https://arxiv.org/abs/2507.02726): Bourbaki turns intermediate conjectures into goals inside a verified-reward MCTS, solving 26 of PutnamBench's 658 Lean problems at pass@512 versus 23 for DeepSeek-Prover-V2.
- [Safety Verification and Refutation by k-invariants and k-induction (extended version)](http://arxiv.org/abs/1506.05671v2): One loop over k alternates k-inductive invariant search from templates with length-k counterexamples, unifying bounded model checking, k-induction, and abstract interpretation; termination is not claimed.
- [Ax-Prover: A Deep Reasoning Agentic Framework for Theorem Proving in Mathematics and Quantum Physics](http://arxiv.org/abs/2510.12787v4): Ax-Prover pairs a Lean prover with an independent verifier that accepts only when no error and no sorry or admit remains, because the prover sometimes stops early with errors left.
- [Munkres’ General Topology Autoformalized in Isabelle/HOL](https://arxiv.org/abs/2604.07455): A sorry-first skeleton separates structure from search: the LLM writes the skeleton, sledgehammer fills each sorry, and the result is 85,472 lines of Isabelle with 0 sorry at about $8,895 list price.
- [Inference-Time Diversity in RL-Trained Lean Theorem Provers: A Diagnostic Study](https://arxiv.org/abs/2601.16172): After RL, 32 extra i.i.d. samples found zero new proofs, while a deterministic schedule of 15 tactic skeletons solved 55/244 at k=16 versus 38/244 for sampling.
- [Can ChatGPT support software verification?](https://arxiv.org/abs/2311.02433): GPT-3.5 proposed one loop invariant per program and 75 of 106 were validated, but a failed candidate is not proof the invariant is wrong, so counts are lower bounds.
- [Reviving DSP for Advanced Theorem Proving in the Era of Reasoning Models](http://arxiv.org/abs/2506.11487v1): A draft-sketch-prove pipeline with stock LLMs and BFS-Prover reaches 80.7% on miniF2F with 1,024 attempts, but pass rate measures coverage and Lean does not check statement fidelity.
- [CAPRI: Contract-Aware Proof Repair for Isabelle](https://arxiv.org/abs/2608.13459): Accept only if Build(R') and Conforms(R, R', C) both hold, because a green build does not show the LLM changed only what the contract authorized.
- [Verification of the Incremental Merkle Tree Algorithm with Dafny](http://arxiv.org/abs/2105.06009v3): A Dafny proof of the Ethereum deposit-contract Merkle tree takes 3,538 lines and 12 person-weeks; it proves a functional recursive algorithm first and reuses it as the invariant of the imperative code.
- [Diffy: Inductive Reasoning of Array Programs using Difference Invariants](https://arxiv.org/abs/2105.14748): Induction on N with loop peeling and difference invariants avoids per-loop invariants for parameterized array programs, and the needed expressions stayed quadratic in N.
- [Partial Contracts Suffice: Sound, LLM-Inferred Regression Verification](https://arxiv.org/abs/2607.10291): The LLM proposes a partial one-sided contract for an old function and ESBMC enforces it, so a wrong guess is rejected rather than believed.
- [Polynomial Invariant Generation for Non-deterministic Recursive Programs](https://arxiv.org/abs/1902.04373v3): Polynomial invariants for recursive nondeterministic programs come from templates and SOS constraints, sound always and complete only under compactness and a large enough SOS degree.
- [Hierarchical Attention Generates Better Proofs](https://arxiv.org/abs/2504.19188): A regularizer penalizes attention flowing from higher to lower proof-state levels, raising miniF2F test from 29.51% to 31.56% for a 2.8B model.
- [Seed-Prover: Deep and Broad Reasoning for Automated Theorem Proving](https://arxiv.org/abs/2507.23726v2): Seed-Prover reuses proved lemmas and iterates on Lean feedback, reaching 78.1% on formalized past IMO problems and 331/657 on PutnamBench.
- [Imbuing Large Language Models with Bidirectional Logic for Robust Chain Repair](https://arxiv.org/abs/2606.05030): Repair only the failed segment between a verified prefix and a verified milestone; a deterministic verifier finds the first failing step, and the model writes only the bridge.
- [Goedel-Architect: Streamlining Formal Theorem Proving with Blueprint Generation and Refinement](https://arxiv.org/abs/2606.06468): Proving through one global blueprint, where each lemma sees only its statement and declared parents, replaces recursive decomposition and lets each node run under its own budget.
- [Clarifying Before Reasoning: A Coq Prover with Structural Context](http://arxiv.org/abs/2507.02541v1): Compiler-intercepted context (qualified names, elaborated types) lifted Coq prover success from 21.8% to 45.8%, but the clarity judge is uncalibrated.
- [CLN2INV: Learning Loop Invariants with Continuous Logic Networks](https://arxiv.org/abs/1909.11542): CLN2INV learns quantifier-free SMT loop invariants from traces by training differentiable continuous logic networks, with Z3 as the final check because low training loss proves nothing.
- [Combining Textual and Structural Information for Premise Selection in Lean](https://arxiv.org/abs/2510.23637): Lean premise selection adds an RGCN over state-premise and premise-premise dependency edges to text embeddings; the excerpt reports no results.
- [Compile to Compress: Boosting Formal Theorem Provers by Compiler Outputs](https://arxiv.org/abs/2604.18587v2): Compiler errors are many-to-one, and inserting the error at the failing source line in a refinement prompt solves 284 of 477 miniF2F problems versus 246 with the error appended at the end.
- [Compiler-Guided Adaptive Proof Search with Cross-Model Synergy on Context-Dependent Theorem Proving](https://arxiv.org/abs/2608.18084): Compile every candidate, map errors to lines, and keep partly correct proofs: alternating exploration and refinement gave +12.8 pp in pass@32 with 21.9% fewer LLM calls.
- [Auto formalisation of Chaitin and of the surprise incompleteness Theorem](https://arxiv.org/abs/2606.12462v1): Claude generated an Agda formalization of Chaitin's and the surprise-examination incompleteness proofs; Agda machine-checks the result.
- [Less Effort, Shorter Proofs: Reinforcement Learning for Security Protocol Analysis in Tamarin](https://arxiv.org/abs/2605.23643): RL for Tamarin claims more and shorter proofs while learning only proposes steps, and Tamarin's rules and final checker remain authoritative.
- [Concise Read-Only Specifications for Better Synthesis of Programs with Pointers](https://doi.org/10.1007/978-3-030-44914-8_6): Symbolic read-only borrows make heap synthesis specs much stronger while staying concise, ruling out odd implementations such as swapping list tails.
- [Verifying LLM-Generated Code in the Context of Software Verification with Ada/SPARK](http://arxiv.org/abs/2502.07728v1): GPT-4o adds Assert and Loop_Invariant annotations to SPARK code, but GNATprove's medium count is not a progress measure and the prompt's edit restriction is never enforced.
- [Towards Autoformalization of Mathematics and Code Correctness: Experiments with Elementary Proofs](https://arxiv.org/abs/2301.02195): Universal Transformer translates LaTeX theorem-and-proof text into Coq, including Hoare-logic code-correctness proofs checked by running Coq.
- [Hammer for Coq: Automation for Dependent Type Theory](https://doi.org/10.1007/s10817-018-9458-4): A Coq hammer combining learned premise selection, ATP translation, and reconstruction proves 40.8% of 9,276 Coq 8.5 stdlib theorems push-button, with no domain knowledge.
- [dafny-annotator: AI-Assisted Verification of Dafny Programs](https://arxiv.org/abs/2411.15143): A small LLM emits annotation text without line numbers; the harness tries each candidate at every syntactic site and keeps the first Dafny accepts, lifting Llama 3.1 8B from 15.7% to 50.6%.
- [DafnyBench: A Benchmark for Formal Software Verification](https://arxiv.org/abs/2406.08467v1): Dafny hint synthesis with the contract fixed scores 26.9% with no LLM, so the baseline matters; it measures hint synthesis, not spec writing.
- [DafnyPro: LLM-Assisted Automated Verification for Dafny Programs](https://arxiv.org/abs/2601.05385): An LLM regenerates Dafny annotations with verifier feedback, and a diff-checker rejects edits to base code, reaching 86.18% on DafnyBench.
- [Gödel's Poetry](http://arxiv.org/abs/2512.14252v1): A Lean prover recursively decomposes hard theorems into subgoals, and a semantic check that the formal statement matches the informal one is needed, since verifier acceptance does not show the contract.
- [Lemma Generation for Horn Clause Satisfiability: A Preliminary Study](https://doi.org/10.4204/EPTCS.299.4): Generates induction lemmas for CHC satisfiability by adding a difference predicate as witness; Z3 and Eldarica fail on the raw clauses, and the paper is self-described ongoing work.
- [Transformational Verification of Quicksort](https://doi.org/10.4204/EPTCS.320.7): Translating recursive list functions to CHC clauses lets a solver prove quicksort postconditions that need list induction it cannot do itself.
- [Elaboration in Dependent Type Theory](https://arxiv.org/abs/1505.04324): Lean's elaborator balances higher-order unification, type class inference, coercions, and tactics; it gives no soundness theorem.
- [KestRel: Relational Verification Using E-Graphs for Program Alignment](https://doi.org/10.1145/3720474): E-graph equality saturation generates many loop alignments of two programs at once, and each extracted alignment is equivalent to the original by construction, exposing shared loop invariants.
- Dissect-and-Restore: AI-based Code Verification with Transient Refactoring: Splits nested loops into single-loop helper methods with generated contracts, so an LLM verifies small pieces, then restores the original shape and reruns the verifier on the merged result.
- [Diversifying to Verify: When Task-Equivalent Programs Differ in Verifiability](https://arxiv.org/abs/2607.09366): One task written as array or list and recursive or loop variants changes verifiability, with 96 of 292 verified initially and 154 after repair, but there is no same-budget control.
- [Formal Theorem Proving by Rewarding LLMs to Decompose Proofs Hierarchically](https://arxiv.org/abs/2411.01829v1): ProD trains a model with RL to decompose theorems into lemmas, rewarding correct novel lemmas even when the main theorem fails.
- [STP: Self-play LLM Theorem Provers with Iterative Conjecturing and Proving](https://arxiv.org/abs/2502.00212v4): Self-play where a model proposes conjectures kept only if the prover solves them 1 to 25% of the time, which targets statements that are barely provable.
- [Proof-Based Synthesis of Sorting Algorithms Using Multisets in Theorema](https://doi.org/10.4204/EPTCS.303.6): Theorema synthesizes sorting algorithms by proving existential conjectures from input and output specs, then extracts conditional rewrite rules as programs.
- [Towards LLM-based Generation of Human-Readable Proofs in Polynomial Formal Verification](https://arxiv.org/abs/2505.23311): ChatGPT-4o proof proposals appear only as example conversations, not checked by a reasoning engine, and hallucinations mean correctness must still be proven.
- [Ilinva: Using Abduction to Generate Loop Invariants](http://arxiv.org/abs/1906.11033v1): Ilinva abduces loop invariants from failed VCs starting from true, strengthening only as needed, and solver timeouts treated as sat can make it miss invariants.
- [On Automated Lemma Generation for Separation Logic with Inductive Definitions](http://arxiv.org/abs/1507.05581v1): Generates separation-logic lemmas from inductive predicate syntax and applies them deterministically, automating entailment for data-structure invariants.
- [A Complete Approach to Loop Verification with Invariants and Summaries](https://arxiv.org/abs/2010.05812v3): A loop's contract is a safe invariant plus a summary relating loop-head and exit states, which turns the loop into a tail-recursive procedure with requires and ensures.
- [FLAMES: Fine-tuning LLMs to Synthesize Invariants for Smart Contract Security](https://arxiv.org/abs/2510.21401): FLAMES fine-tunes an LLM to turn Solidity into require guards without labels, and 96.7% of hardened contracts compile versus 62.6% for base CodeLlama, though this guarantees no safety.
- [Verified Approximation Algorithms](https://doi.org/10.46298/lmcs-18(1:36): Isabelle proofs of six approximation algorithms show published invariants were too weak; test each conjunct against one loop iteration and add missing relations, never weakening an invariant.
- [ExVerus: Verus Proof Repair via Counterexample Reasoning](https://arxiv.org/abs/2603.25810): ExVerus repairs failing Verus proofs by having an LLM translate failing obligations into Z3Py counterexamples, solving 106 of 187 InvariantInjectBench tasks with ten counterexamples versus 100 with one.
- [Proof Strategy Extraction from LLMs for Enhancing Symbolic Provers](https://arxiv.org/abs/2510.10131v2): Proof strategies mined offline from an LLM as Rocq lemmas and given to CoqHammer raise proved theorems from 880 to 998 (+13.4%) under 3-fold cross-validation.
- [A Learning Method for Symbolic Systems Using Large Language Models](https://doi.org/10.48550/arxiv.2605.08694): LLM-mined Ltac tactics from existing Rocq proofs are validated offline and kernel-checked, so CoqHammer runs them with no LLM call at proof time.
- [Complexity and information in invariant inference](https://doi.org/10.1145/3371073): Any invariant learner using only black-box Hoare queries needs exponentially many queries in vocabulary size, even with unbounded computation, which bounds what IC3-style agents can do.
- [Finding Polynomial Loop Invariants for Probabilistic Programs](http://arxiv.org/abs/1707.02690v1): Synthesizes quantitative polynomial loop invariants for probabilistic programs: fix a template, reduce via Positivstellensatz to SOS, solve an SDP, and raise degree if infeasible.
- [Finding Inductive Loop Invariants using Large Language Models](https://arxiv.org/abs/2311.07948v1): An LLM proposes loop invariants and a sound oracle decides; Houdini-style pruning drops blamed candidates, and timeouts can reject true candidates.
- [Enhancing Formal Theorem Proving: A Comprehensive Dataset for Training AI Models on Coq Code](https://arxiv.org/abs/2403.12627v2): coq-facts-props-proofs dataset (103,446 facts, 166,035 proof rows, 142 repos) with provenance; the paper reports no feedback loop into training.
- [Proof-Refactor: Refactoring Generated Formal Proofs into Modular Artifacts](https://doi.org/10.48550/arxiv.2606.03743): Four sequential phases refactor compiling LLM Lean proofs into modular artifacts, gaining +0.31 rubric on Putnam2025 and +0.45 on PutnamBench while keeping the theorem signature.
- [Verifying Procedural Programs via Constrained Rewriting Induction](http://arxiv.org/abs/1409.0166v6): Equivalence of two implementations can serve as the specification for rewriting-induction proofs over procedural programs, so no separate spec language is needed.
- [Beyond k-induction: Learning from Counterexamples to Bidirectionally Explore the State Space](http://arxiv.org/abs/1904.02501v1): Bidirectional k-induction finds violations in about half the steps, but the excerpt suggests most time savings come from the interval invariants.
- [TacticToe: Learning to Reason with HOL4 Tactics](https://arxiv.org/abs/1804.00595): TacticToe learns tactic predictions and runs A* proof search directly in HOL4, producing scripts that HOL4's LCF kernel checks (inference).
- [TacticToe: Learning to Prove with Tactics](https://arxiv.org/abs/1804.00596): TacticToe learns tactic choice from recorded HOL4 proofs and searches with MCTS, proving 66.4% of library theorems in 60 s, with the kernel checking every step.
- [Incremental Forward Reasoning for White-Box Proof Search](https://doi.org/10.1007/978-3-032-22752-2_14): Caches partial forward-rule matches per goal, so near-identical subgoal contexts update cheaply instead of recomputing all matches in Aesop-style search.
- [Automatic Goal Clone Detection in Rocq](https://doi.org/10.4230/LIPIcs.ECOOP.2025.23): clone-finder detects alpha-equivalent proof goals in Rocq projects; 20 of 40 CoqGym projects have clones (mean 27.73 per project), so generalizing them into shared lemmas reduces duplication.
- [Template-based Program Synthesis using Stellensätze](http://arxiv.org/abs/2209.03602v1): Synthesizes polynomial programs from sketches by reducing inductive constraints to quadratic programming via Positivstellensatz-style certificates, avoiding quantifier elimination.
- [The Search for Constrained Random Generators](https://doi.org/10.1145/3808329): Palamedes synthesizes generators whose output set is exactly the predicate's solutions, avoiding runtime backtracking when synthesis yields an assume-free generator.
- [Mostly Automated Proof Repair for Verified Libraries](https://doi.org/10.1145/3591221): When code changes under a fixed spec, the old proof hints at the new loop invariant, and Coq rechecks the repaired proof, so heuristics can miss proofs but cannot cause unsoundness.
- [ProofOptimizer: Training Language Models to Simplify Proofs without Human Demonstrations](http://arxiv.org/abs/2510.15700v1): Proof simplification is verified optimization: Lean accepts only valid rewrites, and a model plus linter shortens proofs by iterated sampling, since bloated RL proofs can be 16x informal length.

- [LemmaHead: RAG Assisted Proof Generation Using Large Language Models](https://arxiv.org/abs/2501.15797): RAG with textbook chunks plus iterative proof augmentation reached 40.0% on MiniF2F validation, but basic RAG without good queries was worse than no retrieval.
- [CircuitProver: Agentic Lean 4 Theorem Proving with Reusable Circuit Proof Library for Hardware Verification](http://arxiv.org/abs/2607.27259v1): Parameterized Chisel hardware was proved correct once for all legal parameters in Lean, with an agentic loop that reuses Lean-checked lemmas, rather than model-checking each instance.
- [Large Language Model for OWL Proofs](https://arxiv.org/abs/2601.12444): LLMs construct faithful OWL proofs by separating axiom extraction, simplification and explanation, with completeness detection.
- [Learning Nonlinear Loop Invariants with Gated Continuous Logic Networks](https://doi.org/10.1145/3385412.3385986): G-CLN learns nonlinear loop invariants from traces and Z3 checks each candidate; fitting all traces is not evidence of inductiveness.
- [ProofEvolve: Neuro-Symbolic Evolution for Formal Automated Theorem Proving](https://arxiv.org/abs/2608.26334): ProofEvolve keeps verified partial proof DAGs from failed root attempts, with a closure-based fitness where extending a DAG never lowers the score, and authors report zero false positives on over 400 re-verified solutions.
- [Generating Millions Of Lean Theorems With Proofs By Exploring State Transition Graphs](http://arxiv.org/abs/2503.04772v1): LeanNavigator generates 4.7 million Lean theorem-proof pairs by exploring proof-state graphs, with Lean validating each step.
- [Let the Library Speak: Self-Advertised Method Selection for Formal Proving](https://www.semanticscholar.org/paper/08041a4b9e74e0c97e53e315d343304688150a76): Method contracts with selection and execution sides let a selector match by applicability rather than similarity; proofs check hole-free terms but not whether the method fits the user intent.
- [Efficient verification of imperative programs using auto2](http://arxiv.org/abs/1610.06996v3): Auto2 uses saturation-based proof search with reusable tables for rewrites, properties, and side conditions, but Verus has no saturation API to copy.
- [Getting More out of Large Language Models for Proofs](https://arxiv.org/abs/2305.04369): GPT-4 Coq proof failures were 34.3% hallucinated names and 20.7% missing dependencies, but the six recommendations in this two-page proposal are untested.
- [Selene: Pioneering Automated Proof in Software Verification](https://arxiv.org/abs/2401.07663): Selene builds a seL4 proof-generation benchmark by isolating each lemma in its own Isabelle session, reusing verified dependencies.
- [Automated Strategy Invention for Confluence of Term Rewrite Systems](https://arxiv.org/abs/2411.06409v2): AI-invented strategies for the CSI confluence prover use a restricted search space to avoid unsound strategies.
- [Understanding and Improving Automated Proof Synthesis for Interactive Theorem Provers](https://www.semanticscholar.org/paper/136a2a3f13638cbe68150025ac11b2abe8c4a19e): Pattern-guided tactic search ranks tactics that match mined transitions first, then falls back to model probability, within a 300-application budget.
- [DreamProver: Evolving Transferable Lemma Libraries via a Wake-Sleep Theorem-Proving Agent](https://arxiv.org/abs/2604.26311): DreamProver grows a persistent Lean lemma library through wake-sleep cycles, keeping generalized lemmas only when they resemble a theorem cluster, and reports a 61% average gain over Hilbert.
- [PhysProver: Advancing Automatic Theorem Proving for Physics](https://www.semanticscholar.org/paper/9db442b772fb24bdeae713f0db0dad048310fe5a): PhysProver runs GRPO on Lean physics with a verifier reward; conjecture synthesis gives 2,608 kept proofs (8.9% yield) and +2.4 points pass@16 on the physics test, with uneven gains.
- [VerusSeek: Retrieval-Augmented LLM-Based Proof Synthesis for Rust Programs](https://doi.org/10.1145/3832783.3834603): VerusSeek retrieves Verus constructs (invariants, lemmas, proof blocks) by verifier error type with bounded context, and every candidate is checked by Verus.
- [Decomposing the Enigma: Subgoal-based Demonstration Learning for Formal Theorem Proving](https://arxiv.org/abs/2305.16366v1): Subgoal-based demonstrations split proofs into steps the LLM can reconstruct and Isabelle accepts, while diffusion-based example selection under a context budget fits only 4.79 examples on average.
- [SubgoalXL: Subgoal-based Expert Learning for Theorem Proving](https://arxiv.org/abs/2408.11172v1): Training a proof generator on subgoal annotations that match formal intermediate Isabelle goals, with reward-weighted expert iteration, produced 38k verified proofs over three iterations.
- [Lyra: Orchestrating Dual Correction in Automated Theorem Proving](https://arxiv.org/abs/2309.15806): Adding tool correction, which tries a fixed list of automation tactics, and conjecture correction to draft-sketch-prove improves Isabelle miniF2F proofs, and every proof is still Isabelle-checked.
- [Solving Formal Math Problems by Decomposition and Iterative Reflection](http://arxiv.org/abs/2507.15225v1): Delta Prover is a training-free Lean agent on Gemini 2.5 Pro that reaches 95.9% on miniF2F-test, and iterative repair beats best-of-n at the same budget.
- [Towards Language Model Guided TLA+ Proof Automation](https://arxiv.org/abs/2512.09758v2): An LLM proposes decompositions of TLA+ inductive proofs, and TLAPS checks that each child implies its parent, lifting protocol proofs to 38.5-50.0% versus 38.5% for the SAPG baseline.
- [Retrieval-Augmented TLAPS Proof Generation with Large Language Models](https://arxiv.org/abs/2501.03073): Splits TLAPS obligations into simpler sub-obligations, which LLMs prove more reliably.
- [Spark-Prover-X1: Formal Theorem Proving Through Diverse Data Training](https://arxiv.org/abs/2511.13043v3): Spark-Prover-X1-7B reaches 37.0% average pass@32 across eight prover benchmarks and solves 27 PutnamBench problems through three training stages.
- [SCOPE: Certified Theorem Proving with a Language Model as the Policy Planner](http://arxiv.org/abs/2610.08319v1): SCOPE splits proof work: a 135M planner picks operators, a symbolic engine computes exactly, and a compiler emits Lean tactics that Lean checks.
- [GenesisGeo: Technical Report](https://arxiv.org/abs/2509.21896v2): GenesisGeo generates one million synthetic geometry problems needing auxiliary constructions, with DDAR proof traces, and trains a small multimodal prover on them.
- [Premise Selection for a Lean Hammer](https://arxiv.org/abs/2506.07477v2): Lean Hammer's neural premise selector reaches a 30.1% full proof rate on Mathlib-test, below the 41.0% from ground-truth premises, so retrieval is the incomplete step.
- [From LLM-Generated Conjectures to Lean Formalizations: Automated Polynomial Inequality Proving via Sum-of-Squares Certificates](https://doi.org/10.1016/j.jsc.2011.08.002): An LLM proposes SOS structure, symbolic computation repairs it exactly, and Lean checks it, with pass rates falling from 44.1% at three variables to 36.7% at five.
